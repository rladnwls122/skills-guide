## 처음 왔다면

이 사이트는 대회 용어로 쓰여 있다. **세트·정답지·기준본 같은 말이 설명 없이 나오면 정상이다** — 검색해도 안 나오는 이 대회만의 말이라 사전을 따로 두었다.

<Steps>

1. **[이 사이트의 말](/reference/glossary/)** 을 먼저 훑는다 (10분)

   과제·과제지·채점 스크립트·세트 넷만 알면 나머지 문서가 읽힌다.

2. **[사전 준비](/start/)** 로 계정과 도구를 갖춘다 (반나절)

   끝에 자가진단 18문이 있다. **아니오가 셋 이상이면 PART 0 부터**, 아니면 PART 1 부터 시작한다.

3. **모듈 하나를 끝까지 해 본다**

   개요 → 이론 → 실습 → (있으면) 드릴 순서다. 한 모듈을 끝내 보면 나머지가 같은 모양이라는 것을 알게 된다.

</Steps>

:::tip[클라우드가 처음이라면 그것도 정상이다]
PART 0 이 운영체제·네트워크·컨테이너부터 시작한다. AWS 를 한 번도 안 써 봤어도 순서대로 가면 된다 — **건너뛴 개념이 나중에 진단을 막는다.**
:::

## 최종 목표

1. 1과제 공통 스택(CloudFront→ALB→EKS/Lambda→DynamoDB + KMS + 관측성)을
   **자기 [런북](/reference/glossary/#런북) 기반으로 4시간 내 배포 + [채점 스크립트](/reference/glossary/#과제지--채점지--채점-스크립트) 90%+** — 문서를 빠르고
   정확하게 실행하는 능력.
2. **문서에 없는 상황을 개념으로 해결** — 배포 중 오류, 문서에 없는 신규 요구가 나와도
   원인을 스스로 짚고, 필요한 리소스를 **콘솔·manifest·tf 혼합**으로 직접 만든다.
3. [과제지](/reference/glossary/#과제지--채점지--채점-스크립트) [30% 변동](/reference/glossary/#변동)을 **30분 내 반영** (grep/sed 드릴).
4. 대표 장애 12종을 확인 명령→원인→조치 순서로 해결.
5. **제공물을 스스로 읽어 낸다** — 수정 불가 Go 바이너리에서 라우트·환경변수를 뽑고,
   Lambda 를 백지에서 쓰고, 느린 질의를 인덱스로 잡는다.

근거는 [실기출 분해](/reference/past-exams/)에 있다. 2024·2025 두 해의 시행문제·채점지·채점 스크립트를 대조해 **매년 나오는 축과 한 해만 나온 축**을 갈라 두었다. 무엇을 먼저 붙잡을지는 그 배점표가 정한다.

## 모듈 사용법 (매 모듈 동일 순서)

<Steps>

1. **모듈 인덱스** — 목표·소요 시간·과금 리소스와 destroy 방침을 먼저 본다.

2. **theory** — 개념 + "왜 이 구성인가". 끝의 자기 점검 퀴즈로 이해를 확인한다.

3. **lab** — 단계별 실습 + 검증 명령 + 함정, 그리고 **정리(destroy)** 까지가 한 세트다.

4. **[오답 노트](/reference/glossary/#오답-노트)** — 증상·원인·다음에 칠 명령 3열로 그날 막힌 것을 남긴다. **실력이 느는 자리가 여기다.**

</Steps>

## 대원칙 ([수상 세트](/reference/glossary/#후보-세트)에서 추출)

1. **채점 스크립트 우선주의** — 구현 전 mark.sh부터. 이름·필드 순서·개수·오타까지 일치.
2. **불필요 리소스 = 감점** — 요구 안 된 bastion/태그/latest 태그/폴더 마커 금지.
3. **긴 작업 먼저 던지기** — EKS 20분, MSK 30분, CloudFront 전파. [소요 시간표](/reference/timings/)
4. **검증 직전 리셋 절차** — 데이터 정리 → 요구 상태 복원 → 트래픽 시드 → No Data 0개.
5. **매일 destroy** — 삭제방지 해제 → 역순 삭제. 비용·이름 충돌 방지.
6. **콘솔 병행 학습** — lab은 IaC(tf/manifest)로 만들되, 만든 리소스를 **콘솔에서 찾아
   설정을 눈으로 확인**하고, 핵심 리소스는 최소 1회 콘솔로도 만들어본다. 실전에서
   문서에 없는 요구는 결국 콘솔 + AWS 공식 문서로 해결하게 된다.

## 비용 가드레일

:::caution[매일 destroy]
시간당 과금 리소스(NAT GW, EKS, MSK, ALB)는 **당일 destroy** 가 원칙이다.
EKS 를 이어서 쓰는 구간(모듈 09→12→13)만 예외이고, 그것도 모듈 인덱스에 명시된 경우만이다.
:::

- AWS Budgets 알람 $50 설정(00 모듈에서 수행). 전체 일정 총 예산 목표 < $100.
- 종료 루틴은 [잔존 리소스 점검](/reference/cleanup-check/) — 빈 출력이어야 그날이 끝난 것.
