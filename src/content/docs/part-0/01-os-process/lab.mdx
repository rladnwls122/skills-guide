> 문서 유형: tutorial

원리는 [01 이론](/part-0/01-os-process/theory/)에 있다. 여기서는 손으로 만든다.

**과금 없음.** 전부 자기 PC 에서 돈다. AWS 계정이 없어도 된다.

## 통과 기준

- [ ] 프로세스를 하나 띄우고 PID 로 찾아 종료시킨다
- [ ] 부모가 죽으면 자식이 어떻게 되는지 눈으로 확인한다
- [ ] 메모리를 점점 먹는 프로그램을 만들고 사용량이 오르는 것을 본다
- [ ] CPU 를 태우는 작업과 기다리는 작업을 지표로 구분한다
- [ ] 마지막에 만든 프로세스를 모두 정리한다

## 0. 준비

PowerShell 7 창 **두 개**를 연다. 하나는 프로세스를 띄우는 창, 하나는 관찰하는 창이다. 한 창에서 하면 관찰할 손이 없다.

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  $PSVersionTable.PSVersion   # 7 이상이면 된다
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  uname -a
  ```
  </TabItem>
</Tabs>

## 1. 프로세스를 만들고 찾아 죽인다

<Steps>

1. **띄우기** — 아무 일도 하지 않고 기다리기만 하는 프로세스를 만든다.

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     # 관찰용 창이 아니라 '띄우는 창'에서 실행
     $p = Start-Process pwsh -ArgumentList '-NoExit','-Command','Start-Sleep 600' -PassThru
     $p.Id
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     sleep 600 &
     echo $!
     ```
     </TabItem>
   </Tabs>

   출력된 숫자가 PID 다. 적어 둔다.

2. **찾기** — 관찰용 창에서 그 PID 를 조회한다.

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     Get-Process -Id <아까 그 PID> | Format-List Name, Id, StartTime, WorkingSet64
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     ps -o pid,ppid,stat,etime,comm -p <아까 그 PID>
     ```
     </TabItem>
   </Tabs>

   기대: 이름과 시작 시각, 메모리 사용량이 나온다. **아무 일도 안 하는데 메모리를 쓰고 있다** — 실행 파일과 런타임이 이미 메모리에 올라와 있기 때문이다.

3. **죽이기** — 프로세스에 종료 신호를 보낸다.

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     Stop-Process -Id <PID>
     Get-Process -Id <PID>     # 이제 오류가 나야 정상이다
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     kill <PID>          # 정중한 종료 요청(SIGTERM)
     ps -p <PID>         # 아무것도 안 나오면 죽은 것
     ```
     </TabItem>
   </Tabs>

</Steps>

:::note[이것이 파드가 죽는 방식이다]
쿠버네티스가 파드를 지울 때 하는 일도 같다 — 먼저 **정중한 종료 신호**를 보내고, 유예 시간(기본 30초) 안에 안 끝나면 강제로 죽인다. 앱이 그 신호를 받아 처리 중인 요청을 마무리하도록 짜여 있으면 무중단 배포가 되고, 무시하면 배포할 때마다 요청이 끊긴다.

강제 종료는 신호를 받을 기회조차 주지 않는다(`kill -9`). 그래서 마지막 수단이다.
:::

## 2. 부모와 자식

<Steps>

1. **자식을 낳는 프로세스** — 셸에서 명령을 실행하면 셸이 부모, 그 명령이 자식이다.

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     # 자기 자신의 PID 와 부모 PID
     $me = Get-CimInstance Win32_Process -Filter "ProcessId = $PID"
     "나: $($me.ProcessId)  부모: $($me.ParentProcessId)"
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     echo "나: $$  부모: $PPID"
     ```
     </TabItem>
   </Tabs>

2. **부모를 죽이면 자식은?** 창 하나에서 셸을 열고 그 안에서 `sleep` 을 띄운 뒤, 셸을 죽여 본다.

   <Tabs syncKey="shell">
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     bash -c 'sleep 300 & echo "자식 PID: $!"; echo "부모 PID: $$"; sleep 2'
     # 부모(bash -c)는 2초 뒤 끝난다. 그 뒤 자식이 살아 있는지 본다
     ps -o pid,ppid,comm -p <자식 PID>
     ```
     </TabItem>
     <TabItem label="PowerShell">
     ```powershell
     # PowerShell 에서는 자식을 남기고 부모만 끝내기가 번거롭다.
     # 원리 확인은 위 Bash 탭(CloudShell)에서 하고, 여기서는 트리만 본다.
     Get-CimInstance Win32_Process | Select-Object ProcessId, ParentProcessId, Name |
       Sort-Object ParentProcessId | Select-Object -First 15
     ```
     </TabItem>
   </Tabs>

   기대(Bash): 자식은 **살아 있고**, 부모 PID 가 1(또는 다른 번호)로 바뀌어 있다. 부모가 죽은 자식은 버려지지 않고 시스템의 첫 프로세스가 거둬 간다.

</Steps>

:::caution[컨테이너에서는 이 규칙이 문제를 만든다]
컨테이너 안에서는 첫 프로세스가 PID 1 이 되고, PID 1 은 **거둬 갈 부모가 없다.** 그래서 앱이 자식을 만드는 구조인데 자식을 거두지 않으면 죽은 자식 기록이 쌓인다.

또 PID 1 은 신호 기본 동작이 다르다 — 보통의 프로세스라면 종료 신호를 받아 그냥 죽지만, PID 1 은 명시적으로 처리하지 않으면 **무시한다.** "파드를 지웠는데 30초를 기다렸다가 강제 종료된다"의 흔한 원인이 이것이다.
:::

## 3. 메모리를 일부러 먹인다

<Steps>

1. **점점 먹는 프로그램** — 1초에 50MB 씩 붙잡는다. 관찰용 창을 함께 본다.

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     # 띄우는 창에서 실행. Ctrl+C 로 언제든 멈춘다
     $hold = @()
     for ($i = 1; $i -le 20; $i++) {
       $b = New-Object byte[] (50MB)
       for ($j = 0; $j -lt $b.Length; $j += 4096) { $b[$j] = 1 }   # 실제로 쓴다
       $hold += ,$b
       "{0}회차: {1:N0} MB" -f $i, ((Get-Process -Id $PID).WorkingSet64 / 1MB)
       Start-Sleep -Seconds 1
     }
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     # CloudShell 은 메모리가 작다. 10회차 정도에서 멈추는 것이 정상이다
     python3 - <<'PY'
     import time
     hold = []
     for i in range(1, 21):
         hold.append(bytearray(50 * 1024 * 1024))   # 할당하고 붙잡는다
         print(f"{i}회차: {sum(len(x) for x in hold)/1024/1024:.0f} MB", flush=True)
         time.sleep(1)
     PY
     ```
     </TabItem>
   </Tabs>

   기대: 수치가 회차마다 약 50MB 씩 오른다. **이것이 메모리 누수의 모양이다** — 단조 증가하고 내려오지 않는다.

2. **정리** — 창을 닫거나 `Ctrl+C` 로 끝낸다. 프로세스가 끝나면 그 메모리는 커널이 전부 회수한다.

</Steps>

:::tip[진단할 때 보는 것은 기울기다]
사용량이 **높은 것**은 문제가 아닐 수 있다. 캐시를 많이 잡아 두는 앱은 원래 그렇다.

문제는 **계속 오르는 것**이다. 부하가 일정한데 사용량 그래프가 우상향 직선이면 누수이고, 한도를 올려도 재시작 시점만 늦춘다. 부하가 오를 때 같이 오르고 내릴 때 같이 내려오면 정상이다.
:::

## 4. 기다림과 태움을 구분한다

<Steps>

1. **두 작업을 각각 재고 그동안의 CPU 를 본다.**

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     # (A) CPU 를 태운다
     Measure-Command { 1..4000000 | ForEach-Object { $_ * 2 } | Out-Null }

     # (B) 기다린다
     Measure-Command { Start-Sleep -Seconds 4 }
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     # (A) CPU 를 태운다
     time (i=0; while [ $i -lt 2000000 ]; do i=$((i+1)); done)

     # (B) 기다린다
     time sleep 4
     ```
     </TabItem>
   </Tabs>

2. **관찰용 창에서** 작업 관리자(또는 `top`)를 띄워 놓고 (A)·(B) 를 다시 돌린다.

   기대: 걸린 시간은 비슷한데 (A) 만 CPU 사용률을 올린다.

</Steps>

**이 구분이 3과제 진단의 첫 갈림길이다.** 응답이 느릴 때 CPU 가 올라 있으면 계산이 병목이고, CPU 가 한가하면 무언가를 기다리는 것이다. 두 경우의 처방이 정반대라 여기서 잘못 갈리면 시간을 통째로 버린다.

## 5. 오독 복구 — 죽일 것을 잘못 골랐다

실전에서 가장 흔한 사고를 재현한다. **이름으로 프로세스를 죽이면 같은 이름의 다른 것도 같이 죽는다.**

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  # 이렇게 하면 지금 이 창까지 죽는다 - 실행하지 말 것
  # Get-Process pwsh | Stop-Process

  # 안전한 방법: 먼저 목록으로 확인하고, PID 를 지정해 죽인다
  Get-Process pwsh | Select-Object Id, StartTime, MainWindowTitle
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  # 이렇게 하면 이름이 겹치는 모든 것이 죽는다 - 실행하지 말 것
  # pkill sleep

  # 안전한 방법: 먼저 무엇이 잡히는지 본다
  pgrep -a sleep
  ```
  </TabItem>
</Tabs>

**교훈.** 지우는 명령은 **먼저 조회로 돌려 보고** 대상이 정확한지 확인한 뒤 실행한다. 이 습관이 대회에서 "요구되지 않은 리소스를 지우다 요구된 것까지 지웠다"를 막는다. 대회 규칙상 사전 제공 리소스를 지우는 것은 되돌릴 수 없는 사고다.

## 6. 정리

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  # 이 실습에서 띄운 sleep/pwsh 자식 창을 닫는다
  Get-Process pwsh | Where-Object { $_.Id -ne $PID } | Select-Object Id, StartTime
  # 목록을 확인한 뒤 필요한 것만
  # Stop-Process -Id <PID>
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  pgrep -a sleep
  # 확인한 뒤 필요한 것만
  # kill <PID>
  ```
  </TabItem>
</Tabs>

과금 리소스가 없으므로 이 모듈에는 destroy 가 없다. 하지만 **정리로 끝내는 습관**은 여기서부터 들인다 — 뒤의 모듈은 정리를 빼먹으면 그대로 비용이 된다.
