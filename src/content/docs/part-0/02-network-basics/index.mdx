> 문서 유형: 개요

1과제의 첫 문항은 언제나 VPC 다. 그리고 VPC 는 새로운 개념이 아니라 **오래된 네트워크 개념에 AWS 이름을 붙인 것**이다.

| AWS 이름 | 원래 이름 |
|---|---|
| VPC | 사설 네트워크 하나 |
| 서브넷 | 그 네트워크를 자른 조각 |
| 라우트 테이블 | 라우팅 테이블 |
| 인터넷 게이트웨이 | 기본 게이트웨이(공인망 쪽) |
| NAT 게이트웨이 | 주소 변환기 |
| 보안 그룹 | 상태 저장 방화벽 |
| 네트워크 ACL | 상태 없는 패킷 필터 |

오른쪽을 알면 왼쪽은 이름만 외우면 된다. 모르면 CIDR 을 한 칸 잘못 계산해 서브넷이 겹치고, 그 상태로 apply 가 성공해 버려서 **한참 뒤 통신이 안 될 때** 원인을 찾게 된다.

## 왜 이 모듈이 중요한가

- 1과제 VPC 문항은 **서브넷 개수·CIDR·라우트 테이블 연결**을 이름 단위로 채점한다. 계산이 틀리면 그 아래 전부가 흔들린다.
- 3과제의 응답 시간 예산은 홉마다 쌓인다. 어디를 지나는지 모르면 어디서 시간을 먹는지도 모른다.
- 실전 장애의 큰 덩어리가 "프라이빗 서브넷에서 밖으로 못 나간다"이고, 그 진단은 **라우팅 → 방화벽** 순서로만 좁혀진다.

## 목표

- [ ] IP 주소와 서브넷 마스크를 읽고, `/24` 를 `/26` 넷으로 쪼갠다
- [ ] 패킷 하나가 목적지까지 가는 경로를 라우팅 테이블로 설명한다
- [ ] 사설 주소와 공인 주소를 구분하고 NAT 가 무엇을 바꾸는지 안다
- [ ] 상태 저장 방화벽과 상태 없는 필터의 차이를 규칙 수로 설명한다
- [ ] "나갈 수 없다"를 라우팅 문제와 방화벽 문제로 가른다
