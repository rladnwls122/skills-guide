> 문서 유형: tutorial

원리는 [02 이론](/part-0/02-network-basics/theory/)에 있다.

**과금 없음.** 자기 PC 와 공개 인터넷만 쓴다.

## 통과 기준

- [ ] 내 PC 의 IP·마스크·기본 게이트웨이를 읽고 사설 대역인지 판정한다
- [ ] `/24` 를 `/26` 넷으로 손으로 쪼개고 계산기로 검증한다
- [ ] 포트를 열어 다른 창에서 접속하고, 닫힌 포트와 열린 포트의 반응 차이를 구분한다
- [ ] 안 되는 상황을 경로 → 방화벽 → 이름 순서로 좁힌다

## 1. 내 자리 읽기

<Steps>

1. **주소·마스크·게이트웨이를 한 번에 본다.**

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     Get-NetIPConfiguration | Select-Object InterfaceAlias,
       @{n='IPv4';e={$_.IPv4Address.IPAddress}},
       @{n='Prefix';e={$_.IPv4Address.PrefixLength}},
       @{n='Gateway';e={$_.IPv4DefaultGateway.NextHop}},
       @{n='DNS';e={($_.DNSServer | Where-Object AddressFamily -eq 2).ServerAddresses -join ','}}
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     ip -4 addr show | grep inet
     ip route show default
     cat /etc/resolv.conf | grep nameserver
     ```
     </TabItem>
   </Tabs>

2. **판정한다.** 나온 주소로 표를 채운다.

   | 질문 | 내 값 |
   |---|---|
   | IP 주소 | |
   | 마스크(`/N`) | |
   | 이 네트워크의 주소 범위 | |
   | 사설인가 공인인가 | |
   | 기본 게이트웨이 | |

   **사설 판정 기준**: `10.`, `172.16.` ~ `172.31.`, `192.168.` 로 시작하면 사설이다.

3. **게이트웨이가 같은 네트워크에 있는지 확인한다.** 있어야 정상이다 — 같은 동네에 있지 않은 게이트웨이는 직접 부를 수 없다.

</Steps>

## 2. CIDR 을 손으로 쪼갠다

계산기를 쓰기 전에 손으로 먼저 한다. 막힌 자리를 좁히는 중에 계산기를 찾아 켤 여유는 없다.

<Steps>

1. **문제.** `10.0.0.0/16` 을 `/24` 로 쪼갤 때, 앞에서 다섯 번째 조각의 CIDR 은?

2. **손으로.** `/24` 의 블록 크기는 셋째 옥텟에서 1 이다. 그러니 `10.0.0.0`, `10.0.1.0`, `10.0.2.0`, `10.0.3.0`, **`10.0.4.0/24`**.

3. **검증한다.**

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     # /26 블록의 시작 주소들을 계산해 본다
     0..3 | ForEach-Object { "10.0.0.$($_ * 64)/26" }
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     for i in 0 1 2 3; do echo "10.0.0.$((i * 64))/26"; done
     ```
     </TabItem>
   </Tabs>

4. **연습 세 문제.** 답을 적고 위 방법으로 검증한다.

   | 문제 | 답 |
   |---|---|
   | `192.168.0.0/24` 를 `/28` 로 쪼개면 조각이 몇 개인가 | |
   | `10.0.16.0/20` 의 마지막 주소는 | |
   | 서브넷 `10.0.1.0/24` 와 `10.0.1.128/25` 는 겹치는가 | |

   :::note[세 번째 문제가 실전에서 사고를 낸다]
   겹친다. `10.0.1.0/24` 는 `10.0.1.0` 부터 `10.0.1.255` 까지이고 `10.0.1.128/25` 는 그 뒷부분이다. AWS 는 **같은 VPC 안에서 겹치는 서브넷 생성을 거부**하지만, 서로 다른 VPC 를 연결할 때는 겹침이 그대로 통신 실패가 된다. VPC Lattice·피어링 문항에서 CIDR 을 겹치게 잡으면 그 지점에서 막힌다.
   :::

</Steps>

## 3. 포트를 열고 연결한다

포트는 프로세스가 가지는 것이지 컴퓨터가 가지는 것이 아니다. 직접 확인한다.

<Steps>

1. **창 A에서 포트를 연다.**

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     # 8080 포트로 아주 단순한 리스너를 띄운다
     $listener = [System.Net.Sockets.TcpListener]::new([System.Net.IPAddress]::Any, 8080)
     $listener.Start()
     "listening on 8080"
     $client = $listener.AcceptTcpClient()   # 접속이 올 때까지 여기서 멈춘다
     "connected: $($client.Client.RemoteEndPoint)"
     $client.Close(); $listener.Stop()
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     # nc 가 있으면
     nc -l 8080
     # 없으면 python 으로
     python3 -m http.server 8080
     ```
     </TabItem>
   </Tabs>

2. **창 B에서 접속한다.**

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     Test-NetConnection -ComputerName 127.0.0.1 -Port 8080
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     curl -sv -m 3 http://127.0.0.1:8080/ 2>&1 | head -5
     ```
     </TabItem>
   </Tabs>

   기대: `TcpTestSucceeded : True`. 창 A 에는 접속한 쪽의 주소와 **임시 포트 번호**가 찍힌다. 클라이언트도 포트를 하나 쓴다는 것이 여기서 보인다.

3. **닫힌 포트와 비교한다.**

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     Test-NetConnection -ComputerName 127.0.0.1 -Port 8081
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     curl -sv -m 3 http://127.0.0.1:8081/ 2>&1 | head -5
     ```
     </TabItem>
   </Tabs>

   기대: **즉시** 실패한다.

</Steps>

:::tip[즉시 거절과 타임아웃은 다른 증상이다]
- **즉시 거절** — 패킷이 목적지까지 갔고, 그 자리에 듣는 프로세스가 없다는 답을 받았다. 네트워크는 정상이고 **앱이 안 떠 있는 것**이다.
- **타임아웃** — 답이 아예 안 온다. 방화벽이 조용히 버렸거나 경로가 없다.

로드밸런서 대상이 unhealthy 일 때 이 둘을 구분하면 볼 곳이 갈린다. 즉시 거절이면 파드·포트를 보고, 타임아웃이면 보안 그룹과 경로를 본다.
:::

## 4. 안 되는 것을 순서대로 좁힌다

일부러 막고 진단한다.

<Steps>

1. **없는 주소로 시도한다** — 경로는 있으나 대상이 없다.

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     Test-NetConnection -ComputerName 10.255.255.1 -Port 443 -WarningAction SilentlyContinue |
       Select-Object ComputerName, TcpTestSucceeded
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     curl -sS -m 5 https://10.255.255.1/ 2>&1 | head -2
     ```
     </TabItem>
   </Tabs>

   기대: 타임아웃. **사설 대역이라 인터넷으로 나가지도 않는다** — 커널이 로컬 경로로 판단하고 응답 없는 주소를 계속 부른다.

2. **없는 이름으로 시도한다** — 이름 해석 단계에서 끝난다.

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     Resolve-DnsName no-such-host-abcxyz.example -ErrorAction SilentlyContinue
     if (-not $?) { "이름 해석 실패 - DNS 단계에서 끝났다" }
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     getent hosts no-such-host-abcxyz.example || echo "이름 해석 실패 - DNS 단계에서 끝났다"
     ```
     </TabItem>
   </Tabs>

3. **두 실패의 메시지를 나란히 적어 둔다.** 실전에서는 이 문구만 보고 어느 단계인지 판정하게 된다.

   | 증상 | 어느 단계 | 다음에 볼 것 |
   |---|---|---|
   | 이름을 못 찾는다 | 해석 | DNS 서버 설정, 사설 호스팅 영역 |
   | 즉시 거절 | 연결 | 대상 프로세스, 포트 번호 |
   | 타임아웃 | 경로·방화벽 | 라우트 테이블 → 보안 그룹 → 네트워크 ACL |

</Steps>

## 5. 오독 복구 — CIDR 을 잘못 읽었다

과제지가 `10.0.0.0/16` 이라고 했는데 `/24` 로 읽고 만들었다고 하자. 이미 서브넷까지 다 만든 뒤에 알았다.

**질문은 하나다 — 고쳐서 살릴 수 있나, 부수고 다시 만들어야 하나.**

VPC 의 기본 CIDR 은 **만든 뒤에 바꿀 수 없다.** 추가 CIDR 을 덧붙일 수는 있지만 기본값 자체는 못 고친다. 그러니 이 경우는 부수고 다시 만드는 쪽이다. 안에 서브넷·게이트웨이·인스턴스가 들어 있으면 그것부터 지워야 한다.

**여기서 배울 것은 시간 감각이다.** 값 하나를 잘못 읽었을 때 되돌리는 비용이 얼마인지 미리 알아 두면, 실전에서 "고칠까 다시 만들까"를 고민하는 시간이 없어진다.

| 값 | 나중에 바꿀 수 있나 |
|---|---|
| VPC 기본 CIDR | **불가** — 다시 만든다 |
| 서브넷 CIDR | **불가** — 그 서브넷만 다시 만든다 |
| 라우트 테이블의 라우트 | 가능 |
| 보안 그룹 규칙 | 가능 |
| 리소스 이름 태그 | 가능 |

**만들기 전에 두 번 확인할 값은 VPC 기본 CIDR 과 서브넷 CIDR 이다.** 이 원칙은 뒤의 모듈에서 클러스터 이름·암호화 키처럼 계속 다시 나온다.

## 6. 정리

창 A 의 리스너를 `Ctrl+C` 로 끝낸다. 만든 것이 프로세스뿐이라 지울 클라우드 리소스는 없다.

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  Get-NetTCPConnection -LocalPort 8080 -ErrorAction SilentlyContinue |
    Select-Object LocalAddress, LocalPort, State, OwningProcess
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  ss -tlnp 2>/dev/null | grep 8080 || echo "8080 리스너 없음 - 정리됨"
  ```
  </TabItem>
</Tabs>

기대: 아무것도 안 나온다. 나오면 그 프로세스를 종료한다.
