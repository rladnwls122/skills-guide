> 문서 유형: 개요

앞 모듈까지는 주소로 이야기했다. 실제 서비스는 이름으로 이야기한다. 그 사이에 세 겹이 있다.

1. **DNS** — 이름을 주소로 바꾼다.
2. **HTTP** — 무엇을 달라고 하고 무엇을 돌려줄지 정한 규약.
3. **TLS** — 그 대화를 남이 못 읽게 감싼다.

이 세 겹을 모르면 로드밸런서도 CDN 도 "설정하면 되는 것"으로 남는다. 알면 **어느 겹에서 응답이 만들어졌는지**를 상태 코드만 보고 짚을 수 있다.

## 왜 이 모듈이 중요한가

3과제 채점의 한 축이 **응답 코드**다. 비정상 요청은 403, 정의되지 않은 경로는 404 를 내야 하는데, 이 둘은 서로 다른 장비가 낸다 — 403 은 앞단의 방화벽이, 404 는 로드밸런서가 낸다. 순서를 모르면 둘이 섞이고, 섞이면 두 항목을 같이 잃는다.

1과제도 마찬가지다. CDN 이 403 을 낼 때 그것이 **CDN 의 403 인지 저장소의 403 인지** 가르지 못하면 진단이 제자리를 돈다.

## 목표

- [ ] 이름 해석이 캐시 → 호스트 파일 → DNS 서버 순으로 간다는 것을 확인한다
- [ ] A · CNAME · ALIAS 를 구분하고 각각 언제 쓰는지 안다
- [ ] TTL 이 바뀐 값의 반영 속도를 어떻게 정하는지 안다
- [ ] HTTP 요청·응답을 손으로 읽고 상태 코드 계열을 구분한다
- [ ] TLS 핸드셰이크가 언제 일어나고 인증서가 무엇을 증명하는지 설명한다
- [ ] L4 와 L7 의 차이를 "무엇을 보고 판단하는가"로 설명한다
