원리와 채점 관점은 [01 이론 — Terraform 문법과 VPC 구조](/part-1/01-terraform-vpc/theory/)에 있다.

**방식**: 정답지를 보지 않고 백지에서 tf 코드를 쓴다 → apply·검증 → 마지막에 `skills-2026` 정답과 diff 해서 설계 차이를 복기한다.

## 실습 목표

- [ ] set-02 VPC 스펙을 변수화된 tf 코드로 직접 작성 (vpc/subnet/igw/nat/rtb)
- [ ] `terraform fmt` / `validate` / `plan` / `apply` 사이클을 몸에 붙이기
- [ ] AWS CLI 로 RTB↔서브넷 매핑을 직접 검증 (채점 스크립트 mark.sh와 같은 방식)
- [ ] output → outputs.json → .env 영속화
- [ ] 당일 destroy 로 NAT 과금 차단

선행 지식과 목표는 [모듈 개요](/part-1/01-terraform-vpc/)에.

:::note[실전 참조 — 막히면 여는 곳]
- Terraform 인자: [aws_vpc](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/vpc) · [aws_subnet](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/subnet) · [aws_nat_gateway](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/nat_gateway) · [aws_route_table](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/route_table)
- 인자 이름만 기억나지 않을 때: `terraform providers schema -json` (`terraform init` 을 마친 디렉터리에서)
- 검증 명령의 플래그·출력 필드: `aws ec2 describe-route-tables help` · `aws ec2 describe-nat-gateways help`
- 찾는 법 자체가 막히면 [실전 문서 검색 가이드](/reference/search-guide/)
:::

## 사전 준비

정답지 저장소를 아직 안 받았다면 [Day 0 §4 저장소 클론](/start/#4-저장소-클론)을 먼저 한다. 저장소는 **홈 디렉터리 아래**에 받는다 — 이 가이드의 정답지 경로는 전부 클론 루트 `~\skills-2026` 기준이다.

명령 안에서는 두 가지로 쓴다. `cd` 는 PowerShell 이 직접 처리하므로 `cd ~\skills-2026\...` 가 그대로 통하고, `git`·`scp` 처럼 외부 프로그램에 경로를 **인자로** 넘길 때는 `$HOME\skills-2026\...` 을 쓴다. 외부 프로그램은 `~` 를 홈으로 풀어 주지 않는다. 클론 위치를 다르게 잡았다면 그 자리에 본인 경로를 넣는다.

```powershell
terraform version    # >= 1.6
aws sts get-caller-identity   # 자격증명 확인
mkdir my-vpc-lab; cd my-vpc-lab
```

`get-caller-identity` 의 기대 출력은 필드 세 개다.

```json
{
    "UserId": "AIDAEXAMPLE...",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/skills"
}
```

`Unable to locate credentials` 나 `ExpiredToken` 이 나오면 코드를 쓰기 전에 자격증명부터 잡는다 — [awscli-basics](/start/awscli-basics/)의 `aws configure` 절차를 다시 밟는다.

## 단계별 절차

<Steps>

1. **스펙만 보고 직접 작성 (정답지 금지)**

   작성할 파일: `versions.tf`, `variables.tf`, `terraform.tfvars`, `data.tf`, `vpc.tf`, `outputs.tf`

   구현 스펙 (set-02 Reference01 실측):

   | 항목 | 값 |
   |---|---|
   | VPC | `wskorea26-vpc`, `172.16.0.0/16`, DNS support/hostnames 활성 |
   | 서브넷 | `wskorea26-pub-subnet-c` 172.16.1.0/24 (2c), `wskorea26-pub-subnet-d` 172.16.2.0/24 (2d), `wskorea26-priv-subnet-c` 172.16.201.0/24 (2c), `wskorea26-priv-subnet-d` 172.16.202.0/24 (2d) |
   | IGW | `book-igw` |
   | NAT | `book-ngw-c`(pub-subnet-c 안), `book-ngw-d`(pub-subnet-d 안) + EIP 각 1 |
   | RTB | `wskorea26-public-rtb`(0.0.0.0/0→IGW, pub 2개 연결), `wskorea26-private-rtb-c`(→ngw-c, priv-c 연결), `wskorea26-private-rtb-d`(→ngw-d, priv-d 연결) |

   필수 제약:

   - 서브넷은 `map(object({cidr, az, tier}))` 변수 + `for_each` 로 생성 (복붙 4개 금지)
   - public 서브넷만 `map_public_ip_on_launch = true`
   - `player_number`, `region`, `vpc_cidr` 는 변수 + tfvars 주입
   - output: `vpc_id`, `public_subnet_ids`(map), `private_subnet_ids`(map), `account_id`

2. **문법 검증 → apply**

   ```powershell
   terraform init
   terraform fmt -check -diff
   terraform validate
   terraform plan     # 리소스 수 확인: VPC1+IGW1+서브넷4+EIP2+NAT2+RTB3+route3+assoc4 = 20개
   terraform apply
   ```

   <details class="diagram-note">
   <summary>이 블록이 하는 일</summary>

   apply 전 4단계 점검이다. `fmt -check -diff` 는 서식이 어긋난 곳을 보여 주고, `validate` 는 문법과 참조를 검사하며, `plan` 은 실제로 만들 리소스 수를 낸다. 20개라는 수를 미리 세어 두면 plan 출력만 보고 빠뜨린 리소스를 찾을 수 있다.

   </details>

   기대: `Apply complete! Resources: 20 added` (NAT 생성으로 2~3분 소요).

   **apply 가 실패하면** 세 갈래부터 본다. 뒤 모듈의 apply 실패도 같은 순서로 좁힌다.

   - **자격증명** — `NoCredentialProviders`·`ExpiredToken` 은 코드 문제가 아니다. `aws sts get-caller-identity` 로 확인하고 [awscli-basics](/start/awscli-basics/) 대로 다시 설정한다.
   - **리전 불일치** — 리소스가 엉뚱한 리전에 생겼다면 `region` 변수와 셸의 `AWS_DEFAULT_REGION` 이 다른 것이다. `$env:AWS_DEFAULT_REGION = "ap-northeast-2"` 로 맞추고 다시 apply 한다.
   - **부분 생성 후 중단** — 절반만 만들고 멈춰도 지우지 않는다. Terraform 은 state 에 기록된 리소스를 건너뛰므로 `terraform apply` 를 그대로 다시 실행하면 나머지만 만든다.

   증상별 확인 명령은 [트러블슈팅](/reference/troubleshooting/)에 있다.

3. **검증 — mark.sh가 보는 방식으로**

   ```powershell
   $env:VPC_ID = terraform output -raw vpc_id

   # (1) CIDR — mark 1-1 상당
   aws ec2 describe-vpcs --vpc-ids $env:VPC_ID --query 'Vpcs[0].CidrBlock'
   # 기대: "172.16.0.0/16"

   # (2) RTB↔서브넷 매핑 — mark 1-2 상당
   aws ec2 describe-route-tables --filters "Name=vpc-id,Values=$env:VPC_ID" `
     --query 'RouteTables[].{Name:Tags[?Key==`Name`]|[0].Value, Subnets:Associations[].SubnetId, Routes:Routes[?DestinationCidrBlock==`0.0.0.0/0`].[GatewayId,NatGatewayId]}' `
     --output json
   ```

   <details class="diagram-note">
   <summary>이 블록이 하는 일</summary>

   채점이 보는 두 항목을 같은 방식으로 확인한다. (1)은 VPC CIDR 이 `172.16.0.0/16` 인지, (2)는 각 RTB 의 이름·연결된 서브넷·기본 경로 대상을 한 번에 뽑는다. `--query` 안의 역따옴표는 JMESPath 의 리터럴 표기이고, PowerShell 에서는 백틱이 줄 이음 문자라 두 문법이 한 줄에 섞인다.

   </details>

   기대 출력 (요지):

   - `wskorea26-public-rtb`: Subnets 2개, 기본 라우트 `GatewayId = igw-...`
   - `wskorea26-private-rtb-c`: Subnets 1개(priv-c), 기본 라우트 `NatGatewayId = nat-...`
   - `wskorea26-private-rtb-d`: Subnets 1개(priv-d), 기본 라우트 `NatGatewayId = nat-...`
   - Name 없는 기본 RTB 하나가 더 보이는 것은 정상 (VPC 기본 RTB, 연결 없음)

   ```powershell
   # (3) NAT 가 "public" 서브넷에 있는지
   aws ec2 describe-nat-gateways --filter "Name=vpc-id,Values=$env:VPC_ID" `
     --query 'NatGateways[].{Name:Tags[?Key==`Name`]|[0].Value, Subnet:SubnetId}'
   # 기대: book-ngw-c → pub-subnet-c 의 ID, book-ngw-d → pub-subnet-d 의 ID
   ```

4. **output 영속화**

   ```powershell
   terraform output -json | Set-Content ..\outputs.json
   @"
   `$env:VPC_ID = "$(terraform output -raw vpc_id)"
   `$env:PRIV_SUBNET_C = "$((terraform output -json private_subnet_ids | ConvertFrom-Json).'wskorea26-priv-subnet-c')"
   `$env:PRIV_SUBNET_D = "$((terraform output -json private_subnet_ids | ConvertFrom-Json).'wskorea26-priv-subnet-d')"
   "@ | Set-Content ..\.env.ps1
   . ..\.env.ps1   # 새 터미널에서도 이 한 줄로 복원
   ```

   <details class="diagram-note">
   <summary>이 블록이 하는 일</summary>

   출력값을 파일 두 개로 남긴다. `outputs.json` 은 원본 보관용이고, `.env.ps1` 은 다음 터미널에서 바로 불러 쓰는 환경 변수 스크립트다. here-string 안의 백틱 `` `$ `` 이 핵심이다 — 지금 확장하지 말고 `$env:VPC_ID` 라는 글자 그대로 파일에 쓰라는 표시다.

   </details>

   여기서 저장하는 변수는 세 개뿐이다 — 이 실습의 tf 가 VPC 만 만들기 때문이다. PART-2 의 `eksctl` 렌더는 보안 그룹·KMS 키·IAM 정책 ARN 까지 아홉 개를 쓰고, 그 값들은 정답지 `set-02\task-1\terraform` 을 통째로 apply 해야 나온다. 전체 목록과 저장 블록은 [04 실습의 사전 준비](/part-2/04-eksctl-cluster/lab/)에 있다.

5. **정답과 diff**

   ```powershell
   git diff --no-index .\vpc.tf $HOME\skills-2026\set-02\task-1\terraform\vpc.tf
   git diff --no-index .\variables.tf $HOME\skills-2026\set-02\task-1\terraform\variables.tf
   ```

   diff 에서 확인할 관점 (기능이 같아도 설계 차이를 본다):

   - 서브넷 이름을 map **key** 로 썼는가 (정답 방식) vs 별도 name 필드
   - NAT 배치를 `public_by_az` locals 매핑으로 풀었는가 vs 하드코딩 인덱스
   - `aws_route` 를 별도 리소스로 뺐는가 vs 인라인 route 블록
   - 이름이 `기본값 + tfvars` 구조인가 vs 리소스에 직접 리터럴

</Steps>

## :badge[함정]{variant=danger} 목록

| 함정 | 증상 / 결과 |
|---|---|
| private 서브넷을 public RTB 에 연결 | 인터넷은 되지만 **mark 1-2 실격** — 채점은 매핑을 본다 |
| NAT 를 private 서브넷에 배치 | NAT 가 인터넷에 못 나감, private 아웃바운드 전멸 |
| `aws_eip` 에 `domain = "vpc"` 누락 | 구버전 스타일 경고/실패 |
| NAT 에 `depends_on = [aws_internet_gateway.this]` 누락 | 간헐적 생성 실패 (IGW 없는 상태에서 NAT 프로비저닝) |
| for_each 에 list 직접 전달 | `The given "for_each" argument value is unsuitable` — `toset()` 필요 |
| Name 태그 오타 | 이름 정확 일치 채점 항목 전부 실패. 변수 default 를 과제지에서 복사해 넣기 |
| 리전 미변수화 / 오리전 apply | mark.sh가 리소스를 못 찾음 — 전 항목 0점 |

## 통과 기준 (mark 항목 연결)

- [ ] VPC CIDR = 172.16.0.0/16 (mark 1-1)
- [ ] RTB 3개 이름 정확 일치, 서브넷 연결 4건 정확, 기본 라우트가 각각 GatewayId/NatGatewayId (mark 1-2)
- [ ] NAT 2개가 각각 같은 AZ public 서브넷에 배치, 이름 book-ngw-c/d
- [ ] `terraform fmt -check` 통과, `validate` 통과, 재 `plan` 시 `No changes`
- [ ] `.env.ps1` 재실행만으로 새 터미널에서 변수 복원

## 정리 (destroy)

```powershell
terraform destroy   # NAT 시간당 과금 — 실습 종료 즉시, 당일 필수
aws ec2 describe-nat-gateways --filter "Name=vpc-id,Values=$env:VPC_ID" `
  --query 'NatGateways[].State'   # deleted 확인
aws ec2 describe-addresses --query 'Addresses[].PublicIp'   # 남은 EIP 없어야 함 (있으면 시간당 과금)
```

VPC 모듈은 의존 리소스가 없으므로 destroy 순서 고민 없이 한 번에 끝난다.

:::caution[과금 주의]
EIP 가 남았는지 마지막으로 꼭 확인한다 — 남아 있으면 시간당 과금이다.
:::
