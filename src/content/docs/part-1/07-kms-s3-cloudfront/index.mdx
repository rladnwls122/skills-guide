## 학습 목표

- [ ] CMK 키 정책 구조(admin 액션 vs use 액션 분리)와 envelope encryption 을 설명할 수 있다
- [ ] set-02 방식(서비스별 CMK 3개 + ECR 은 관리형 aws/ecr)의 "불필요 리소스 감점 회피" 판단을 할 수 있다
- [ ] set-03 root-less 키 정책(root·`kms:*` 금지, 배포자 신원 admin, lockout safety check)을 직접 작성할 수 있다
- [ ] 퍼블릭 차단 4종 + SSE-KMS + BucketKey 버킷과 CloudFront OAC 연동(SourceArn 버킷 정책)을 구성할 수 있다
- [ ] key→distribution→bucket→key 순환 참조를 `aws:SourceAccount` 조건으로 우회하는 이유를 안다
- [ ] WAF Web ACL을 CloudFront(CLOUDFRONT scope, us-east-1 고정)에 연결할 수 있다
- [ ] 관리형 규칙 그룹과 커스텀 매치 규칙의 구조 차이를 설명할 수 있다
- [ ] RuleActionOverrides로 오탐 규칙 하나만 Count 전환하는 절차를 설명할 수 있다
- [ ] set-02 의 키 구성을 set-07 의 **용도별 분류**로 직접 이행할 수 있다 — 개수가 같아도 설계가 다르다
- [ ] 리전을 넘는 요구(CloudFront WAF 로그)가 왜 다중 리전 키를 부르는지 설명할 수 있다
- [ ] `plan` 출력으로 in-place 와 재생성을 판정하고, 버킷 이름 재생성의 파급을 셀 수 있다
- [ ] CDN 이 403 을 낼 때 CDN → 버킷 정책 → 키까지 계층을 좁힐 수 있다

## 소요 시간

- 약 5~6시간 (이론 2h + 실습 3h + 정답 diff 1h)

## 과금 리소스와 destroy 방침

| 리소스 | 과금 | 방침 |
|---|---|---|
| KMS CMK ×3 | **키당 월 $1 (일할)** + API 호출 | destroy 시 `deletion_window_in_days = 7` 대기 상태로 전환 — 대기 중엔 과금 없음 |
| S3 | 저장/요청 소액 | 객체 몇 개 수준이라 무시 가능, destroy 로 정리 |
| CloudFront | 요청/전송량 과금, 배포 자체는 무료 | destroy 시 disable→삭제로 5~10분 소요 |

:::caution[과금 주의]
이 모듈에는 NAT 처럼 시간당 과금이 큰 리소스가 없다. 다만 **KMS 키가 세트마다 쌓이면 키당 월 $1 이 계속 붙는다** — 실습 종료 시 반드시 destroy 한다.
:::

## 선행 지식

- 정책 JSON 4요소(Effect/Action/Resource/Condition)와 **명시적 Deny 우선** — [iam-basics](/start/iam-basics/)
- 권한 정책 vs 신뢰 정책의 차이 — KMS 키 정책은 리소스에 붙는 권한 정책이다 — [iam-basics](/start/iam-basics/)
- root를 Principal에서 빼는 이유 — root로 만든 리소스는 이후 키 사용이 막힌다 — [iam-basics](/start/iam-basics/)
- 봉투 암호화 — 데이터 키로 데이터를 암호화하고 CMK 는 그 데이터 키만 감싼다 — [kms-basics](/start/kms-basics/)
- 키 정책과 IAM 정책이 왜 둘 다 필요한가 — [kms-basics](/start/kms-basics/)
- 접근 통제 4층(BPA · 버킷 정책 · ACL · IAM)과 BPA 가 가장 먼저 이긴다는 것 — [s3-basics](/start/s3-basics/)
- OAC 와 OAI 의 차이 — SSE-KMS 버킷은 OAI 로 못 읽는다 — [s3-basics](/start/s3-basics/)
- `aws ... --query`로 배포·버킷 속성만 뽑아 확인하는 법 — [awscli-basics](/start/awscli-basics/)

막히는 항목이 있으면 그 링크를 먼저 읽는다. 아니면 바로 다음 파일로 간다.

## 공식 문서

전부 읽지 않는다. 각 문서에서 **읽을 자리**만 적었다.

**모듈에 들어가기 전에 읽는다**

- [KMS 키 정책](https://docs.aws.amazon.com/kms/latest/developerguide/key-policies.html) · 키 관리 권한과 사용 권한을 가르는 부분. 두 권한을 섞으면 열쇠를 잠근 채 잃는다
- [CloudFront OAC 로 S3 접근 제한](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html) · 버킷 정책 예시와 `AWS:SourceArn` 조건. 버킷을 비공개로 두고 배포만 통과시키는 구조의 정본이다
- [Amazon S3 사용 설명서](https://docs.aws.amazon.com/AmazonS3/latest/userguide/) · 퍼블릭 액세스 차단 네 항목과 SSE-KMS 를 다루는 부분. 네 항목이 각각 무엇을 막는지 구분한다

**실습 중 대조한다**

- [서비스별 액션·리소스·조건 키](https://docs.aws.amazon.com/service-authorization/latest/reference/reference_policies_actions-resources-contextkeys.html) · 해당 서비스 페이지의 Action 표와 Condition key 표. 정책에 쓸 수 있는 이름의 전수표다
- [`aws_cloudfront_distribution`](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/cloudfront_distribution) · `origin` 과 `default_cache_behavior` 두 블록의 인자 목록
- [AWS WAF 개발자 안내서](https://docs.aws.amazon.com/waf/latest/developerguide/waf-chapter.html) · Web ACL 과 관리형 규칙 그룹, 그리고 `RuleActionOverrides` 를 다루는 부분. 오차단을 되돌릴 때 연다
