## 학습 목표

- [ ] Dockerfile 베이스 선택(scratch/alpine/distroless)이 ECR 스캔·TLS·타임존에 미치는 영향을 설명할 수 있다
- [ ] tzdata + `TZ=Asia/Seoul` 미설정 시 Go 바이너리 `created_at` 이 UTC 로 저장돼 채점에 실패하는 이유를 안다
- [ ] scanOnPush + KMS 암호화 ECR 리포지토리를 만들고, 요구된 태그만 push 할 수 있다 (latest 추가 = 감점)
- [ ] PK + GSI(HASH+RANGE) + PITR(지정 시점 복구 — 최근 35일 중 원하는 초 단위 시점으로 되돌린다) + 삭제방지 DynamoDB 테이블을 설계하고, boto3 Decimal 함정을 피할 수 있다
- [ ] ALB 통합 Lambda(boto3 Query, ScanIndexForward=False, 환경변수 주입, 응답 포맷)를 작성할 수 있다

- [ ] set-02 의 레지스트리·테이블·함수를 set-07 요구로 **직접 이행**할 수 있다
- [ ] 조회 기준이 뒤집힌 요구에서 파티션 키와 GSI 축을 다시 배치할 수 있다
- [ ] 파티션 키 재생성의 파급과 **삭제방지를 먼저 꺼야 하는 순서**를 안다
- [ ] `validate` 가 막을 때 오타인지 **프로바이더가 낡은 것인지** 판정할 수 있다
- [ ] 로그가 남는 실패와 로그조차 안 남는 실패를 구분해 계층을 좁힐 수 있다

## 과금 리소스와 destroy 방침

| 리소스 | 과금 | 방침 |
|---|---|---|
| ECR | 저장 GB당 소액 | destroy (`force_delete = true` 로 이미지 포함 삭제) |
| DynamoDB (PAY_PER_REQUEST) | 요청당 과금, 실습 수준 무시 가능. **PITR 은 저장량 과금** | destroy 전 **삭제방지 해제** 필요 |
| Lambda | 호출당, 무시 가능 | destroy |
| KMS CMK 1개 | 월 $1 일할 | destroy → 7일 대기 |
| CloudWatch Logs | 저장 소액 | destroy 로 함께 삭제 |

:::caution[destroy 순서 주의]
시간당 과금이 큰 리소스는 없다. 다만 **DynamoDB 는 `deletion_protection_enabled = true` 상태에서 destroy 가 실패한다** — 정리 절차([실습](/part-1/08-container-lambda-dynamodb/lab/) §정리)를 반드시 따른다.
:::

## 선행 지식

- push 3단계: build → tag(레지스트리 주소 포함) → push — [docker-basics](/start/docker-basics/)
- `RUN`은 빌드 시점, `ENTRYPOINT`/`CMD`는 실행 시점 — [docker-basics](/start/docker-basics/)
- 베이스 이미지 크기가 pull 지연과 스캔 결과를 좌우한다 — [docker-basics](/start/docker-basics/)
- 역할(Role) = 자격증명 없는 신원. Lambda 실행역할이 이것 — [iam-basics](/start/iam-basics/)
- 파티션 키로 항목을 찾고, 다른 축의 조회는 GSI 로 푼다 — [dynamodb-basics](/start/dynamodb-basics/)
- Query 는 파티션 키로 좁혀 읽고 Scan 은 전부 읽고 거른다 — [dynamodb-basics](/start/dynamodb-basics/)
- boto3 로 숫자를 저장할 때는 `float` 가 아니라 `Decimal` — [dynamodb-basics](/start/dynamodb-basics/)
- Lambda 핸들러의 `event` 모양과 ALB 통합 응답 형식 — [python-basics](/start/python-basics/)

:::tip[Lambda 코드를 직접 고쳐야 한다면]
이 모듈의 4절은 완성된 Lambda 를 읽는다. **백지에서 쓰거나 요구가 바뀌어 고쳐야 한다면** [Python·boto3 기초](/start/python-basics/#3-1-가장-단순한-조회--set-07task-1)가 실제 과제 Lambda 셋을 줄 단위로 해부한다. 마지막에 변형 과제 여섯 개가 있다.
:::

막히는 항목이 있으면 그 링크를 먼저 읽는다. 아니면 바로 다음 파일로 간다.

## 공식 문서

전부 읽지 않는다. 각 문서에서 **읽을 자리**만 적었다.

**모듈에 들어가기 전에 읽는다**

- [DynamoDB 개발자 안내서](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/) · 기본 키와 보조 인덱스를 설명하는 부분. 조회 패턴이 테이블 설계를 정한다는 사실이 여기서 나온다
- [ALB 의 Lambda 대상](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/lambda-functions.html) · 응답 형식을 규정하는 부분. 형식이 어긋나면 코드가 정상이어도 502 가 난다

**실습 중 대조한다**

- [Dockerfile 레퍼런스](https://docs.docker.com/reference/dockerfile/) · `FROM`·`RUN`·`ENV`·`ENTRYPOINT` 네 항목. 명령마다 레이어가 생기는지 여부를 확인한다
- [Amazon ECR 사용 설명서](https://docs.aws.amazon.com/AmazonECR/latest/userguide/) · 로그인과 이미지 푸시 절차. 인증 토큰의 수명이 짧다는 점을 확인한다
- [boto3 DynamoDB 레퍼런스](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/dynamodb.html) · `Query` 의 인자 목록과 반환 타입. 숫자가 `Decimal` 로 오는 것이 흔한 함정이다
