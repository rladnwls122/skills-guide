<details class="diagram-note">
<summary>이 블록이 하는 일</summary>

`terraform output` 값을 지금 셸에 올리고, 같은 값을 파일 하나로 굳힌다. 어느 셸이든 요령은 같다 — **값은 지금 확장하고, 변수 이름은 글자 그대로 파일에 남긴다**. PowerShell 은 here-string 안의 백틱 `` `$ `` 가 "지금 확장하지 말라"는 표시이고, 큰따옴표 안의 `$env:VPC_ID` 는 반대로 지금 값으로 바뀐다. bash 는 heredoc 이 `$( )` 만 지금 실행하고 `export VPC_ID=` 부분은 글자로 남긴다. 마지막 Grafana 비밀번호 줄만 작은따옴표인 것은 비밀번호에 `$` 가 들어가서, 파일을 다시 읽을 때 그 뒤가 변수로 확장되는 것을 막기 위해서다.

</details>

**검증**: `terraform output` 이 에러 없이 뜨고 `..\.env.ps1`(bash 는 `../.env.sh`)이 생겼으면 된다. 새 터미널로 이어서 할 땐 `set-02\task-1` 에서 `. .\.env.ps1`(bash 는 `source ./.env.sh`) 한 줄만 다시 실행한다.

## 1. 환경변수 로드 + 렌더

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  cd ~\skills-2026\set-02\task-1
  . .\.env.ps1                      # terraform output 영속 파일

  cd eksctl
  $c = Get-Content cluster.yaml -Raw
  foreach ($v in 'VPC_ID','PRIV_SUBNET_C','PRIV_SUBNET_D','CLUSTER_EXTRA_SG_ID','NODE_SG_ID',
                 'EKS_KMS_ARN','BOOK_APP_POLICY_ARN','LBC_POLICY_ARN','FLUENT_BIT_POLICY_ARN') {
    $c = $c.Replace('${' + $v + '}', [Environment]::GetEnvironmentVariable($v))
  }
  $c | Set-Content cluster.rendered.yaml
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  cd ~/skills-2026/set-02/task-1
  source ./.env.sh                  # terraform output 영속 파일

  cd eksctl
  envsubst '$VPC_ID $PRIV_SUBNET_C $PRIV_SUBNET_D $CLUSTER_EXTRA_SG_ID $NODE_SG_ID
            $EKS_KMS_ARN $BOOK_APP_POLICY_ARN $LBC_POLICY_ARN $FLUENT_BIT_POLICY_ARN' \
    < cluster.yaml > cluster.rendered.yaml
  ```
  </TabItem>
</Tabs>

<details class="diagram-note">
<summary>이 블록이 하는 일</summary>

`cluster.yaml` 의 `${VAR}` 자리 아홉 개를 실제 값으로 바꿔 `cluster.rendered.yaml` 을 만든다. 값의 출처는 앞 모듈이 남긴 `.env.ps1`(bash 는 `.env.sh`)이라 점 하나로 먼저 불러온다. PowerShell 은 `.Replace()` 로 문자열을 그대로 치환하므로 `${...}` 의 특수문자를 신경 쓰지 않아도 되고, bash 는 `envsubst` 에 **치환할 변수 목록을 명시**한다 — 목록을 주지 않으면 YAML 안의 다른 `$` 표기까지 건드린다. 치환한 파일을 따로 만드는 이유는 원본을 그대로 두어 다시 렌더할 수 있게 하려는 것이다.

</details>

**검증 — 치환 누락 grep:**

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  Select-String '\$\{' cluster.rendered.yaml
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  grep -n '\${' cluster.rendered.yaml
  ```
  </TabItem>
</Tabs>

:::caution[생략 금지]
기대 출력: **아무것도 없음**. 한 줄이라도 나오면 해당 변수가 env에 없는 것 — `.env.ps1`(bash 는 `.env.sh`) 재확인.
치환이 남은 채로 생성에 들어가면 20분을 버린다.
:::

## 4. :badge[함정]{variant=danger} 정리

| 함정 | 증상 | 예방 |
|---|---|---|
| `${VAR}` 치환 누락 | eksctl이 서브넷/SG를 못 찾고 실패 | grep 검사 필수 (1절) |
| Pod Identity 사용 | agent가 app 노드에 떠서 mark 5-4 감점 | set-02는 IRSA 고정 |
| 기본 애드온 자동설치 | metrics-server가 app 노드 스케줄 → 5-4 감점 | `addonsConfig.disableDefaultAddons: true` |
| coredns 노드 미고정 | coredns가 app 노드로 → 5-4 감점 | `configurationValues` nodeSelector |
| `tags.Name`만 쓰고 instanceName 누락 | EC2 인스턴스 Name 태그 미적용 | 둘 다 유지 (역할이 다름) |
| version 따옴표 없이 `1.35` | YAML이 float로 파싱 | `version: "1.35"` |
| 생성 도중 중단 | 스택 일부만 존재 | 아래 부분 복구 |

**부분 복구 (생성 중단 시):**

<Tabs syncKey="shell">
  <TabItem label="PowerShell">

## 7. 변형 셀프 체크

당일 과제의 약 30% 가 수정된다. 재배포 없이, 각 질문에 먼저 답한 뒤 펼쳐 확인한다.

1. 클러스터 이름이 `wskorea26-cluster` 에서 다른 값으로 바뀌면 무엇을 고치나?

   <details>
   <summary>답 확인</summary>

   파일 안의 리터럴은 `eksctl/cluster.yaml` 의 `metadata.name` 한 곳뿐이다. `terraform/variables.tf` 의 `cluster_name` 은 선언만 있고 어느 리소스도 참조하지 않는다 — `grep -rn "var.cluster_name" *.tf` 가 0건이다. 나머지는 명령 인자다: `aws eks update-kubeconfig --name` 과 LBC helm 의 `--set clusterName`. mark 5-1-A 부터 5-4-A 까지 전부 이 이름으로 클러스터를 찾는다.

   </details>

2. EKS 버전 요구가 `1.35` 에서 `1.34` 로 바뀌면?

   <details>
   <summary>답 확인</summary>

   `cluster.yaml` 의 `version` 한 곳이다. 값에 따옴표를 빼면 YAML 이 숫자로 읽어 `1.34` 가 소수로 파싱된다. mark 5-1-A 는 `wskorea26-cluster 1.35` 처럼 이름과 버전을 한 줄로 비교하므로 문자열이 그대로 맞아야 한다.

   </details>

3. 노드그룹을 addon·app 둘에서 셋으로 늘리라면 어디를 고치고, 어디를 그대로 두나?

   <details>
   <summary>답 확인</summary>

   `cluster.yaml` 의 `managedNodeGroups` 에 항목을 하나 더 넣고 `labels`·`tags.Name`·`instanceName` 을 과제지 이름대로 채운다. `vpc.subnets` 와 `iam.serviceAccounts` 는 그대로 둔다 — 노드그룹이 같은 프라이빗 서브넷 두 개를 공유하기 때문이다. 필드 이름이 막히면 `eksctl utils schema` 출력이나 [schema.eksctl.io](https://schema.eksctl.io/)를 열고, 찾는 순서는 [검색 가이드](/reference/search-guide/)에 있다.

   </details>

4. `addonsConfig.disableDefaultAddons` 를 빼면 어느 체크가 흔들리나?

   <details>
   <summary>답 확인</summary>

   mark 5-4-A 다. 이 항목은 kube-system 파드가 올라간 노드의 `node-type` 라벨을 뽑아 중복을 지우고 출력한다. 기대값은 `addon` 한 줄인데, 기본 애드온이 설치되면 metrics-server 가 app 노드에 스케줄돼 `app` 이 함께 나온다. 예외로 빠지는 것은 `aws-node` 와 `kube-proxy` 둘뿐이다.

   </details>

막히면 [트러블슈팅](/reference/troubleshooting/), 그날을 끝냈으면 [잔존 리소스 점검](/reference/cleanup-check/)을 돌린다.
