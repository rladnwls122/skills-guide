이 모듈에서 새로 배울 개념은 없다. 무너지는 것은 지식이 아니라 순서다.

선행 지식과 목표는 [모듈 개요](/part-2/07-full-deploy-set02/)에.

**마지막 줄만 앞 모듈에 없다.** 나머지는 전부 한 번씩 손으로 해 본 것이다.

### 이 모듈에서 처음 나오는 것 — Audit Role

읽기 전용 감사자에게 권한을 위임하는 역할이다. 요구는 셋이다.

- 다른 신원이 이 역할을 맡을 수 있어야 하되, **약속된 문자열을 함께 제시해야만** 허용된다
- 한 번 맡으면 **정해진 시간** 뒤에 자동으로 끊긴다
- 맡은 뒤에 할 수 있는 일은 **읽기 중 일부로 제한**된다 — 전부가 아니다

세 요구가 각각 어느 필드로 가는지는 [iam-basics](/start/iam-basics/)의 신뢰 정책과 권한 정책 구분에서 나온다. `mark.sh` 의 `9-1-A`·`9-2-A` 가 이것을 잰다 — **약속된 문자열 없이 맡으려 하면 거부되는 것까지** 확인한다.

## 2. 이행 (타이머 4시간)

타이머를 걸고 시작한다. **여기부터 이 문서를 닫는다.**

막히면 해당 계층의 모듈 lab 을 연다. 어느 모듈인지는 위 표에 있다.

### 순서를 먼저 적고 시작한다

코드를 고치기 전에 **종이에 순서를 적는다.** 이것이 이 모듈의 핵심 훈련이다.

<Steps>

1. **의존을 적는다** — 무엇이 무엇의 출력을 받나. 예를 들어 클러스터는 서브넷 ID 를 받고, 워크로드는 타깃그룹 ARN 을 받는다

2. **병렬 가능한 것을 표시한다** — 클러스터 생성은 20분 걸린다. 그동안 놀지 않는다

3. **되돌리기 비싼 것을 표시한다** — 앞 모듈들이 각각 하나씩 짚었다. VPC CIDR, 버킷 이름, 파티션 키, Secret 암호화 키, ALB 스킴, Prometheus 저장소다. **이 여섯 개는 만들기 전에 확정한다**

</Steps>

세 번째가 이 실습에서 가장 비싼 실수를 막는다. 여섯 개를 `terraform.tfvars` 와 매니페스트에 먼저 적고 시작한다.

### 시간이 모자랄 때

전부 못 할 것 같으면 **버릴 것을 배점으로 고른다.** [07 이론 4절](/part-2/07-full-deploy-set02/theory/)에 세트별 배점이 있다. 관측성이 WAF 보다 무겁다.

버리는 것과 미완으로 두는 것은 다르다. **반쯤 만든 것이 채점을 깨뜨리는 경우가 있다** — 예를 들어 로그 그룹만 만들고 수집기를 못 붙이면 빈 그룹이 남아 오히려 혼선을 준다.

## 3. 통과 기준

배포 없이 판정되는 것부터 본다. 앞 모듈들의 3절을 합친 것이다.

<Steps>

1. **옛 이름 잔존 0건 — 전체 트리에서**

   <Tabs syncKey="shell">
     <TabItem label="PowerShell">
     ```powershell
     Select-String -Pattern 'wskorea26|node-type' -Path $HOME\final-run -Recurse |
       Select-Object -First 20
     ```
     </TabItem>
     <TabItem label="Bash (Linux/CloudShell)">
     ```bash
     grep -rnE 'wskorea26|node-type' ~/final-run | head -20
     ```
     </TabItem>
   </Tabs>

   기대: **출력 없음.** 주석과 `description` 도 포함이다 — 채점은 안 보지만 남아 있으면 자기가 헷갈린다.

2. **Terraform 이 계획을 낸다**

   ```bash
   terraform init -upgrade
   terraform validate
   terraform plan
   ```

   `validate` 가 막으면 오타인지 프로바이더인지부터 가른다 — [03 실습 6-2](/part-1/03-container-lambda-dynamodb/lab/)의 판정 순서다.

3. **클러스터 매니페스트가 펼쳐진다**

   ```bash
   eksctl create cluster -f cluster.rendered.yaml --dry-run
   ```

4. **k8s 매니페스트가 API 서버 검증을 통과한다**

   ```bash
   kubectl apply --dry-run=server -R -f rendered/
   ```

   클러스터가 아직 없으면 이 단계는 배포 뒤로 미룬다.

</Steps>

## 4. 복기

**배포 전에 한 번, 채점 뒤에 한 번** 한다. 배포 전 복기가 20분을 아낀다.

[set-07 `task-1/`](https://github.com/ishs-cloud-computing/skills-2026/tree/main/set-07/task-1) 전체와 대조한다. 계층별로 앞 모듈의 4절이 이미 대조 대상을 지목해 두었다.

놓친 곳을 셋으로 나누는 것은 같다. 여기서는 넷째가 붙는다.

- 과제지를 못 읽은 것
- 읽었는데 어디를 고칠지 못 찾은 것
- 찾았는데 틀린 것
- **알았는데 시간이 없어서 못 한 것** — 이것이 이 모듈에서 처음 세는 항목이다

넷째가 많으면 지식이 아니라 순서 문제다. 2절에서 적은 순서를 다시 본다.

## 5. 배포와 채점

### 순서

앞 단계가 뒤 단계의 입력을 만든다. 바꾸면 실패한다.

<Steps>

1. **Terraform** — 네트워크와 AWS 리소스. 출력을 파일로 굳힌다

2. **이미지 빌드·push** — Docker 가 필요하므로 CloudShell 에서. **3번과 병행한다**

3. **클러스터** — 약 20분. 2번과 동시에 돌린다

4. **작업 경로 확보** — private 클러스터면 `kubectl` 이 본 PC 에서 안 된다. [04 실습 5절](/part-2/04-eksctl-cluster/lab/)이 이 문제를 다룬다

5. **컨트롤러 → 워크로드 → 관측성** — 이 셋은 순서가 고정이다

6. **시드** — 채점이 볼 데이터를 만든다. CloudFront 전파와 로그 파이프라인 지연을 기다린다

</Steps>

2번과 3번을 병행하지 않으면 그것만으로 20분을 버린다.

### 채점

[set-07 `mark.sh`](https://github.com/ishs-cloud-computing/skills-2026/blob/main/set-07/task-1/mark.sh) 를 CloudShell VPC Environment 에서 돌린다.

**돌리기 전에 작업용 리소스를 지운다.** 4번에서 만든 접속용 EC2 가 남아 있으면 불필요 리소스 감점이다.

```bash
bash mark.sh 2>&1 | tee ~/mark-result.txt
```

항목별로 기대값과 대조하고 점수를 낸다. 목표는 **80% 이상**이다.

:::danger[안 되는지를 재는 항목을 놓치지 않는다]
`mark.sh` 에는 "되면 감점"인 항목이 셋 있다.

- `8-5-A` — 로드밸런서 직접 호출이 **응답하면** 안 된다
- `11-1-A` 둘째 줄 — 헬스체크 로그가 **한 건도** 없어야 한다
- `11-2-A` 둘째 줄 — 관리형 컴포넌트용 ServiceMonitor 가 **0** 이어야 한다

다른 항목을 다 맞히고 이 셋을 놓치는 경우가 많다. 만드는 데 집중하다 보면 "안 만들어야 하는 것"이 눈에 안 들어온다.
:::

## 6. 복구·진단 드릴 색인

이 모듈은 새 고장 시나리오를 만들지 않는다. 앞 모듈이 심어 둔 것을 **무작위로 골라 도는 것**이 여기서 할 일이다.

### 드릴 진행법

<Steps>

1. **주입은 짝에게 시킨다** — 혼자면 목록에서 무작위로 뽑되 **주입 명령만 보고 증상 설명은 읽지 않는다**

2. **타이머를 건다** — 원인을 짚는 데 걸린 시간을 잰다. 5분을 넘기면 그 계층이 약한 것이다

3. **짚은 뒤에 문서를 열어 대조한다** — 좁히는 순서가 문서와 달랐다면 왜 달랐는지 적는다

4. **복구까지 한다** — 원인만 알고 넘어가지 않는다. 복구 명령이 손에 붙어 있어야 당일에 쓴다

</Steps>

### 회고 양식

드릴이 끝나면 세 줄로 적는다.

- 어느 계층에서 가장 오래 걸렸나
- 건너뛴 단계가 있었나 (예: `describe` 를 안 보고 설정부터 고쳤다)
- 다음에 먼저 볼 것 하나

**같은 계층이 두 번 나오면 그 모듈의 이론으로 돌아간다.** 진단이 안 되는 것은 대개 구조를 모르는 것이다.

PART-6 의 종합 드릴은 이 색인을 전 파트로 넓힌 것이다.

## 7. 정리

**순서가 있다.** 뒤에서 앞으로 지운다.

<Steps>

1. **작업용 EC2** — 채점 전에 이미 지웠어야 한다. 남아 있으면 지금 지운다

2. **k8s 리소스와 helm release** — 볼륨이 남는지 확인한다

3. **클러스터** — `eksctl delete cluster`. 남은 CloudFormation 스택을 직접 센다

4. **DynamoDB 삭제 방지 해제** — 끄고 apply 한 뒤에야 destroy 가 된다

5. **버킷 비우기** — 버전 관리를 켰으므로 버전까지 지운다

6. **Terraform destroy**

</Steps>

각 단계의 명령과 함정은 해당 모듈의 8절에 있다. 여기서는 순서만 지킨다.
