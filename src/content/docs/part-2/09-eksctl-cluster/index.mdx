## 학습 목표

- [ ] eksctl ClusterConfig의 5대 블록(metadata / vpc / iam / managedNodeGroups / addons)을 백지에 쓸 수 있다
- [ ] IRSA(OIDC) vs Pod Identity vs Access Entry 3방식의 차이와 **세트별 채점 갈림**을 설명할 수 있다
- [ ] 노드그룹 2분할(addon/app)의 이유(mark 5-4)와 label/taint 설계를 설명할 수 있다
- [ ] `${VAR}` 플레이스홀더를 terraform output으로 치환해 클러스터를 생성할 수 있다
- [ ] `tags.Name` vs `instanceName` 함정, `disableDefaultAddons` 함정을 안다
- [ ] set-02 구성을 set-07 의 private·Pod Identity 요구로 **직접 이행**할 수 있다
- [ ] 잘못 만든 값을 만났을 때 **수정 API 가 있는지로** 고칠지 다시 만들지 판정할 수 있다
- [ ] 파드가 안 뜨거나 AWS 호출이 거부될 때 계층을 좁혀 원인을 짚을 수 있다

:::caution[과금 주의 — destroy 방침 예외]
**04 → 05는 클러스터를 삭제하지 않고 유지한다.**

클러스터 하루 방치 비용 ≈ $0.10×24 + $0.21×24 ≈ **$7.4/일** — 잊지 말 것.

## 선행 지식

- 컨트롤 플레인(EKS가 관리) ↔ 노드(EC2) 분담. `kubectl`은 API server로 간다 — [k8s-basics](/start/k8s-basics/)
- ServiceAccount = 파드의 신원. IRSA·Pod Identity는 여기에 IAM 역할을 붙이는 방식 — [k8s-basics](/start/k8s-basics/)
- 신뢰 정책(문지기) + 호출자 권한, **둘 다** 통과해야 AssumeRole이 성립 — [iam-basics](/start/iam-basics/)
- 클러스터를 만든 신원만 기본 kubectl 접근을 갖는다 — [iam-basics](/start/iam-basics/)
- IRSA 는 OIDC 공급자를, Pod Identity 는 EKS 서비스 주체를 신뢰 근거로 쓴다 — [eks-basics](/start/eks-basics/)
- VPC CNI 가 파드에 VPC IP 를 직접 준다. 서브넷 IP 와 ENI 상한이 곧 파드 상한 — [eks-basics](/start/eks-basics/)
- 노드는 프라이빗 서브넷에 있다. NAT 경로가 없으면 이미지 pull부터 실패 — [vpc-basics](/start/vpc-basics/)

막히는 항목이 있으면 그 링크를 먼저 읽는다. 아니면 바로 다음 파일로 간다.
