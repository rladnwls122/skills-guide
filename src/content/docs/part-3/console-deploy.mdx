> 문서 유형: how-to

[PART-1](/part-1/console-deploy/)은 코드와 실제가 어긋날 때를, [PART-2](/part-2/console-deploy/)는 되돌리는 주체가 다를 때를 다뤘다. PART-3 은 **코드에 아예 없는 리소스**를 다룬다.

[16 실습](/part-3/16-private-eks-iam/lab/)의 작업 호스트가 그 예다. 손으로 만들었으니 `plan` 이 모르고, **지우는 것도 사람 몫이다.** 그것을 잊으면 불필요 리소스 감점이다.

:::note[클릭 순서는 적지 않는다]
콘솔 화면은 자주 바뀐다. **무엇을 만들려는지**와 **만든 뒤 무엇을 확인하는지**만 적는다.
:::

## 1. 같은 리소스, 두 경로

VPC 엔드포인트 하나를 콘솔로 만들고 코드가 만든 것과 대조한다. 닫힌 환경에서 가장 자주 손대는 리소스다.

### 만들 것

`com.amazonaws.<리전>.ssm` 인터페이스 엔드포인트 하나. 서브넷 하나에만 붙이고 이름 태그는 `console-lab-ep` 로 둔다.

:::caution[비용]
인터페이스 엔드포인트는 **ENI 하나당 시간당 과금**된다. 확인이 끝나면 정리 절에서 바로 지운다.
:::

### 만든 뒤 확인

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  aws ec2 describe-vpc-endpoints --filters "Name=tag:Name,Values=console-lab-ep" `
    --query "VpcEndpoints[].{Id:VpcEndpointId,Service:ServiceName,Type:VpcEndpointType,PrivateDns:PrivateDnsEnabled,State:State,Subnets:SubnetIds,SGs:Groups[].GroupId}" --output json
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  aws ec2 describe-vpc-endpoints --filters "Name=tag:Name,Values=console-lab-ep" \
    --query 'VpcEndpoints[].{Id:VpcEndpointId,Service:ServiceName,Type:VpcEndpointType,PrivateDns:PrivateDnsEnabled,State:State,Subnets:SubnetIds,SGs:Groups[].GroupId}' --output json
  ```
  </TabItem>
</Tabs>

기대: 엔드포인트 하나가 JSON 으로 나온다.

**`PrivateDns` 값을 눈에 담아 둔다.** 다음 절이 그것을 다룬다.

## 2. 콘솔이 몰래 정하는 것

PART-1·2 는 콘솔이 **만드는** 것을 셌다. 여기서는 콘솔이 **정하는** 것이 문제다.

### 프라이빗 DNS 기본값

인터페이스 엔드포인트 마법사는 프라이빗 DNS 를 **기본으로 켠 상태**로 제시한다. 그 한 칸이 닫힌 환경의 동작을 가른다.

| 프라이빗 DNS | 서비스 이름을 조회하면 | 닫힌 환경에서 |
|---|---|---|
| 켜짐 | **VPC 안의 프라이빗 IP** 가 나온다 | 정상 동작 |
| 꺼짐 | 퍼블릭 IP 가 나온다 | **나갈 길이 없어 타임아웃** |

**꺼져 있을 때의 증상이 방화벽 문제와 똑같다.** 이름은 풀리는데 안 닿으니 보안 그룹부터 뒤지게 된다. [16 실습 7-1](/part-3/16-private-eks-iam/lab/)의 좁히는 순서가 "이름이 풀리나"를 두 번째로 두는 이유가 이것이다.

기본값이 켜짐이라 콘솔로 만들면 대개 문제가 없다. **문제는 반대다** — 코드로 만들 때 그 인자를 안 적으면 프로바이더 기본값이 꺼짐일 수 있다. 콘솔과 코드의 기본값이 다르다.

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  aws ec2 describe-vpc-endpoints --query "VpcEndpoints[?VpcEndpointType=='Interface'].{Service:ServiceName,PrivateDns:PrivateDnsEnabled}" --output table
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  aws ec2 describe-vpc-endpoints --query "VpcEndpoints[?VpcEndpointType=='Interface'].{Service:ServiceName,PrivateDns:PrivateDnsEnabled}" --output table
  ```
  </TabItem>
</Tabs>

기대: 계정의 인터페이스 엔드포인트가 전부 나오고 값이 섞여 있으면 그 자체가 신호다. **콘솔로 만든 것과 코드로 만든 것의 기본값이 갈린 흔적**이다.

### 보안 그룹 기본값

엔드포인트에 붙일 보안 그룹을 안 고르면 **VPC 의 기본 보안 그룹**이 붙는다. 기본 보안 그룹은 자기 자신을 출처로 하는 인바운드만 허용하므로, **다른 보안 그룹을 쓰는 인스턴스에서 접근이 막힌다.**

이것도 증상이 방화벽 문제로 보인다. [16 실습 7-1](/part-3/16-private-eks-iam/lab/)의 마지막 단계가 엔드포인트 보안 그룹을 보는 이유다.

### 정책 마법사가 넓게 준다

IAM 역할을 콘솔로 만들 때 정책을 고르는 화면에서 관리형 정책을 붙이기 쉽다. 그것들은 대개 **필요한 것보다 넓다.**

채점이 최소권한을 보는 세트에서는 이것이 감점이다. [16 이론 주제 4](/part-3/16-private-eks-iam/theory/)가 다루듯 **좁힐 수 있는 것만 좁힌 형태**가 통과하는 형태다.

## 3. drift 판단 — 코드가 모르는 리소스

**이 절이 이 문서의 존재 이유다.**

지금까지의 drift 는 "코드에 있는데 값이 다르다"였다. 여기서는 **코드에 아예 없다.**

### 무엇이 문제인가

[16 실습](/part-3/16-private-eks-iam/lab/)의 작업 호스트를 예로 든다. 닫힌 클러스터라 본 PC 에서 `kubectl` 이 안 되니 접속용 EC2 를 손으로 만들었다. 그 EC2 는 이렇다.

| | 상태 |
|---|---|
| AWS 가 아는가 | 안다 — 실행 중이고 과금된다 |
| Terraform 이 아는가 | **모른다** |
| `terraform plan` 이 알려 주나 | **아니다.** 코드에 없으니 비교 대상도 없다 |
| `terraform destroy` 가 지우나 | **아니다** |
| 채점이 보나 | **본다 — 불필요 리소스 감점** |

**`plan` 이 조용하다는 것이 안전하다는 뜻이 아니다.** 코드 밖 리소스에 대해서는 `plan` 이 아무 말도 할 수 없다.

### 찾는 방법은 조회뿐이다

코드가 모르므로 도구가 알려 주지 않는다. 사람이 세는 수밖에 없다.

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  aws ec2 describe-instances --filters Name=instance-state-name,Values=running `
    --query "Reservations[].Instances[].{Id:InstanceId,Name:Tags[?Key=='Name']|[0].Value,Type:InstanceType}" --output table
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  aws ec2 describe-instances --filters Name=instance-state-name,Values=running \
    --query "Reservations[].Instances[].{Id:InstanceId,Name:Tags[?Key=='Name']|[0].Value,Type:InstanceType}" --output table
  ```
  </TabItem>
</Tabs>

기대: 목록에 **클러스터 노드 말고 다른 것이 있으면** 그것이 코드 밖 리소스다.

이 조회를 습관으로 만든다. [15 실습 7절](/part-2/15-full-deploy-set02/lab/)의 정리 확인과 같은 명령이다.

### 선택지는 셋이다

| 선택 | 무엇을 하나 | 옳은 때 |
|---|---|---|
| **코드로 옮긴다** | 그 리소스를 tf 로 선언하고 스위치를 단다 | **연습 때.** set-03 이 이 길을 골랐다 |
| **손으로 만들고 손으로 지운다** | 만든 것을 목록에 적어 두고 채점 전에 지운다 | 당일, 급할 때 |
| **import 한다** | 이미 만든 것을 상태에 등록한다 | 거의 없다 — [PART-1](/part-1/console-deploy/) 참조 |

**첫 번째와 두 번째의 갈림이 [16 실습](/part-3/16-private-eks-iam/lab/)의 변동 그 자체다.** set-07 은 손으로 만들고 손으로 지우고, set-03 은 코드에 넣고 변수 하나로 켜고 끈다.

두 방식의 진짜 차이는 편의가 아니라 **잊을 수 있는가**다.

- 손으로 만든 것은 **채점 전에 기억해서 지워야 한다.** 대회 막판에 그것을 기억할 확률은 낮다
- 코드에 있으면 **지우는 것이 배포 절차의 일부**가 된다. 변수를 끄고 apply 하면 끝난다

### 목록을 적는 습관

당일에 손으로 만들 것이 생기면 **만드는 순간 어딘가에 적는다.** 종이든 메모장이든 상관없다.

적을 것은 셋이다 — **무엇을, 어느 리전에, 왜.** 마지막이 중요하다. 이유를 적어 두면 채점 전에 "이건 지워도 되나"를 판단할 수 있다.

## 4. 판단표 — 콘솔이 옳은 때, 코드가 옳은 때

| 상황 | 고르는 쪽 | 이유 |
|---|---|---|
| 엔드포인트를 하나 급히 추가한다 | **콘솔** | 닫힌 환경에서 막혔을 때 가장 빠른 우회다 |
| 엔드포인트 여러 개를 놓는다 | **코드** | 서비스 이름만 다르고 나머지가 같다 |
| 접속용 호스트를 만든다 | **연습은 코드, 당일은 콘솔** | 당일은 속도, 연습은 지우는 습관 |
| IAM 역할을 최소권한으로 만든다 | **코드** | 콘솔 마법사는 넓게 준다 |
| 정책 한 줄을 급히 고친다 | **콘솔** | 전파가 빠르고 되돌리기도 쉽다 |
| 프라이빗 DNS 를 켠다 | **어느 쪽이든** | 다만 **코드는 인자를 명시**한다 — 기본값이 콘솔과 다르다 |

### 한 줄로

**닫힌 환경에서 콘솔은 우회로지 건설 도구가 아니다.**

우회로로 쓴 것은 반드시 목록에 남기고, 채점 전에 그 목록을 지워 나간다. [16 실습 6-3](/part-3/16-private-eks-iam/lab/)이 그 실수를 다룬다 — 고치는 문제가 아니라 **존재 자체가 감점**인 유일한 종류다.

## 정리

이 문서에서 만든 엔드포인트를 지운다. **시간당 과금이라 잊으면 계속 나간다.**

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  $E = aws ec2 describe-vpc-endpoints --filters "Name=tag:Name,Values=console-lab-ep" --query "VpcEndpoints[0].VpcEndpointId" --output text
  aws ec2 delete-vpc-endpoints --vpc-endpoint-ids $E
  aws ec2 describe-vpc-endpoints --filters "Name=tag:Name,Values=console-lab-ep" --query "VpcEndpoints[].VpcEndpointId" --output text
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  E=$(aws ec2 describe-vpc-endpoints --filters "Name=tag:Name,Values=console-lab-ep" --query 'VpcEndpoints[0].VpcEndpointId' --output text)
  aws ec2 delete-vpc-endpoints --vpc-endpoint-ids "$E"
  aws ec2 describe-vpc-endpoints --filters "Name=tag:Name,Values=console-lab-ep" --query 'VpcEndpoints[].VpcEndpointId' --output text
  ```
  </TabItem>
</Tabs>

기대: 마지막 조회가 빈 출력. 삭제에 잠시 걸리므로 바로 안 비면 다시 조회한다.

**코드 밖 리소스 전체 점검**은 위 3절의 인스턴스 조회와 [잔존 리소스 점검](/reference/cleanup-check/)을 함께 돌린다.
