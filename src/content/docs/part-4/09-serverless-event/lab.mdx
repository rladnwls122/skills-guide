## Part A — 유형 1 · 서버리스 워크플로 (ap-southeast-1)

<Steps>

1. **A-1. 배포**

   ```powershell
   cd ~\skills-2026\set-02\task-2\module-1-workflow\terraform
   terraform init
   terraform apply -var "player_number=$env:NUM"
   terraform output -json > outputs.json
   ```

2. **A-2. 리소스 검증**

   ```powershell
   $NUM = $env:NUM
   $B = "wsc2026-student-score-bucket-$NUM"
   $env:AWS_DEFAULT_REGION = "ap-southeast-1"

   aws dynamodb describe-table --table-name wsc2026-student-score --query "Table.[TableName,KeySchema]" --output json
   aws lambda get-function-configuration --function-name wsc2026-student-score-function --query "[FunctionName,Runtime,Environment.Variables]" --output json
   $SM_ARN = aws stepfunctions list-state-machines --query "stateMachines[?name=='wsc2026-student-score-workflow'].stateMachineArn" --output text
   aws stepfunctions describe-state-machine --state-machine-arn $SM_ARN --query "[name,type]" --output text
   ```

   <details class="diagram-note">
   <summary>이 블록이 하는 일</summary>

   배포된 리소스 셋을 각각 확인한다. DynamoDB 는 테이블 이름과 키 구성, Lambda 는 런타임과 환경 변수, Step Functions 는 이름과 유형(Standard)이다. 상태 머신은 이름으로 바로 조회가 안 돼 목록에서 ARN 을 먼저 찾는다.

   </details>

   기대 출력:

   - 테이블: `wsc2026-student-score`, KeySchema `studentId` HASH + `examDate` RANGE
   - Lambda: `wsc2026-student-score-function`, `python3.12`, env에 S3_BUCKET/DDB_TABLE
   - State Machine: `wsc2026-student-score-workflow  STANDARD`

3. **A-3. 최종 실행 절차** (채점 직전 리셋 — 순서 엄수)

   ```powershell
   # 1) 잔여물 제거
   aws s3 rm s3://$B/processed/ --recursive
   aws s3 rm s3://$B/error/ --recursive

   # 2) DynamoDB 비우기
   $items = aws dynamodb scan --table-name wsc2026-student-score --query "Items[].{studentId:studentId,examDate:examDate}" --output json | ConvertFrom-Json
   foreach ($i in $items) {
     $key = ($i | ConvertTo-Json -Compress) -replace '"', '\"'
     aws dynamodb delete-item --table-name wsc2026-student-score --key $key
   }

   # 3) test.csv 정확 1회 업로드
   aws s3 cp ..\..\provided\module1\test.csv s3://$B/input/test.csv

   # 4) 실행 확인
   aws stepfunctions list-executions --state-machine-arn $SM_ARN --query "executions[].[status,startDate]" --output text
   ```

   <details class="diagram-note">
   <summary>이 블록이 하는 일</summary>

   채점 직전 리셋 절차다. 순서가 중요하다 — 앞선 실행이 남긴 `processed/`·`error/` 객체와 DynamoDB 항목을 먼저 비우고, 그다음 `test.csv` 를 **정확히 한 번** 올린다. 두 번 올리면 오류 JSON 이 8개가 되어 기대값과 어긋난다. 마지막 조회로 실행이 한 건만 SUCCEEDED 인지 확인한다.

   </details>

4. **A-4. 결과 검증 + 기대 출력**

   ```powershell
   aws dynamodb get-item --table-name wsc2026-student-score --key '{\"studentId\":{\"S\":\"STU1020\"},\"examDate\":{\"S\":\"2026-05-30\"}}' --query "Item.[studentId.S,average.N,grade.S]" --output text
   # 기대: STU1020    96.6    A   (항목이 아예 없으면 float 저장이 TypeError 로 죽은 것)

   aws s3 ls s3://$B/
   # 기대: PRE error/  PRE input/  PRE processed/  — 딱 3줄

   aws s3 ls s3://$B/processed/
   # 기대: test.csv 한 줄만

   aws s3 ls s3://$B/error/
   # 기대: error_*_STU2001 / STU2002 / STU2004 / unknown .json — 정확히 4개
   ```

   <details class="diagram-note">
   <summary>이 블록이 하는 일</summary>

   결과를 네 지점에서 대조한다. 특정 학생의 평균·등급이 기대값과 같은지, 버킷 최상위에 접두어가 정확히 셋인지, `processed/` 에 파일이 하나인지, `error/` 에 오류 JSON 이 넷인지다. 첫 조회에서 항목이 아예 없다면 평균을 float 로 저장하려다 함수가 죽은 경우다.

   </details>

</Steps>

### A-5. :badge[함정]{variant=danger} (여기서 대부분 틀린다)

- test.csv 2회 업로드 → error JSON 8개 → 오답. 재실행은 반드시 A-3의 1)~2)부터.
- processed/·error/에 폴더 마커를 만들어두면 `s3 ls`에 0바이트 잉여 라인 → 오답. 마커는 `input/`만.
- 평균을 float로 계산 → boto3 가 `Float types are not supported` 로 저장 거부. `decimal.Decimal` 로 계산·저장.
- 처리 Lambda 이름은 mark에만 있다(`wsc2026-student-score-function`) — task.md만 보고 이름을 지어내면 0점.
- PowerShell에서 JSON 인자는 `\"` 이스케이프 필수.

### A-6. 통과 기준

- [ ] A-2 세 항목 모두 기대값 일치
- [ ] SUCCEEDED 실행 정확 1건
- [ ] STU1020 96.6 A / processed 1개 / error 4개

## Part B — 유형 2 · 이벤트 자동복구 (eu-west-1)

<Steps>

1. **B-1. 배포**

   ```powershell
   cd ~\skills-2026\set-02\task-2\module-3-event\terraform
   terraform init
   terraform apply -var "player_number=$env:NUM"
   ```

   **apply 후 5~10분 대기** — CloudTrail 이벤트 전달 활성화 + Config 첫 평가. 급하면:

   ```powershell
   $env:AWS_DEFAULT_REGION = "eu-west-1"
   aws configservice start-config-rules-evaluation --config-rule-names wsc2026-required-tags-rule wsc2026-sg-ssh-rule
   ```

2. **B-2. 리소스 검증**

   ```powershell
   $env:AWS_DEFAULT_REGION = "eu-west-1"
   $ACCOUNT_ID = aws sts get-caller-identity --query Account --output text
   $INSTANCE_ID = aws ec2 describe-instances --filters "Name=tag:Name,Values=wsc2026-event-ec2" "Name=instance-state-name,Values=running,stopped" --query "Reservations[0].Instances[0].InstanceId" --output text
   $SG_ID = aws ec2 describe-security-groups --filters "Name=group-name,Values=wsc2026-event-sg" --query "SecurityGroups[0].GroupId" --output text

   # Lambda 4개 (mark) + 2개 (task 전용) — 전부 python3.12
   foreach ($fn in "wsc2026-ec2-stop-remediation","wsc2026-ec2-terminate-alert","wsc2026-sg-remediation","wsc2026-tag-alert","wsc2026-role-remediation","wsc2026-ec2-type-remediation") { aws lambda get-function --function-name $fn --query "Configuration.[FunctionName,Runtime]" --output text }
   # EventBridge 타깃
   foreach ($rule in "wsc2026-ec2-stop-rule","wsc2026-ec2-terminate-rule") { "$rule -> $(aws events list-targets-by-rule --rule $rule --query 'Targets[0].Arn' --output text)" }
   # Config 룰 ACTIVE
   aws configservice describe-config-rules --config-rule-names wsc2026-sg-ssh-rule wsc2026-required-tags-rule --query "ConfigRules[*].[ConfigRuleName,ConfigRuleState]" --output text
   ```

   <details class="diagram-note">
   <summary>이 블록이 하는 일</summary>

   유형 2 스택의 배선을 확인한다. 인스턴스와 보안 그룹 ID 를 태그·이름으로 역조회해 변수에 담고, 함수 6개의 런타임을 한 번에 훑고, EventBridge 룰에 타깃이 붙어 있는지 보고, Config 룰이 `ACTIVE` 인지 본다. 이 네 가지가 갖춰져야 복구 시연이 성립한다.

   </details>

3. **B-3. 복구 시연 + 기대 출력**

   ```powershell
   # 위반 주입: 중지 + SSH 인바운드 추가
   aws ec2 stop-instances --instance-ids $INSTANCE_ID | Out-Null
   aws ec2 authorize-security-group-ingress --group-id $SG_ID --protocol tcp --port 22 --cidr 0.0.0.0/0 | Out-Null
   Start-Sleep 90

   "EC2 State: $(aws ec2 describe-instances --instance-ids $INSTANCE_ID --query 'Reservations[0].Instances[0].State.Name' --output text)"
   # 기대: running
   "SG Inbound Count: $(aws ec2 describe-security-groups --group-ids $SG_ID --query 'SecurityGroups[0].IpPermissions | length(@)' --output text)"
   # 기대: 0
   aws configservice get-compliance-details-by-config-rule --config-rule-name wsc2026-required-tags-rule --compliance-types NON_COMPLIANT --query "EvaluationResults[0].EvaluationResultIdentifier.EvaluationResultQualifier.ResourceId" --output text
   # 기대: None
   ```

   <details class="diagram-note">
   <summary>이 블록이 하는 일</summary>

   위반을 일부러 만들고 자동 복구를 확인한다. 인스턴스를 중지하고 SSH 인바운드를 열어 둔 뒤 90초를 기다린다 — CloudTrail 경유 경로라 즉시 반응하지 않기 때문이다. 기대값은 인스턴스가 다시 `running`, 인바운드 규칙 수가 0, 태그 규칙 위반 리소스가 없음이다.

   </details>

4. **B-4. 타입 원복 시연** (task 전용, 수동 채점 대비)

   ```powershell
   aws events disable-rule --name wsc2026-ec2-stop-rule          # 필수! 레이스 방지
   aws ec2 stop-instances --instance-ids $INSTANCE_ID
   aws ec2 wait instance-stopped --instance-ids $INSTANCE_ID
   aws ec2 modify-instance-attribute --instance-id $INSTANCE_ID --instance-type t3.small
   aws ec2 start-instances --instance-ids $INSTANCE_ID
   Start-Sleep 180
   aws ec2 describe-instances --instance-ids $INSTANCE_ID --query "Reservations[0].Instances[0].[InstanceType,State.Name]" --output text
   # 기대: t3.micro    running   (자동 원복)
   aws events enable-rule --name wsc2026-ec2-stop-rule
   ```

   <details class="diagram-note">
   <summary>이 블록이 하는 일</summary>

   인스턴스 타입 원복을 시연한다. 첫 줄의 룰 비활성화가 필수다 — 켜 둔 채로 인스턴스를 멈추면 중지 복구 함수가 인스턴스를 다시 켜 버려 타입 변경이 `IncorrectInstanceState` 로 실패한다. 타입을 바꾸고 시작한 뒤 3분을 기다리면 복구 함수가 원래 타입으로 되돌린다. 마지막에 룰을 반드시 다시 켠다.

   </details>

</Steps>

### B-5. :badge[함정]{variant=danger}

- 배포 직후 바로 B-3 실행 → SG 복구 실패처럼 보임. CloudTrail 경로는 활성화+전달까지 수 분. 첫 시도에서 Inbound가 1이면 잠시 후 B-3만 재실행.
- stop-rule 비활성화 없이 타입 시연 → `IncorrectInstanceState` (stop-remediation이 인스턴스를 다시 켜는 레이스).
- 프로파일 이름에 `-profile` 접미사 → role 원복 실패. 프로파일 이름 = 역할 이름.
- Config 스코프를 넓히면 태그 없는 관리형 리소스가 NON_COMPLIANT → "None" 기대 깨짐.
- 타입 시연 후 plan에 diff가 보이면 `lifecycle.ignore_changes = [instance_type]` 누락.

### B-6. 통과 기준

- [ ] 함수 6개 전부 python3.12로 조회됨
- [ ] stop/terminate 룰 타깃이 각각 stop-remediation / terminate-alert Lambda ARN
- [ ] Config 룰 2개 ACTIVE
- [ ] B-3: running / 0 / None
- [ ] B-4: t3.micro running 자동 원복
