> 문서 유형: 개요

2과제 유형 세 개를 다룬다: **유형 3 — 오토스케일링**(SQS→KEDA→Karpenter, set-07 task-2 module-3 — 실채점 전 항목 통과 확정), **유형 4 — 로깅**(OTel→Loki→Grafana, set-07 task-2 module-4 — **정답지 미착수**, 과제지·`mark4.sh` 기반 설계안), **유형 5 — 스트리밍**(Kinesis/Flink Studio·MSK, set-02 task-2 module-2·4 — **정답지 대조 필수, 배포는 선택**).

## 학습 목표

- [ ] SQS 큐 길이 → KEDA(Pod 1~5) → Karpenter(Node) 2단 스케일링 체인을 백지에서 그릴 수 있다
- [ ] scaleDown `stabilizationWindowSeconds: 15`(+ `Percent 100/15s`) + NodePool `consolidateAfter: 60s`가 "150초 내 수렴" 채점과 한 쌍인 이유를 설명할 수 있다
- [ ] Pod requests 500m×5가 t3.medium 1대(allocatable ~1.9 vCPU)를 넘어 노드 2대가 유발되는 계산을 할 수 있다
- [ ] Karpenter 디스커버리 태그(`karpenter.sh/discovery` 서브넷, `aws:eks:cluster-name` SG)의 역할을 안다
- [ ] OTel Collector filelog(container 파서) → Loki OTLP → Grafana 로그 파이프라인을 구성할 수 있다
- [ ] LogQL `{k8s_namespace_name="..."} | json | level="ERROR"` 쿼리와 라벨 승격 원리를 설명할 수 있다
- [ ] Kinesis `wsc2026-order-stream`(`ACTIVE`/`ON_DEMAND`)와 Flink `wsc2026-analytics-flink`(`READY`/`ZEPPELIN-FLINK-3_0`)가 채점하는 값을 정확히 말할 수 있다
- [ ] MSK `wsc2026-msk-cluster`(`ACTIVE`/`3.6.0`/`kafka.t3.small`/`Sasl.Iam.Enabled=True`)와 DynamoDB가 `temperature.S`로 조회되는 이유를 설명할 수 있다

## 소요 시간 / 일차

- Day 11, 약 7~9시간 (이론 2h + 유형 3 실습 2.5h + 유형 4 실습 3h + 유형 5 정답지 대조 1h) — 유형 5를 실제로 배포하면 module-2 기준 +30분, module-4(MSK) 기준 +1시간 내외 추가된다
- EKS 클러스터 생성 ~20분 ×2회가 포함되므로 두 실습을 병렬로 돌리면 단축된다 (리전이 달라 간섭 없음)

## 과금 리소스와 destroy 방침

| 리소스 | 과금 | 방침 |
|---|---|---|
| **EKS 클러스터 ×2** (skm-eks-cluster, o11y-cluster) | **시간당 컨트롤플레인 과금 (가장 큼)** | **실습 종료 즉시 `eksctl delete cluster`** |
| 노드 EC2 (t3.medium 등) | 시간당 과금 | 클러스터 삭제로 함께 정리 |
| NAT Gateway (모듈 VPC) | 시간당 + 처리량 | terraform destroy 즉시 |
| ALB ×2 (유형 4) | 시간당 과금 | terraform destroy |
| SQS / ECR / EBS PV | 소액 | destroy로 정리 |
| MSK 브로커 ×2 (유형 5, 선택 — set-02 module-4) | **생성 ~30분 + 시간당 과금 (큼)** | 확인 즉시 `terraform destroy` |
| Kinesis+Flink+EC2+ALB+NAT (유형 5, 선택 — set-02 module-2) | 시간당 과금(생성 지연 없음) | 확인 즉시 `terraform destroy` |

:::caution[삭제 순서 주의]
k8s 리소스(TGB, Karpenter 노드) → helm → `eksctl delete cluster` → `terraform destroy`. Karpenter가 만든 노드가 남아 있으면 클러스터 삭제가 걸릴 수 있으니 NodePool을 먼저 지운다.
:::

유형 5는 기본적으로 배포하지 않는다 — 정답지 코드와 mark 항목 대조만으로 학습 목표를 채울 수 있다. 실제로 배포하면(특히 MSK) 과금이 크므로 [Lab Part C](/part-4/10-scaling-logging-streaming/lab/)의 즉시 destroy 절차를 반드시 따른다.
