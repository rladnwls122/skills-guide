> 문서 유형: 개요

2과제 **유형 3 — 이벤트 기반 오토스케일링**을 다룬다. 기준본은 set-07 task-2 module-3 이다(실채점 전 항목 통과 확정). 이행 타깃은 같은 체인을 다른 값으로 쓰는 set-08 task-2 module-4 다.

같은 파트의 나머지 유형은 따로 갈라져 있다 — [16. 컨테이너 로깅](/part-4/16-container-logging/), [17. 스트리밍](/part-4/17-streaming/).

## 학습 목표

- [ ] SQS 큐 길이 → KEDA(Pod 1~5) → Karpenter(Node) 2단 스케일링 체인을 백지에서 그릴 수 있다
- [ ] scaleDown `stabilizationWindowSeconds: 15`(+ `Percent 100/15s`) + NodePool `consolidateAfter: 60s`가 "150초 내 수렴" 채점과 한 쌍인 이유를 설명할 수 있다
- [ ] Pod requests 500m×5가 t3.medium 1대(allocatable ~1.9 vCPU)를 넘어 노드 2대가 유발되는 계산을 할 수 있다
- [ ] Karpenter 디스커버리 태그(`karpenter.sh/discovery` 서브넷, `aws:eks:cluster-name` SG)의 역할을 안다
- [ ] set-08 module-4(Fargate 컨트롤러 + SQS)가 set-07 module-3과 갈리는 지점 — `min 0`이면 `pollingInterval`이 유효해지는 이유, TriggerAuthentication, nodeSelector 2개 — 을 설명할 수 있다

## 소요 시간

- 약 4~5시간 (이론 1.5h + 기준본 실습 2h + 이행 1h). EKS 클러스터 생성 ~20분이 포함된다. Week 3.

## 과금 리소스와 destroy 방침

| 리소스 | 과금 | 방침 |
|---|---|---|
| **EKS 클러스터** (skm-eks-cluster) | **시간당 컨트롤플레인 과금 (가장 큼)** | **실습 종료 즉시 `eksctl delete cluster`** |
| 노드 EC2 (t3.medium 등) | 시간당 과금 | 클러스터 삭제로 함께 정리 |
| NAT Gateway (모듈 VPC) | 시간당 + 처리량 | terraform destroy 즉시 |
| SQS / ECR / EBS PV | 소액 | destroy로 정리 |

:::caution[삭제 순서 주의]
k8s 리소스(TGB, Karpenter 노드) → helm → `eksctl delete cluster` → `terraform destroy`. Karpenter가 만든 노드가 남아 있으면 클러스터 삭제가 걸릴 수 있으니 NodePool을 먼저 지운다.
:::

## 선행 지식

:::tip[개념이 낯설면 여기부터]
이 모듈의 이론은 **1장 요약**이라 서비스 개념을 설명하지 않고 시간 예산과 채점 함정부터 다룬다. 다음 네 가지 중 하나라도 흐릿하면 [autoscaling-basics](/start/autoscaling-basics/)를 먼저 읽는다(약 1.5시간).

- HPA의 이용률 계산과 안정화 창
- KEDA의 ScaledObject가 HPA를 만들어 준다는 구조
- Karpenter가 Cluster Autoscaler와 다른 점
- Fargate 프로파일

SQS 자체가 처음이면 [serverless-basics](/start/serverless-basics/)의 SQS 절도 함께 본다.
:::

- HPA·KEDA·Karpenter·Fargate가 각각 무엇을 조정하는지 — [autoscaling-basics](/start/autoscaling-basics/)
- SQS 큐 길이 지표와 가시성 제한 시간 — [serverless-basics](/start/serverless-basics/)
- Deployment의 `replicas`를 바깥에서 조종하는 것이 오토스케일러(KEDA/HPA)다 — [k8s-basics](/start/k8s-basics/)
- 파드 `requests`가 스케줄링 단위 — 노드 수 계산의 입력값 — [k8s-basics](/start/k8s-basics/)
- ServiceAccount에 붙는 IAM 역할이 SQS·S3 접근을 만든다 — [iam-basics](/start/iam-basics/)

막히는 항목이 있으면 그 링크를 먼저 읽는다. 아니면 바로 다음 파일로 간다.
