> 문서 유형: 개요

2과제 **유형 4 — 컨테이너 로깅 파이프라인**을 다룬다. 기준본은 set-07 task-2 module-4 이고 정답지 구현이 있다(`module-4-container-logging`).

**리전은 `ap-northeast-1`(도쿄)** 다. 앞 모듈이 서울이므로 시작 전에 리전부터 다시 세운다 — 틀리면 리소스는 만들어져도 채점이 그 모듈을 0점으로 본다.

## 학습 목표

- [ ] OTel(OpenTelemetry) Collector filelog(container 파서) → Loki OTLP → Grafana 경로를 백지에서 그린다
- [ ] LogQL `{k8s_namespace_name="..."} | json | level="ERROR"` 쿼리와 라벨 승격 원리를 설명한다
- [ ] 순서 의존을 지킨다 — LBC 설치가 TargetGroupBinding CRD 를 만들고, Loki 가 있어야 OTel 이 보낼 곳이 생긴다
- [ ] 제공 Dockerfile 의 결함(의존성 미설치)을 찾아 자기 Dockerfile 로 대체한다
- [ ] 대시보드 패널이 비었을 때 원인을 파이프라인의 어느 고리인지로 좁힌다

## 소요 시간

- 약 3~4시간 (이론 1h + 실습 2~3h). EKS 클러스터 생성 ~20분이 포함된다. Week 3.

## 과금 리소스와 destroy 방침

| 리소스 | 과금 | 방침 |
|---|---|---|
| **EKS 클러스터** (o11y-cluster) | **시간당 컨트롤플레인 과금 (가장 큼)** | 실습 종료 즉시 `eksctl delete cluster` |
| 노드 EC2 | 시간당 과금 | 클러스터 삭제로 함께 정리 |
| NAT Gateway | 시간당 + 처리량 | terraform destroy 즉시 |
| ALB ×2 (앱·Grafana) | 시간당 과금 | terraform destroy |
| EBS 볼륨 (Loki PVC) | 소액 | **클러스터를 지워도 남을 수 있다** — 콘솔에서 확인 |

:::caution[삭제 순서]
k8s 리소스(TargetGroupBinding) → helm → `eksctl delete cluster` → `terraform destroy`.
:::
