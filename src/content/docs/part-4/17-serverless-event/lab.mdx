원리와 채점 관점은 [17 이론 — 서버리스 워크플로·이벤트 자동복구 패턴](/part-4/17-serverless-event/theory/)에 있다.

**방식**: 기준본을 정답지 tf 로 세워 동작을 눈으로 확인한 뒤, **다른 세트의 요구로 직접 이행한다.** 배포한 다음에는 값을 잘못 읽었을 때의 복구와 고장 진단까지 간다.

이 모듈이 재는 것은 tf 를 타이핑하는 속도가 아니라 **파이프라인이 실제로 도는지 검증하고 실패 지점을 짚는 능력**, 그리고 **요구가 바뀌었을 때 기전을 갈아 끼우는 판단**이다.

## 0. 변동 짝과 리전

이 모듈은 유형 둘을 담는다. 유형마다 파트가 하나씩이고, **이행 훈련은 유형 2 에 붙는다.**

| 파트 | 유형 | 기준본 | 리전 | 이행 타깃 | 리전 |
|---|---|---|---|---|---|
| A | 서버리스 워크플로 | set-02 모듈1 | `ap-southeast-1` | 짝 없음 — 기준본만 | — |
| B | 이벤트 자동복구 | set-02 모듈3 — **RC 판에서 삭제됨**(아래 배너) | `eu-west-1` | — | — |
| C | 이벤트 자동복구 **이행** | 위 B 의 결과 | | **set-08 모듈3** | `ap-southeast-1` |

:::danger[리전을 먼저 맞춘다]
2과제는 **모듈마다 리전이 다르다.** 이 문서 안에서만 세 리전이 나온다.

리전을 틀리면 리소스는 멀쩡히 만들어지고 `apply` 도 성공한다. **채점 스크립트가 지정된 리전만 조회하므로 그 모듈이 통째로 0점이 된다.** 도구도 알려 주지 않는다.

명령마다 `--region` 을 붙이거나 `AWS_DEFAULT_REGION` 을 파트 시작에서 다시 세운다. 파트를 넘어갈 때 이것부터 한다.
:::

PART-1~3 에는 없던 축이다. 거기서는 리전이 서울로 고정이었다.

### A-5. :badge[함정]{variant=danger} (여기서 대부분 틀린다)

- test.csv 2회 업로드 → error JSON 8개 → 오답. 재실행은 반드시 A-3의 1)~2)부터.
- processed/·error/에 폴더 마커를 만들어두면 `s3 ls`에 0바이트 잉여 라인 → 오답. 마커는 `input/`만.
- 평균을 float로 계산 → boto3 가 `Float types are not supported` 로 저장 거부. `decimal.Decimal` 로 계산·저장.
- 처리 Lambda 이름은 mark에만 있다(`wsc2026-student-score-function`) — task.md만 보고 이름을 지어내면 0점.
- PowerShell에서 JSON 인자는 `\"` 이스케이프 필수. bash 는 작은따옴표로 감싸면 그대로 통한다.

### 6-3. 탐지 수단을 기준본 그대로 뒀다

**상황.** 이름과 리전은 다 바꿨는데 위반을 잡는 방식을 상태 평가 그대로 뒀다. 규칙 이름만 새 이름으로 갈아 끼웠다.

**판정.** 채점 `3-4` 가 호출 기록 장치의 활성 상태와 이벤트 패턴을 본다. 상태 평가 쪽에는 그런 것이 없다.

**여기서 고칠 것은 값이 아니라 구성이다.** 규칙 이름을 바꾸는 것으로는 안 된다 — 감시하는 대상 자체가 상태에서 호출로 바뀌어야 한다.

**복구.** 상태 평가 쪽을 지우고 호출 기록 쪽을 새로 놓는다. 리소스 종류가 달라 옮겨 쓸 수 있는 것이 거의 없다.

**교훈.** **"같은 요구, 다른 기전"이 이 모듈의 핵심이다.** [17 이론 유형 2](/part-4/17-serverless-event/theory/)의 확인 블록이 두 수단이 각각 무엇을 약속하는지 보여 준다. 요구를 읽을 때 "무엇을 감시하라고 했나"를 먼저 가른다 — 상태인지 행위인지.

## 7. 장애 진단

정상으로 선 상태에서 일부러 고장을 내고 증상만 보고 좁혀 간다. **주입 명령과 복구 명령이 짝으로 있다.**

### 7-1. 위반을 넣었는데 복구가 안 돈다

**주입.** 규칙과 함수 사이의 호출 권한을 뗀다. 문장 ID 는 첫 명령이 알려준다.

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  aws lambda get-policy --region ap-southeast-1 --function-name skills-ceh-remediate-fn --query Policy --output text
  aws lambda remove-permission --region ap-southeast-1 --function-name skills-ceh-remediate-fn --statement-id <statement-id>
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  aws lambda get-policy --region ap-southeast-1 --function-name skills-ceh-remediate-fn --query Policy --output text
  aws lambda remove-permission --region ap-southeast-1 --function-name skills-ceh-remediate-fn --statement-id <statement-id>
  ```
  </TabItem>
</Tabs>

**증상.** 보호 대상에 인바운드를 넣어도 사라지지 않는다. 규칙은 활성이고 함수도 정상이다.

**좁히는 순서.** 이벤트가 흐르는 순서대로 앞에서 뒤로 간다.

<Steps>

1. **함수를 직접 불러 본다** — 채점이 하는 것과 같다. 직접 부르면 복구가 되는데 위반을 넣으면 안 되면, **함수는 멀쩡하고 배선이 끊긴 것이다.** 이 갈림이 첫째다

2. **규칙이 이벤트를 받았나** — 규칙의 호출 지표를 본다. 0 이면 이벤트 자체가 안 온 것이고, 그러면 호출 기록 장치 쪽 문제다

3. **규칙이 타깃을 부를 수 있나** — `aws lambda get-policy` 로 함수가 그 규칙의 호출을 허용하는지 본다. 비었거나 해당 문장이 없으면 여기가 원인이다

4. **함수가 실행은 됐는데 실패했나** — 함수 로그를 본다. 로그가 있으면 실행은 된 것이라 권한이 아니라 코드·대상 문제다

</Steps>

**1번을 먼저 하는 이유가 있다.** 함수와 배선 중 어느 쪽인지를 한 번에 가르기 때문이다. 이것을 안 하면 코드와 규칙을 번갈아 보며 시간을 쓴다.

**복구.** 코드가 실제 상태와의 차이를 메운다.

```bash
terraform plan
terraform apply
```

기대: `plan` 이 `aws_lambda_permission` 하나를 `+ create` 로 잡는다. drift 복구다.

### 7-2. 복구가 도는데 계속 다시 돈다

**주입.** 복구 함수가 자기 행위를 다시 잡지 않도록 걸러 내는 조건을 지운다 — 규칙의 이벤트 패턴에서 **호출 주체를 배제하는 부분**을 뺀다.

이 고장은 코드 수정이 필요하므로, 규칙의 패턴을 콘솔이나 CLI 로 넓혀 재현한다. 넓히기 전에 원본 패턴을 받아 둔다.

<Tabs syncKey="shell">
  <TabItem label="PowerShell">
  ```powershell
  aws events describe-rule --region ap-southeast-1 --name skills-ceh-sg-change-rule --query EventPattern --output text | Set-Content $HOME\ceh-rule-backup.json
  ```
  </TabItem>
  <TabItem label="Bash (Linux/CloudShell)">
  ```bash
  aws events describe-rule --region ap-southeast-1 --name skills-ceh-sg-change-rule --query EventPattern --output text > ~/ceh-rule-backup.json
  ```
  </TabItem>
</Tabs>

**증상.** 복구는 도는데 함수 호출 수가 계속 늘고 로그가 끝없이 쌓인다. 결과는 맞는데 **비용과 스로틀이 문제가 된다.**

**좁히는 순서.**

<Steps>

1. **호출 수를 본다** — 위반을 한 번 넣었는데 호출이 여러 번이면 되먹임이다. **결과가 맞다고 정상인 것은 아니다**

2. **무엇이 함수를 부르나** — 함수 로그의 이벤트 본문에서 호출 주체를 본다. 복구 함수 자신의 역할이 찍혀 있으면 자기가 자기를 부르고 있는 것이다

3. **규칙 패턴이 그것을 거르나** — 패턴에 호출 주체를 배제하는 조건이 있는지 본다. 없으면 여기가 원인이다

</Steps>

**복구.** 받아 둔 패턴으로 되돌리고, 코드 쪽도 함께 확인한다.

```bash
terraform plan
terraform apply
```

**교훈.** **자동복구는 자기 행위도 이벤트로 남긴다.** 되돌리는 API 호출이 다시 규칙에 걸리면 무한히 돈다. 이벤트 기반 복구를 만들 때는 항상 **자기 배제**를 먼저 넣는다. 이 고장은 결과가 맞아서 눈에 안 띄고, 청구서로 드러난다.
