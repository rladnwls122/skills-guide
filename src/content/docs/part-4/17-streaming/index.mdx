> 문서 유형: 개요

2과제 **유형 5 — 스트리밍**을 다룬다. 갈래가 둘이다.

| 갈래 | 구성 | 기준본 |
|---|---|---|
| Kinesis + Flink Studio | 스트림 → Zeppelin 노트북에서 SQL 질의 → Glue 카탈로그 | set-02 task-2 module-2 |
| MSK + Lambda 컨슈머 | Kafka 토픽 → Lambda 이벤트 소스 매핑 → DynamoDB·SNS | set-02 task-2 module-3 |

:::caution[이 모듈만 실제 배포가 선택이다]
MSK 는 **apply 만 35분, destroy 23분**이 걸린다(실측 2026-08-16, 클러스터 하나가 31분 40초). 학습 시간의 절반을 대기로 쓰게 되고 그동안 계속 과금된다.

그래서 필수 경로는 **정답지 대조**다. 채점 항목이 대부분 리소스의 구성값이라, 무엇이 어떤 값으로 있어야 하는지를 코드에서 확인하면 재현할 수 있다. 배포는 시간과 예산이 남을 때의 선택이다.

실전에서는 사정이 다르다 — MSK 가 나오면 **가장 먼저 apply 를 걸어 두고** 그 35분 동안 다른 모듈을 끝낸다. 순서를 반대로 하면 그 자체로 시간이 모자란다.
:::

## 학습 목표

- [ ] Kinesis `ACTIVE`/`ON_DEMAND` 와 Flink `READY`/`ZEPPELIN-FLINK-3_0` 등 채점이 읽는 값을 정확히 말한다
- [ ] MSK 의 `ACTIVE`·버전·인스턴스 타입·IAM 인증 활성 여부가 채점 대상임을 안다
- [ ] DynamoDB 항목이 특정 속성 타입으로 조회되는 이유를 설명한다
- [ ] Flink Studio 를 terraform 으로 직접 만들 수 없어 CloudFormation 으로 감싸는 이유를 안다
- [ ] MSK 의 생성·삭제 소요를 당일 일정에 반영한다

## 소요 시간

- 대조만 하면 약 1~1.5시간. 실제로 배포하면 module-2 기준 +30분, MSK 는 apply·destroy 만 1시간이 더 든다. Week 3.

## 과금 리소스와 destroy 방침

| 리소스 | 과금 | 방침 |
|---|---|---|
| MSK 브로커 ×2 | **apply 35분·destroy 23분 + 시간당 과금 (큼)** | 확인 즉시 `terraform destroy` |
| Kinesis + Flink Studio + EC2 + ALB + NAT | 시간당 과금 (생성 지연은 없다) | 확인 즉시 `terraform destroy` |

:::danger[MSK destroy 가 중간에 멈출 수 있다]
프라이빗 서브넷과 VPC 삭제가 네트워크 인터페이스 회수를 기다리다 교착한다. terraform 로그만 봐서는 원인이 안 보인다 — **terraform state 밖의 일**이다. 30분 넘게 진행이 없으면 콘솔에서 남은 네트워크 인터페이스를 확인한다.
:::
