> 문서 유형: 개요

**배점이 가장 큰 축이다.** [2025 1과제 배점](/reference/past-exams/#2-1-2025년-1과제-30점)에서 Continuous Integration 2.5 점과 Continuous Delivery 4.5 점을 더하면 7점이다. 30점 만점 중 가장 큰 묶음이다. Network Configuration 이 1.5 점인 것과 비교된다.

두 해 모두 나왔고 **도구만 바뀌었다.**

| 해 | 도구 |
|---|---|
| 2024 2과제 | CodeCommit → CodeBuild → ECR → CodeDeploy(In-place) → CodePipeline |
| 2025 1과제 | GitHub(OAuth) → CodeBuild → ECR → CodePipeline |
| 2025 2과제 | GitHub Actions → ECR → ArgoCD |

이 모듈은 CI 까지 다룬다. **CD(ArgoCD·Rollouts)는 [29 번 모듈](/part-4/29-gitops-rollouts/)** 이다.

:::caution[CodeCommit 은 신규 생성이 막혀 있다]
AWS 가 2024년 7월 이후 신규 고객에게 CodeCommit 저장소 생성을 열지 않는다. 2024 과제가 CodeCommit 을 요구했지만 지금 계정에서는 만들지 못할 수 있다.

**그래서 이 모듈은 GitHub 기준으로 쓴다.** 파이프라인의 소스 단계만 바뀌고 나머지는 같다. 당일 CodeCommit 이 열려 있다면 소스 공급자만 바꾼다.
:::

:::tip[이 모듈은 문서가 넷이다]
개념은 [이론](/part-4/28-cicd-pipeline/theory/), 구축은 [실습](/part-4/28-cicd-pipeline/lab/), 그리고 **[드릴](/part-4/28-cicd-pipeline/drill/)** 이 이행·복기·진단을 맡는다(약 30분). 실습을 마친 뒤에 연다.
:::

## 학습 목표

- [ ] CI 와 CD 가 각각 무엇을 자동화하는지 구분해 설명할 수 있다
- [ ] `buildspec.yaml` 의 단계별 역할과 `artifacts` 가 무엇을 넘기는지 안다
- [ ] CodeBuild 가 ECR 에 이미지를 올리려면 필요한 권한 두 가지를 짚을 수 있다
- [ ] CodeBuild 에서 Docker 를 쓰려면 필요한 설정을 안다
- [ ] CodePipeline 의 단계·작업·아티팩트 구조를 설명할 수 있다
- [ ] GitHub 연결 방식 셋(OAuth·개인 토큰·CodeConnections)의 차이를 안다
- [ ] GitHub Actions 워크플로를 쓰고 특정 파일 변경에만 돌게 만들 수 있다
- [ ] Actions 에서 AWS 자격증명을 안전하게 얻는 두 방법을 비교할 수 있다
- [ ] 빌드 실패를 로그에서 좁힐 수 있다

## 소요 시간

약 6~7시간 (이론 2h + 실습 4~5h)

## 과금 리소스와 destroy 방침

| 리소스 | 과금 | 방침 |
|---|---|---|
| CodeBuild | 빌드 분당 과금. `BUILD_GENERAL1_SMALL` 은 매우 저렴 | 프로젝트는 두어도 무방, 정리 시 destroy |
| CodePipeline | 활성 파이프라인당 월 과금(첫 파이프라인 무료) | 실습 후 destroy |
| ECR | 저장 용량당 과금 | 이미지까지 삭제 |
| S3 아티팩트 버킷 | 저장량당 소액 | 비우고 삭제 |
| GitHub Actions | 공개 저장소는 무료 | — |

:::caution[GitHub Actions 무료 할당량]
2025 2과제 유의사항이 "Github Action 의 무료 할당량을 소진하여 채점 시 불이익을 받지 않도록" 경고한다. **저장소를 public 으로 만들면 Actions 가 무제한 무료**다. 문제지도 `Repository Type: Public` 을 지정했다.
:::
