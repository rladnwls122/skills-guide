> 문서 유형: 개요

[2025 1과제](/reference/past-exams/#2-1-2025년-1과제-30점)에서 **단일 항목 최대 배점(4.5점)** 이다. 2과제 CI/CD 모듈에도 ArgoCD 가 나온다. 한 해에 두 과제에서 요구된 축이다.

요구를 그대로 옮기면 이렇다.

> gitops 브랜치에 새로운 커밋이 푸쉬되는 것을 감지하여 Blue/Green 방식으로 롤아웃되어야 합니다. 새로운 커밋이 push 될 경우 새로운 애플리케이션은 Green Stage 에서 /health 경로로 Health Check 를 진행해야합니다. Health Check 후 애플리케이션에 문제가 없을 시 Blue Stage 로 배포되어야 합니다. CI/CD 는 3분안에 작업이 완료되어야 합니다.

여기에 시크릿 요구가 붙는다.

> 환경변수 값은 Pod 에 직접적으로 명시해선 안되며 Secrets Manager 에 저장된 값을 External Secrets 을 사용해 읽어와야 합니다.

:::tip[이 모듈은 문서가 넷이다]
개념은 [이론](/part-4/29-gitops-rollouts/theory/), 구축은 [실습](/part-4/29-gitops-rollouts/lab/), 그리고 **[드릴](/part-4/29-gitops-rollouts/drill/)** 이 이행·복기·진단을 맡는다(약 25분). 실습을 마친 뒤에 연다.
:::

## 학습 목표

- [ ] GitOps 가 기존 배포 방식과 무엇이 다른지 설명할 수 있다
- [ ] ArgoCD 의 Application·동기화·자동 복구가 각각 무엇인지 안다
- [ ] Deployment 로는 Blue/Green 을 하기 어려운 이유를 설명할 수 있다
- [ ] Argo Rollouts 의 activeService 와 previewService 가 무엇을 가리키는지 안다
- [ ] `prePromotionAnalysis` 와 `autoPromotionEnabled` 의 관계를 설명할 수 있다
- [ ] External Secrets 의 SecretStore·ExternalSecret 두 오브젝트 역할을 구분한다
- [ ] IRSA 가 파드에 권한을 주는 경로를 순서대로 말할 수 있다
- [ ] IRSA 정책의 Resource 를 좁히는 이유와 좁히는 법을 안다
- [ ] 3분 제약을 못 지킬 때 어디를 줄일지 판단할 수 있다

## 소요 시간

약 7~8시간 (이론 3h + 실습 4~5h)

## 과금 리소스와 destroy 방침

| 리소스 | 과금 | 방침 |
|---|---|---|
| **EKS 클러스터** | **시간당 고정 과금**. 이 모듈에서 가장 비싸다 | 실습 종료 즉시 destroy |
| 노드그룹 EC2 | 시간당 과금 | 클러스터와 함께 |
| NLB·ALB | 시간당 + LCU 과금 | 서비스·인그레스 삭제로 함께 |
| Secrets Manager | 시크릿당 월 과금(소액) | 복구 대기 없이 즉시 삭제 |
| ECR | 저장량 | 이미지까지 삭제 |

:::danger[EKS 는 클러스터가 있는 것만으로 과금된다]
파드가 없어도 컨트롤 플레인 요금이 시간당 붙는다. 노드까지 있으면 그만큼 더다. **실습을 마치면 클러스터를 지운다.**
:::

:::caution[Secrets Manager 는 지워도 바로 안 지워진다]
기본 복구 대기가 7일이라 같은 이름으로 다시 만들 수 없다. 실습에서는 즉시 삭제를 쓴다.

```bash
aws secretsmanager delete-secret --secret-id <이름> --force-delete-without-recovery
```
:::

## 공식 문서

전부 읽지 않는다. 각 문서에서 **읽을 자리**만 적었다.

**모듈에 들어가기 전에 읽는다**

- [Argo CD 개요](https://argo-cd.readthedocs.io/en/stable/) · Application 과 동기화를 설명하는 앞부분. 클러스터가 저장소를 따라간다는 방향이 GitOps 의 전부다
- [Argo Rollouts BlueGreen](https://argo-rollouts.readthedocs.io/en/stable/features/bluegreen/) · `activeService` 와 `previewService` 항목. 서비스 두 개로 버전을 가르는 구조다

**실습 중 대조한다**

- [Argo Rollouts 분석](https://argo-rollouts.readthedocs.io/en/stable/features/analysis/) · `prePromotionAnalysis` 와 AnalysisTemplate 항목. 승격 전 자동 검사를 붙일 때 연다
- [External Secrets Operator](https://external-secrets.io/latest/) · SecretStore 와 ExternalSecret 두 리소스. 비밀을 저장소에 두지 않고 주입할 때 연다
- [EKS IRSA](https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html) · 서비스 계정 애너테이션과 신뢰 정책 예시
