> 문서 유형: 개요

[2025 2과제](/reference/past-exams/#3-2-2025-2과제--small-challenge-4시간) Serverless Inventory 모듈의 제약이 이 모듈의 전부다.

> Step Functions, API Gateway, DynamoDB 등을 사용해 별도의 컴퓨팅 서비스를 사용하지 않고 다음의 요구사항을 만족할 수 있는 시스템을 구축해야 합니다. **Lambda 를 포함한 EC2, ECS 등의 컴퓨팅 서비스의 사용이 불가합니다.**

Lambda 를 쓸 수 없다는 제약이 문제의 성격을 뒤집는다. 평소라면 Lambda 한 장으로 끝날 일을 서비스끼리 직접 잇는 방법으로 풀어야 한다.

:::note[왜 이런 제약을 내나]
서비스 통합을 아느냐를 보는 문제다. Lambda 는 무엇이든 할 수 있으니 Lambda 로 풀면 각 서비스가 제공하는 통합 기능을 몰라도 된다. 그것을 막으면 Step Functions 의 SDK 통합과 API Gateway 의 서비스 프록시를 알아야만 풀린다.
:::

:::tip[이 모듈은 문서가 넷이다]
개념은 [이론](/part-4/30-stepfunctions-apigw/theory/), 구축은 [실습](/part-4/30-stepfunctions-apigw/lab/), 그리고 **[드릴](/part-4/30-stepfunctions-apigw/drill/)** 이 이행·복기·진단을 맡는다(약 25분). 실습을 마친 뒤에 연다.
:::

## 학습 목표

- [ ] Step Functions 의 상태 타입 다섯 가지를 구분하고 쓸 자리를 안다
- [ ] ASL(Amazon States Language) 의 `Parameters` · `ResultPath` · `OutputPath` 가 각각 무엇을 하는지 설명할 수 있다
- [ ] Lambda 없이 DynamoDB 를 읽고 쓰는 Task 를 쓸 수 있다
- [ ] `Choice` 상태로 조건 분기를 만들 수 있다
- [ ] API Gateway 통합 유형 셋의 차이를 안다
- [ ] AWS 서비스 프록시 통합의 요청·응답 매핑 템플릿을 쓸 수 있다
- [ ] VTL 로 조건에 따라 403 을 내는 방법을 안다
- [ ] DynamoDB 응답의 타입 표기를 벗겨 값만 내보낼 수 있다
- [ ] 실행이 실패했을 때 어느 상태에서 왜 실패했는지 찾을 수 있다

## 소요 시간

약 5~6시간 (이론 2.5h + 실습 3h)

## 과금 리소스와 destroy 방침

| 리소스 | 과금 | 방침 |
|---|---|---|
| DynamoDB (온디맨드) | 요청당. 실습 규모는 무시 가능 | destroy |
| Step Functions (Standard) | 상태 전이당. 매우 저렴 | destroy |
| API Gateway REST | 요청당 + 캐시 사용 시 시간당 | **캐시를 켜지 않는다** |
| CloudWatch Logs | 저장량 | 보존 기간 짧게 |

이 모듈은 과금이 가장 작다. **컴퓨팅이 없어서다.** 그것이 이 아키텍처의 장점이기도 하다.

:::caution[API Gateway 캐시는 시간당 과금이다]
스테이지 설정에서 캐싱을 켜면 켜 둔 시간만큼 과금된다. 실습에서 켤 이유가 없다.
:::

## 공식 문서

전부 읽지 않는다. 각 문서에서 **읽을 자리**만 적었다.

**모듈에 들어가기 전에 읽는다**

- [API Gateway REST API 통합 유형](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-api-integration-types.html) · `AWS`·`AWS_PROXY`·`HTTP` 세 유형의 차이. 어느 유형을 고르느냐가 매핑 템플릿의 필요 여부를 정한다
- [Step Functions 의 AWS SDK 통합](https://docs.aws.amazon.com/step-functions/latest/dg/supported-services-awssdk.html) · 통합 호출 형식 부분. Lambda 없이 서비스를 직접 부를 수 있다는 사실이 설계를 바꾼다

**실습 중 대조한다**

- [Amazon States Language](https://docs.aws.amazon.com/step-functions/latest/dg/concepts-amazon-states-language.html) · 상태 타입 목록과 입출력 필드
- [API Gateway 매핑 템플릿](https://docs.aws.amazon.com/apigateway/latest/developerguide/models-mappings.html) · VTL 문법과 `$input` 변수. 요청 본문을 바꿔 넘길 때 연다
- [aws_api_gateway_integration](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/api_gateway_integration) · `type` 과 `uri`, `request_templates` 인자
- [aws_sfn_state_machine](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/sfn_state_machine) · `definition` 과 `role_arn` 인자
