:::danger[Lambda 를 만들면 그 모듈이 0점이다]
문제지가 "Lambda 를 포함한 EC2, ECS 등의 컴퓨팅 서비스의 사용이 불가"라고 못 박았다. 막히더라도 Lambda 로 우회하지 않는다. 이 실습의 목적이 그 우회 없이 푸는 것이다.
:::

## 실습 목표

- [ ] DynamoDB `inventory` 테이블을 만들고 초기 항목을 넣는다
- [ ] Step Functions 상태 머신으로 재고와 잔고를 갱신한다
- [ ] Lambda 없이 DynamoDB 를 부르는 Task 를 쓴다
- [ ] REST API 를 AWS 서비스 프록시 통합으로 만든다
- [ ] VTL 로 요청과 응답을 변환해 값만 내보낸다
- [ ] `mysecret` 으로 시작하는 요청에 403 을 낸다
- [ ] 실기출 채점 명령으로 확인한다
- [ ] 실패한 실행을 이력에서 좁힌다
- [ ] 정리한다

## 2. DynamoDB

<Steps>

1. **테이블을 만든다.**

   ```hcl title="main.tf"
   terraform {
     required_providers { aws = { source = "hashicorp/aws", version = "~> 5.0" } }
   }
   provider "aws" { region = var.region }

   variable "region" { default = "us-west-1" }

   data "aws_caller_identity" "this" {}

   resource "aws_dynamodb_table" "inventory" {
     name         = "inventory"
     billing_mode = "PAY_PER_REQUEST"

       type = "S"
     }

   ```

   파티션 키만 정의한다. `value` 는 키가 아니므로 선언하지 않는다([DynamoDB 기초](/start/dynamodb-basics/)).

   ```bash
     --item '{"name": {"S": "balance"}, "value": {"N": "1000"}}'
   aws dynamodb put-item --table-name inventory \
     --item '{"name": {"S": "stock"}, "value": {"N": "100"}}'
   ```

   확인한다.


## 3. 상태 머신

동작을 먼저 정한다. 문제지가 상태 머신의 세부 로직을 지정하지 않았지만 채점 스크립트가 기대값을 드러낸다.

```bash
# 채점 5-3
put balance=1000, stock=50
start-execution {"sales": 20}
get balance -> ?
get stock   -> ?
```

`sales` 만큼 재고에서 빼고, 판매 대금을 잔고에 더하는 것이 자연스럽다. **단가를 정해야 한다.** 실습에서는 단가 10 으로 둔다. 실전이라면 채점 스크립트의 기대값에서 역산한다.

<Steps>

1. **상태 머신 역할을 만든다.**

   ```hcl title="sfn.tf"
   resource "aws_iam_role" "sfn" {
     name = "inventory-sfn-role"
     assume_role_policy = jsonencode({
       Version = "2012-10-17"
       Statement = [{
         Effect    = "Allow"
         Principal = { Service = "states.amazonaws.com" }
         Action    = "sts:AssumeRole"
       }]
     })
   }

   resource "aws_iam_role_policy" "sfn" {
     role = aws_iam_role.sfn.id
     policy = jsonencode({
       Version = "2012-10-17"
       Statement = [{
         Effect   = "Allow"
         Action   = ["dynamodb:GetItem", "dynamodb:UpdateItem", "dynamodb:PutItem"]
         Resource = aws_dynamodb_table.inventory.arn
       }]
     })
   }
   ```

   Resource 를 테이블 ARN 으로 좁힌다.

2. **ASL 을 쓴다.**

   ```json title="inventory.asl.json"
   {
     "Comment": "재고 차감과 잔고 증가",
     "StartAt": "ValidateSales",
     "States": {
       "ValidateSales": {
         "Type": "Choice",
         "Choices": [
           {
             "Variable": "$.sales",
             "NumericGreaterThanEquals": 1,
             "Next": "CheckUpperBound"
           }
         ],
         "Default": "InvalidInput"
       },

       "CheckUpperBound": {
         "Type": "Choice",
         "Choices": [
           {
             "Variable": "$.sales",
             "NumericLessThanEquals": 30,
             "Next": "DecreaseStock"
           }
         ],
         "Default": "InvalidInput"
       },

       "DecreaseStock": {
         "Type": "Task",
         "Resource": "arn:aws:states:::aws-sdk:dynamodb:updateItem",
         "Parameters": {
           "TableName": "inventory",
           "Key": { "name": { "S": "stock" } },
           "UpdateExpression": "SET #v = #v - :sales",
           "ExpressionAttributeNames": { "#v": "value" },
           "ExpressionAttributeValues": {
             ":sales": { "N.$": "States.Format('{}', $.sales)" }
           }
         },
         "ResultPath": null,
         "Next": "IncreaseBalance"
       },

       "IncreaseBalance": {
         "Type": "Task",
         "Resource": "arn:aws:states:::aws-sdk:dynamodb:updateItem",
         "Parameters": {
           "TableName": "inventory",
           "Key": { "name": { "S": "balance" } },
           "UpdateExpression": "SET #v = #v + :amount",
           "ExpressionAttributeNames": { "#v": "value" },
           "ExpressionAttributeValues": {
             ":amount.$": "States.Format('{}', States.MathAdd($.sales, 0))"
           }
         },
         "ResultPath": null,
         "Next": "Done"
       },

       "Done": { "Type": "Succeed" },
       "InvalidInput": {
         "Type": "Fail",
         "Error": "InvalidSales",
         "Cause": "sales must be between 1 and 30"
       }
     }
   }
   ```

   :::caution[`IncreaseBalance` 의 값 형식에 주의한다]
   `":amount.$"` 처럼 키 이름 끝에 `.$` 를 붙였다. 값이 타입 표기 없는 문자열이 되므로 실제로는 `{"N": ...}` 을 감싸야 한다. 아래처럼 쓰는 편이 확실하다.

   ```json
   ":amount": { "N.$": "States.Format('{}', $.sales)" }
   ```

   단가를 곱하려면 `States.MathAdd` 만으로는 부족하다. 곱셈 내장 함수가 없어 `Pass` 상태에서 미리 계산하거나 `sales` 자체를 대금으로 취급한다. 실습에서는 단가 1로 두어 `sales` 를 그대로 더한다.
   :::

   위 주의에 맞춰 `IncreaseBalance` 의 `ExpressionAttributeValues` 를 이렇게 고친다.

   ```json
   "ExpressionAttributeValues": {
     ":amount": { "N.$": "States.Format('{}', $.sales)" }
   }
   ```

3. **상태 머신을 만든다.**

   ```hcl title="sfn.tf"
   resource "aws_sfn_state_machine" "inventory" {
     name       = "inventory-state-machine"
     role_arn   = aws_iam_role.sfn.arn
     definition = file("${path.module}/inventory.asl.json")
   }
   ```

   ```bash
   terraform apply
   ```

4. **실행해 본다.**

   ```bash
   export SM_ARN="arn:aws:states:${AWS_DEFAULT_REGION}:${ACCOUNT_ID}:stateMachine:inventory-state-machine"

   aws dynamodb put-item --table-name inventory --item '{"name":{"S":"balance"},"value":{"N":"1000"}}'
   aws dynamodb put-item --table-name inventory --item '{"name":{"S":"stock"},"value":{"N":"50"}}'

   aws stepfunctions start-execution --state-machine-arn "$SM_ARN" --input '{"sales": 20}'
   sleep 5

   aws dynamodb get-item --table-name inventory --key '{"name":{"S":"balance"}}' --query Item.value.N --output text
   aws dynamodb get-item --table-name inventory --key '{"name":{"S":"stock"}}'   --query Item.value.N --output text
   ```

   `1020` 과 `30` 이 나오면 동작한 것이다.

   실패하면 이력을 본다.

   ```bash
   EXEC=$(aws stepfunctions list-executions --state-machine-arn "$SM_ARN" \
     --max-items 1 --query 'executions[0].executionArn' --output text)
   aws stepfunctions get-execution-history --execution-arn "$EXEC" \
     --query 'events[?type==`TaskFailed`].taskFailedEventDetails'
   ```

</Steps>

## 4. REST API

<Steps>

1. **API Gateway 역할을 만든다.**

   ```hcl title="apigw.tf"
   resource "aws_iam_role" "apigw" {
     name = "inventory-apigw-role"
     assume_role_policy = jsonencode({
       Version = "2012-10-17"
       Statement = [{
         Effect    = "Allow"
         Principal = { Service = "apigateway.amazonaws.com" }
         Action    = "sts:AssumeRole"
       }]
     })
   }

   resource "aws_iam_role_policy" "apigw" {
     role = aws_iam_role.apigw.id
     policy = jsonencode({
       Version = "2012-10-17"
       Statement = [{
         Effect   = "Allow"
         Action   = "dynamodb:GetItem"
         Resource = aws_dynamodb_table.inventory.arn
       }]
     })
   }
   ```

2. **API 와 리소스와 메서드를 만든다.**

   ```hcl title="apigw.tf"
   resource "aws_api_gateway_rest_api" "this" {
     name = "inventory-rest-api"
   }

   resource "aws_api_gateway_resource" "inventory" {
     rest_api_id = aws_api_gateway_rest_api.this.id
     parent_id   = aws_api_gateway_rest_api.this.root_resource_id
     path_part   = "inventory"
   }

   resource "aws_api_gateway_method" "get" {
     rest_api_id   = aws_api_gateway_rest_api.this.id
     resource_id   = aws_api_gateway_resource.inventory.id
     http_method   = "GET"
     authorization = "NONE"

     request_parameters = {
       "method.request.querystring.item" = true
     }
   }
   ```

3. **통합을 만든다. AWS 서비스 프록시다.**

   ```hcl title="apigw.tf"
   resource "aws_api_gateway_integration" "get" {
     rest_api_id = aws_api_gateway_rest_api.this.id
     resource_id = aws_api_gateway_resource.inventory.id
     http_method = aws_api_gateway_method.get.http_method

     type                    = "AWS"          # 서비스 프록시
     integration_http_method = "POST"         # DynamoDB API 는 언제나 POST
     uri                     = "arn:aws:apigateway:${var.region}:dynamodb:action/GetItem"
     credentials             = aws_iam_role.apigw.arn
     passthrough_behavior    = "NEVER"

     request_templates = {
       "application/json" = <<-EOT
         #set($item = $input.params('item'))
         #if($item == "")
           #set($item = "__none__")
         #end
         {
           "TableName": "inventory",
           "Key": { "name": { "S": "$item" } }
         }
       EOT
     }
   }
   ```

   `item` 이 비면 `__none__` 을 넣는다. 빈 문자열을 키로 보내면 DynamoDB 가 오류를 내므로 미리 막는다.

4. **메서드 응답 둘을 등록한다. 403 을 여기서 열어 준다.**

   ```hcl title="apigw.tf"
   resource "aws_api_gateway_method_response" "ok" {
     rest_api_id = aws_api_gateway_rest_api.this.id
     resource_id = aws_api_gateway_resource.inventory.id
     http_method = aws_api_gateway_method.get.http_method
     status_code = "200"
   }

   resource "aws_api_gateway_method_response" "forbidden" {
     rest_api_id = aws_api_gateway_rest_api.this.id
     resource_id = aws_api_gateway_resource.inventory.id
     http_method = aws_api_gateway_method.get.http_method
     status_code = "403"      # 등록하지 않으면 403 을 낼 수 없다
   }
   ```

5. **통합 응답에서 값만 뽑고 403 을 판정한다.**

   ```hcl title="apigw.tf"
   resource "aws_api_gateway_integration_response" "ok" {
     rest_api_id = aws_api_gateway_rest_api.this.id
     resource_id = aws_api_gateway_resource.inventory.id
     http_method = aws_api_gateway_method.get.http_method
     status_code = aws_api_gateway_method_response.ok.status_code

     response_templates = {
       "application/json" = <<-EOT
         #set($item = $input.params('item'))
         #if($item.startsWith("mysecret"))
         #set($context.responseOverride.status = 403)
         403 Forbidden
         #else
         #set($v = $input.path('$.Item.value.N'))
         $v
         #end
       EOT
     }

     depends_on = [aws_api_gateway_integration.get]
   }
   ```

   :::note[왜 응답 단계에서 판정하나]
   요청 단계에서 상태코드를 바꾸면 통합이 먼저 실행되어 순서가 꼬인다. 응답 단계의 `$context.responseOverride.status` 는 확실히 동작한다. `mysecret123` 이라는 키로 DynamoDB 를 조회하면 항목이 없어 빈 응답이 오고, 그것을 우리가 403 으로 덮어쓴다.
   :::

6. **배포한다.**

   ```hcl title="apigw.tf"
   resource "aws_api_gateway_deployment" "this" {
     rest_api_id = aws_api_gateway_rest_api.this.id

     triggers = {
       redeploy = sha1(jsonencode([
         aws_api_gateway_resource.inventory,
         aws_api_gateway_method.get,
         aws_api_gateway_integration.get,
         aws_api_gateway_integration_response.ok,
       ]))
     }

     lifecycle { create_before_destroy = true }
   }

   resource "aws_api_gateway_stage" "v1" {
     rest_api_id   = aws_api_gateway_rest_api.this.id
     deployment_id = aws_api_gateway_deployment.this.id
     stage_name    = "v1"
   }

   output "api_endpoint" {
     value = "${aws_api_gateway_stage.v1.invoke_url}/inventory"
   }
   ```

   `triggers` 가 없으면 매핑 템플릿을 고쳐도 반영되지 않는다.

   ```bash
   terraform apply
   export API=$(terraform output -raw api_endpoint)
   echo $API
   ```

</Steps>

## 6. 막혔을 때

### 6-1. 상태 머신 실행 실패

```bash
EXEC=$(aws stepfunctions list-executions --state-machine-arn "$SM_ARN" \
  --max-items 1 --query 'executions[0].executionArn' --output text)
aws stepfunctions describe-execution --execution-arn "$EXEC" \
  --query '{status:status,error:error,cause:cause}'
aws stepfunctions get-execution-history --execution-arn "$EXEC" \
  --query 'events[?type==`TaskFailed`].taskFailedEventDetails'
```

| `error` | 원인 | 고침 |
|---|---|---|
| `DynamoDb.AccessDeniedException` | 역할 권한 | `UpdateItem` 이 정책에 있는지 |
| `DynamoDb.ValidationException` | `Parameters` 형식 | 숫자가 문자열인지, `#v` 자리표시자 |
| `States.Runtime` | 경로 오류 | `.$` 가 가리키는 필드가 입력에 있는지 |
| `States.NoChoiceMatched` | `Choice` 에 맞는 게 없고 `Default` 없음 | `Default` 추가 |

`value` 를 자리표시자 없이 쓰면 예약어 오류가 난다.

```
Invalid UpdateExpression: Attribute name is a reserved keyword; reserved keyword: value
```

`ExpressionAttributeNames` 로 `#v` 를 쓰는 이유다.

### 6-2. API 가 이상하다

실행 로그를 켠다.

```bash
API_ID=$(aws apigateway get-rest-apis --query "items[?name=='inventory-rest-api'].id" --output text)
aws apigateway update-stage --rest-api-id "$API_ID" --stage-name v1 \
  --patch-operations op=replace,path=/*/*/logging/loglevel,value=INFO \
                     op=replace,path=/*/*/logging/dataTrace,value=true
```

:::caution[실행 로그에는 계정 수준 CloudWatch 역할이 필요하다]
API Gateway 가 로그를 쓰려면 계정에 로깅 역할이 설정돼 있어야 한다. 없으면 `CloudWatch Logs role ARN must be set` 오류가 난다.

```bash
aws apigateway update-account --patch-operations \
  op=replace,path=/cloudwatchRoleArn,value=arn:aws:iam::${ACCOUNT_ID}:role/<로깅역할>
```
:::

로그를 본다.

```bash
aws logs tail "API-Gateway-Execution-Logs_${API_ID}/v1" --since 5m
```

변환 전후가 그대로 남아 매핑 템플릿의 결과를 볼 수 있다.

| 증상 | 원인 |
|---|---|
| 500 | 템플릿 문법 오류 또는 통합 권한 |
| `{"Item":...}` 그대로 | 응답 템플릿 미적용. 재배포 확인 |
| 빈 본문 | 항목이 없다. `scan` 으로 확인 |
| 403 이 200 | 메서드 응답에 403 미등록 |
| 바꿔도 안 변함 | `triggers` 없이 배포되지 않음 |

강제로 재배포한다.

```bash
aws apigateway create-deployment --rest-api-id "$API_ID" --stage-name v1
```
