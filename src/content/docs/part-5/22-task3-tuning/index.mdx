> 문서 유형: 개요

[21. 배포 실습](/part-5/21-task3-deploy/)이 세운 스택 위에서 이어 간다. 3과제의 점수는 배포가 아니라 **그다음 두 시간**에서 갈린다 — 트래픽이 들어온 뒤 가용성·성능·비용을 동시에 지키는 운영이다.

이 모듈이 훈련하는 것은 손이 아니라 **판단의 순서**다. 지표를 보고, 노브를 하나만 돌리고, 다시 재는 것. 두 개를 동시에 바꾸면 무엇이 들었는지 알 수 없고, 그 상태로는 다음 판단도 못 한다.

## 목표

- [ ] k6 3단 프로파일(정상·과부하·지속)로 부하를 주고 SLO 를 지키는지 판정한다
- [ ] 30초 주기 감시 루프로 파드·노드·큐·응답 시간을 함께 본다
- [ ] 노브를 하나 돌리고 재측정해 **변화를 원인과 결과로 설명한다**
- [ ] 부하 중 장애 10종 중 7개 이상을 5분 안에 복구한다
- [ ] 부하 전 구간에서 노드를 비용 밴드 안에 유지한다
- [ ] 드릴이 끝나면 부하부터 멈추고 스택을 지운다

## 소요 시간

- 8~10시간 (부하 드릴 3회 + 장애 드릴). Week 4.

## 과금 / destroy

:::caution[시간당 과금이 가장 비싼 구간이다]
EKS + NAT GW + ALB + CloudFront + RDS Multi-AZ + 노드 최대 9대가 동시에 떠 있다.

- 드릴 1회는 배포~부하~정리까지 **3시간 안에** 끝내고 당일 destroy 한다.
- 부하는 자기 CloudFront 로만 주입한다. 종료 시 **부하부터 멈추고** 스택을 지운다.
- 정리 순서: k6 중지 → `kubectl delete` → `eksctl delete cluster` → `terraform destroy` → [잔존 리소스 점검](/reference/cleanup-check/).
:::
