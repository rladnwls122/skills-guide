> 문서 유형: 개요

[21. 배포 실습](/part-5/21-task3-deploy/)이 세운 스택 위에서 이어 간다. 3과제의 점수는 배포가 아니라 **그다음 두 시간**에서 갈린다 — 트래픽이 들어온 뒤 가용성·성능·비용을 동시에 지키는 운영이다.

이 모듈이 훈련하는 것은 손이 아니라 **판단의 순서**다. 지표를 보고, 노브를 하나만 돌리고, 다시 재는 것. 두 개를 동시에 바꾸면 무엇이 들었는지 알 수 없고, 그 상태로는 다음 판단도 못 한다.

## 목표

- [ ] k6 3단 프로파일(정상·과부하·지속)로 부하를 주고 SLO 를 지키는지 판정한다
- [ ] 30초 주기 감시 루프로 파드·노드·큐·응답 시간을 함께 본다
- [ ] 노브를 하나 돌리고 재측정해 **변화를 원인과 결과로 설명한다**
- [ ] 부하 중 장애 10종 중 7개 이상을 5분 안에 복구한다
- [ ] 부하 전 구간에서 노드를 비용 밴드 안에 유지한다
- [ ] 노드 시간을 직접 재고 회차마다 줄이면서 SLO 가 버티는 한계를 찾는다
- [ ] 드릴이 끝나면 부하부터 멈추고 스택을 지운다

## 소요 시간

- 8~10시간 (부하 드릴 3회 + 장애 드릴). Week 4.

## 과금 / destroy

:::caution[시간당 과금이 가장 비싼 구간이다]
EKS + NAT GW + ALB + CloudFront + RDS Multi-AZ + 노드 최대 7대가 동시에 떠 있다.

- 드릴 1회는 배포~부하~정리까지 **3시간 안에** 끝내고 당일 destroy 한다.
- 부하는 자기 CloudFront 로만 주입한다. 종료 시 **부하부터 멈추고** 스택을 지운다.
- 정리 순서: k6 중지 → `kubectl delete` → `eksctl delete cluster` → `terraform destroy` → [잔존 리소스 점검](/reference/cleanup-check/).
:::

## 공식 문서

전부 읽지 않는다. 각 문서에서 **읽을 자리**만 적었다. 부하 중에는 문서를 찾을 시간이 없으므로 지금 읽는다.

**모듈에 들어가기 전에 읽는다**

- [파드에 CPU·메모리 리소스 할당](https://kubernetes.io/docs/tasks/configure-pod-container/assign-cpu-resource/) · CPU 요청이 초과될 때의 동작. CPU limit 을 걸지 않는 판단의 근거다
- [MySQL — 옵티마이저가 인덱스를 쓰는 방식](https://dev.mysql.com/doc/refman/8.0/en/mysql-indexes.html) · WHERE 절과 인덱스의 관계를 다루는 앞부분. 인덱스 하나가 성능 축을 좌우하는 이유가 여기 있다
- [CloudFront — 캐시 키와 캐시 정책](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/controlling-the-cache-key.html) · 캐시 키 구성 항목. 응답이 요청 값을 되돌려주는 API 를 왜 캐시할 수 없는지가 여기서 갈린다

**실습 중 대조한다**

- [Karpenter Disruption](https://karpenter.sh/docs/concepts/disruption/) · consolidation 항목. 노드 시간을 깎는 드릴이 이 동작 위에 선다
- [RDS Proxy 개념](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/rds-proxy.html) · 커넥션 풀링과 다중화 항목. 파드가 늘어도 백엔드 커넥션이 늘지 않는 구조다
- [WAF — Web ACL 규칙 평가 순서](https://docs.aws.amazon.com/waf/latest/developerguide/web-acl-processing.html) · 규칙 우선순위와 종료 동작 항목
- [k6 — 시나리오 실행기](https://grafana.com/docs/k6/latest/using-k6/scenarios/) · `ramping-vus` 와 `constant-arrival-rate` 두 항목. 부하 프로파일 3단이 이 둘로 만들어진다
