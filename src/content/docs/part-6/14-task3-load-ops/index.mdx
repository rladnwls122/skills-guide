> 문서 유형: 개요

3과제는 리소스 존재 여부를 세지 않는다. 트래픽을 주입하고 **결과 로그(`results_<비번호>.log`)의 4개 비율**만 본다 — 비정상 요청 처리·가용성·성능·비용 ratio 40점. 배포는 입장권이고, 점수는 T+60분 트래픽 개시 이후 2시간의 운영에서 갈린다.

이 모듈은 배포를 T+50분 안에 끝내고, 부하 중 4축을 동시에 지키는 튜닝·감시·복구를 훈련한다.

## 목표

- [ ] 정답지(`skills-2026/task-3`) 런북으로 CloudFront 스택을 **T+50분 내** 배포하고 스모크 6종 통과
- [ ] 부하 드릴에서 user·product `p(90) < 200ms`, stress `p(90) < 1000ms`, 실패율 < 10% 달성
- [ ] 부하 전 구간에서 노드 2~9대 밴드 유지 (비용 ratio 0.5~3.75)
- [ ] 부하 중 장애 10종 중 7개 이상을 확인 명령 → 조치 순서로 5분 내 복구

## 소요 / 일차

- Day 15~16, 각 8~10시간 (배포 1시간 + 부하 드릴 3회 + 장애 드릴)

## 과금 / destroy

- **시간당 과금이 가장 비싼 모듈**: EKS + NAT GW + ALB + CloudFront + RDS Multi-AZ(db.t3.micro) + 노드 최대 9대.
- 드릴 1회는 배포~부하~정리까지 3시간 안에 끝내고 **당일 destroy**한다.
- k6 부하는 자기 CloudFront로만 주입한다. 종료 시 부하부터 멈추고 스택을 지운다.
- 정리 순서: k6 중지 → `kubectl delete` → `eksctl delete cluster` → `terraform destroy` → [잔존 리소스 점검](/reference/cleanup-check/).
