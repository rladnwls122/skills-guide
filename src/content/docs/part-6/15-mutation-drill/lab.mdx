## 훈련 ① — 30분 치환 드릴

타이머 30분. 변형 과제지를 받는 순간 시작.

<Steps>

1. **변경 분류** — 변경 목록을 훑고 **접두어 변경 / 개별 이름 변경 / 스펙 변경**으로 나눈다 (2분)

2. **기계 치환** — 이름 변경 건별로

   ```bash
   grep -rl --exclude-dir=.terraform '옛이름' . | xargs sed -i 's/옛이름/새이름/g'
   ```

3. **스펙 변동 직접 수정** — `terraform.tfvars` 열어 CIDR·타입·개수 수정 (sed로 안 잡히는 것)

4. **숨는 곳 8종 순회 점검** — tfvars / YAML 리터럴(라벨 키 `wsc2026/node` 류) / JS 코드(쿠키명 `x-sp-ab`, KVS 키명) / Grafana dashboard JSON / mark.sh / eksctl cluster.yaml / userdata 템플릿 / Lambda env

5. **최종 검증** — 옛이름 전부에 대해

   ```bash
   grep -rn --exclude-dir=.terraform '옛이름' .   # 0건이어야 함
   ```

6. **`terraform fmt && terraform validate` 통과**

7. **(스택이 떠 있으면) apply 후 mark.sh 재실행**

</Steps>

### 판정 기준

| 항목 | 기준 |
|---|---|
| 시간 | **30분 내** 5번(누락 0건 확인)까지 도달 |
| 누락 | 옛이름 잔존 grep **0건** |
| 채점 | mark.sh **재통과** (스택 미기동 시 validate + mark 리터럴 대조로 대체) |

미달이면 변경 목록을 새로 받아 재도전. 통과 기록 2회가 목표.

## 훈련 ② — 아키텍처 이해 검증 (종이 먼저)

<Steps>

1. **에디터를 열기 전에** 새 변형 과제지를 받고 종이에 답한다

   - 각 변경이 닿는 컴포넌트는? (예: 헤더 값 변경 → CloudFront 커스텀 헤더 + ALB 리스너 룰)
   - 각 변경이 닿는 파일 경로는? (terraform/*.tf, k8s/*.yaml, app/*, eksctl/*)

2. **대조** — 종이 목록 완성 후 grep으로 실제 영향 파일을 뽑아 맞춰본다

3. **누락 기록** — 종이에서 빠뜨린 파일마다 "왜 못 봤는가"를 한 줄로

4. **수정 진행** — 그 다음에 훈련 ①과 동일 절차

</Steps>

**판정**: 종이 목록과 실제 영향 파일의 일치율 80% 이상. 이해했으면 바뀐 요구사항이 닿는 파일이 즉시 보인다 — 안 보이면 해당 컴포넌트의 PART-2~4 모듈로 돌아간다.

## 훈련 ③ — mark 스크립트 표 만들기

[mark 스크립트 가이드](/reference/mark-script-guide/)의 읽기 절차를 그대로 사용해 mark 스크립트 **3개**(set-02/task-1 mark.sh, set-02/task-2 mark2-2.sh, set-07/task-2 mark2.sh)를 표로 정리한다.

<Steps>

1. **항목(N-N) 단위로 자른다**

2. **표 작성** — **항목 | 검사 명령 | 기대값(리터럴)**

   예시 (set-02 mark.sh 7-2):

   | 항목 | 검사 명령 | 기대값 |
   |---|---|---|
   | 7-2-A | `aws elbv2 describe-rules ... HttpHeaderConfig.Values[]` + `curl http://$ALB_DNS/book` | 커스텀 헤더 값 + `403` |
   | 6-1-A | `aws lambda get-function-configuration --function-name wskorea26-book-lambda` | 이름·런타임·`TABLE_NAME` env |

3. **기대값의 모든 리터럴을 구현 체크리스트로 옮긴다**

4. **환경 준비 라인 표시** — sleep/재시도 항목과 `rm -rf ~/.aws` 같은 줄 (set-07 mark2.sh 첫머리 실측 — 반드시 CloudShell에서)

</Steps>

**판정**: 3개 스크립트 전 항목이 표에 있고, 각 표의 리터럴만 보고 "무엇을 만들어야 하는지" 재구성이 가능하면 통과.
