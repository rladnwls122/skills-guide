## 규칙 (대회 조건 재현)

:::tip[허용 — 대회장에서 쓸 수 있는 것 전부]
자기 런북·skills-2026 저장소·이 가이드·본인 노트·AWS 공식 문서·CLI help·**Amazon Q**.
:::

:::caution[닫아 둘 것 — 조건을 대회장과 같게]
평소 쓰던 학습용 AI(Claude·GPT 등)와 검색엔진. 대회 도구는 Amazon Q와 공식 문서다. Q를 쓰되 출력은 공식 문서로 검증한다 — 절차는 [모듈 26](/part-6/26-ai-assisted-drill/)에 있다.
:::

- 타이머 **4시간**. set-02 1과제(또는 가장 자신 없는 세트)를 완주. 작업 루트는 `~\skills-2026\set-02\task-1` — 저장소가 없다면 [사전 준비 §4 저장소 클론](/start/#4-저장소-클론)을 타이머 시작 **전에** 끝낸다.
- 막힘 기록: 런북 밖 상황에서 10분 이상 소모한 항목은 즉시 오답 노트에 기록.
- 파이프라인: terraform → docker/ECR → eksctl → k8s/helm → 검증 시드 → mark.sh 셀프 채점.

:::danger[변형 주입 — T+1:00 개봉]
모의 대회 전날 저녁 AI에게 "문서에 없는 소형 신규 요구 3건"을 만들게 해 봉인해 둔다(예: SNS 장애 알림 토픽 추가, S3 수명주기 규칙, ALB 액세스 로그 활성화, DynamoDB TTL, 특정 태그 정책).

**T+1:00에 개봉** — 런북에 없으므로 개념+콘솔+공식 문서로 즉석 해결해야 한다. 콘솔로 먼저 만들어 통과시킨 뒤 여유 있으면 IaC 반영.
:::

선행 지식과 목표는 [모듈 개요](/part-6/25-mock-exam/)에.

:::note[실전 참조 — 막히면 여는 곳]
- 변형 카드는 런북 밖 요구다. [Terraform AWS Provider 리소스 목록](https://registry.terraform.io/providers/hashicorp/aws/latest/docs)에서 리소스 타입부터 찾는다
- 인터넷 없이 끝나는 조회: `aws <서비스> <명령> help` · `kubectl explain <경로>` · `helm show values <차트>`
- 채점 직전 리셋은 [mark 스크립트 가이드](/reference/mark-script-guide/), 착수 순서는 [소요 시간표](/reference/timings/)
- 4시간을 검색에 뺏기지 않으려면 [실전 문서 검색 가이드](/reference/search-guide/)의 훈련 드릴을 미리 돌린다
:::

## 진행 절차

착수 순서는 [소요 시간표](/reference/timings/) — 긴 것 먼저.

- [ ] **T+0:00** 타이머 시작. mark 항목 표 훑기(5분) — 무엇이 채점되는지부터
- [ ] **T+1:00** 변형 카드 3장 개봉 — 각 15분 상한, 콘솔 우선으로 해결 후 본 파이프라인 복귀
- [ ] **T+0:05** terraform apply 시작 (VPC·IAM·데이터·ECR)
- [ ] apply 완료 즉시 **eksctl create cluster 던지기** (~20분)
- [ ] eksctl 대기 중 CloudShell에서 **docker build/push 병렬** + ECR 스캔 결과 확인 (High/Critical이면 `apk upgrade --no-cache` 재빌드)
- [ ] 클러스터 완료 → kubeconfig → helm/k8s apply (번호 prefix 순서)
- [ ] ingress로 ALB 확보 → **2차 apply** (`-var enable_cdn=true`) → `aws cloudfront wait distribution-deployed`
- [ ] 전파 대기 중 검증 시드 준비 (POST 데이터·트래픽·Grafana 패널)
- [ ] **T+3:20 목표** 구현 완료. [mark 스크립트 가이드](/reference/mark-script-guide/)의 **채점 직전 리셋 체크리스트** 수행
- [ ] mark.sh 실행 (지정 환경에서 — `rm -rf ~/.aws`류 있으면 반드시 CloudShell) → 항목별 O/X 기록
- [ ] **T+4:00** 하드 스톱. 미완이어도 채점

## 판정 기준

| 항목 | 기준 |
|---|---|
| 자동 채점 | mark.sh **90% 이상** 득점 (런북과 대회 도구만으로) |
| 변형 대응 | 변형 3건 중 **2건 이상**을 각 15분 내 해결 — 문서 밖 대응력의 직접 측정 |
| 백지 도식 | 종료 후 아무것도 안 보고 아키텍처 재현 — **화살표별 인증 방식 주석**(OAC/커스텀 헤더/IRSA 등) 포함 |
| 운영 | 착수 순서가 [timings](/reference/timings/)와 일치했는가, 리셋 체크리스트 누락 0건 |

90% 미만이면: 실패 항목이 몰린 컴포넌트의 PART 모듈 재실습 후 **다른 세트로 재시험**.

## 오답 노트 양식 (3열)

```
| 증상 | 원인 | 다음에 칠 명령 |
|---|---|---|
| TG unhealthy 지속 | probe path 오타 | kubectl describe pod → describe-target-health |
```

- 런북 밖에서 10분+ 소모한 항목, 변형 카드 실패 항목도 한 행으로 기록.
- 작성 후 실패 항목을 [트러블슈팅](/reference/troubleshooting/)에 자기 언어로 추가.

## 종료 후 (남는 시간)

- [ ] 오답 노트 → [troubleshooting](/reference/troubleshooting/) 반영
- [ ] 선택 A — **3과제 대비**: 1시간 내 "빌드+트래픽" 미니 스택 (set-02 스택 축소판: VPC 최소 + 앱 1개 배포 + curl 트래픽 검증)
- [ ] 선택 B — 취약 모듈 재실습 (오답 노트에서 가장 빈번한 컴포넌트)
- [ ] **스택 전체 destroy** — k8s(LBC ALB 포함) → eksctl delete → terraform destroy → 콘솔 잔존 확인
