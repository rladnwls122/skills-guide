> 문서 유형: 개요

도구로 Amazon Q 만 열 수 있는 조건을 가정한다. 그러면 훈련의 목표가 "전부 외워서 손으로 쓰기"에서 **"Q의 초안을 빠르게 검증해 고치기"**로 옮겨간다. 이 모듈은 그 왕복을 시간 안에 도는 절차를 만든다.

:::caution[근거와 한계]
Amazon Q 사용 가능은 2026-08 실습 강의에서 확인된 사항이다. 그 이전의 "제공 여부 협의 중" 방침을 대체한다. 제공 형태는 대회 직전에 다시 바뀔 수 있으므로, **Q가 없어도 손으로 쓸 수 있는 상태**를 함께 유지한다.
:::

Q가 코드를 대신 써 준다고 해서 문법을 안 익혀도 되는 것은 아니다. 채점은 리소스 이름과 인자값의 정확 일치를 보고, Q의 출력은 그럴듯한 옛 인자명을 자주 섞는다. **틀린 곳을 짚어내는 능력이 곧 Q를 쓰는 능력**이다.

## 목표

- [ ] 과제지 한 문단을 Q 프롬프트 3요소(버전·이름·판정 방법)로 옮겨 쓴다
- [ ] Q가 낸 Terraform 리소스 초안의 오류를 **공식 문서로 3분 안에** 특정한다
- [ ] 매니페스트·WAF 규칙·CloudFront Function 각 1건을 Q 초안 → 검증 → 적용까지 통과시킨다
- [ ] Q 출력의 실패 유형 4종(옛 인자명·없는 필드·이름 불일치·과잉 리소스)을 자기 사례로 채운다
- [ ] 변형된 요구사항 1건을 Q와 함께 15분 내 반영하고 적용까지 끝낸다

## 소요

정해진 주차 없음 — 배점이 없는 훈련이라 시간이 남을 때 끼워 넣는다. 약 3~4시간. 모의 대회(모듈 25) 전에 한 번은 끝내 둔다.

## 과금 / destroy

- 드릴 A~C는 `terraform plan`·`kubectl apply --dry-run=server` 까지만 하면 과금이 없다.
- 실제 적용까지 확인하는 드릴 D·E는 기존 실습 스택 위에서 돌리고 당일 destroy 한다.
- 정리 확인은 [잔존 리소스 점검](/reference/cleanup-check/).

- HCL 블록 구조와 변수·`locals` — Q 출력의 어느 줄이 인자이고 어느 줄이 블록인지 구분 — [hcl-basics](/start/hcl-basics/)

## 공식 문서

전부 읽지 않는다. 각 문서에서 **읽을 자리**만 적었다. 이 모듈에서 문서는 배우는 곳이 아니라 **AI 출력을 반증하는 곳**이다.

**드릴에 들어가기 전에 읽는다**

- [Amazon Q Developer](https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/what-is.html) · 기능 범위와 제약 항목. 무엇을 못 하는지를 알아야 어디를 의심할지 정해진다
- [Terraform AWS Provider](https://registry.terraform.io/providers/hashicorp/aws/latest/docs) · 리소스 페이지의 인자 목록. 존재하지 않는 인자를 지어낸 출력을 여기서 잡는다

**드릴 중 대조한다**

- [kubectl explain](https://kubernetes.io/docs/reference/kubectl/generated/kubectl_explain/) · 명령 사용법. 필드가 실재하는지 클러스터에 직접 묻는 방법이다
- [WAF 규칙 구문](https://docs.aws.amazon.com/waf/latest/developerguide/waf-rule-statements.html) · statement 종류 목록과 중첩 규칙. 생성된 규칙의 구조를 대조한다
- [CloudFront Functions](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-functions.html) · 런타임 제약과 이벤트 객체 구조
