> 문서 유형: reference

`terraform destroy`·`eksctl delete cluster`가 끝나도 **과금은 끝나지 않았을 수 있다.**
매일 학습 종료 시 아래 블록을 통째로 실행하고, 출력이 비어 있어야 그날이 끝난 것이다.

## destroy가 못 지우는 것 (:badge[실측]{variant=note} :badge[함정]{variant=danger})

| 잔존물 | 왜 남나 | 삭제 |
|---|---|---|
| LBC가 만든 ALB + SG | terraform/eksctl 밖에서 컨트롤러가 생성 — **클러스터를 ingress 삭제 전에 지우면 고아**가 된다 | 콘솔 EC2 → Load Balancers / Security Groups 수동 삭제 |
| 동적 PVC의 EBS 볼륨 | StorageClass `reclaimPolicy: Retain`이면 클러스터 삭제 후에도 available로 잔존 | `aws ec2 delete-volume` |
| NAT GW의 EIP | NAT 삭제 후 EIP가 미연결 상태로 남으면 과금 | `aws ec2 release-address` |
| CloudWatch 로그 그룹 | Fluent Bit·Lambda가 만든 그룹은 IaC 밖 — 비용은 미미하나 **다음날 재생성 시 이름 충돌** | `aws logs delete-log-group` |
| ECR 이미지 | 리포는 destroy돼도 `--force` 없으면 이미지 있는 리포는 삭제 실패 | `aws ecr delete-repository --force` |

:::caution[순서 원칙]
**k8s ingress/svc 삭제 → 클러스터 삭제 → terraform destroy**.
역순으로 하면 LBC 고아 ALB·SG 때문에 VPC destroy가 `DependencyViolation`으로 막힌다.
:::

## 일괄 점검 블록 (CloudShell/Git Bash에 통째 붙여넣기)

```bash
echo "=== Running EC2 ===" && aws ec2 describe-instances \
  --query 'Reservations[].Instances[?State.Name==`running`].[InstanceId,InstanceType,Tags[?Key==`Name`].Value|[0]]' --output text
echo "=== EKS ===" && aws eks list-clusters --output text
echo "=== ALB/NLB ===" && aws elbv2 describe-load-balancers \
  --query 'LoadBalancers[].[LoadBalancerName,Scheme]' --output text
echo "=== NAT GW ===" && aws ec2 describe-nat-gateways --filter Name=state,Values=available \
  --query 'NatGateways[].NatGatewayId' --output text
echo "=== Idle EIP ===" && aws ec2 describe-addresses \
  --query 'Addresses[?AssociationId==null].[PublicIp,AllocationId]' --output text
echo "=== Unattached EBS ===" && aws ec2 describe-volumes --filters Name=status,Values=available \
  --query 'Volumes[].[VolumeId,Size]' --output text
echo "=== MSK ===" && aws kafka list-clusters-v2 \
  --query 'ClusterInfoList[].[ClusterName,State]' --output text
```

:::tip[판정 기준]
전부 빈 출력(또는 의도적으로 유지 중인 것만)이면 통과. D4→D5처럼 README에 명시된
유지 예외만 남긴다.
:::

## 비용 실측 (다음날 아침 확인)

Cost Explorer 반영은 최대 24시간 지연 — destroy 당일이 아니라 다음날 확인한다.

```bash
aws ce get-cost-and-usage \
  --time-period Start=$(date -u -d '7 days ago' +%F),End=$(date -u +%F) \
  --granularity DAILY --metrics UnblendedCost \
  --query 'ResultsByTime[*].[TimePeriod.Start,Total.UnblendedCost.Amount]' --output table
```

어제 비용이 $0에 수렴하지 않으면 서비스별로 범인을 찾는다:

```bash
aws ce get-cost-and-usage \
  --time-period Start=$(date -u -d '2 days ago' +%F),End=$(date -u +%F) \
  --granularity DAILY --metrics UnblendedCost \
  --group-by Type=DIMENSION,Key=SERVICE --output table
```
