> 문서 유형: reference

이 문서는 **학습용이 아니다.** 대회장에 앉은 뒤 위에서 아래로 실행하는 순서이고, 각 단계에서 어느 문서를 여는지의 색인이다. 정답지 저장소(`skills-2026`)의 `DAY-OF.md` 가 명령 전문을 가진 정본이고, 여기서는 **판단이 갈리는 지점과 사이트 문서로의 연결**만 남긴다.

:::danger[대회장의 전제 넷]
- **과제지는 종이로 배부된다.** 파일 대조(diff)가 불가능하고 눈으로 훑어야 한다.
- **재시동하면 파일이 초기화된다.** 도구 설치와 클론을 매번 다시 한다.
- **AI 코딩 보조가 없다.** 웹 Amazon Q 만 허용되고 그마저 확정이 아니다([대회 운영 규칙](/reference/competition-rules/)).
- **추가 시간이 없다.** 문항이 늘어도 시간은 그대로다.
:::

## 과제별로 날이 다르다

| 날 | 과제 | 성격 |
|---|---|---|
| Day 1 | 1과제 | 단일 리전 종합 인프라. 한 스택을 끝까지 |
| Day 2 | 2과제 | 독립 모듈 4~6개. 모듈별 병렬 |
| Day 3 | 3과제 | 당일 배부 앱을 분석해 띄우고 운영 |

**성격이 다르므로 운영 방식도 다르다.** 1과제는 순서대로 쌓고, 2과제는 오래 걸리는 것부터 병렬로 던지고, 3과제는 배포를 입장권으로 보고 그 뒤 운영에서 점수를 낸다.

## 0. 도착 직후 — 과제지를 펼치기 전

끝 조건: `aws sts get-caller-identity` 성공 · CloudShell 접속 확인 · 저장소 클론.

두 트랙으로 병행한다. 도구 설치가 도는 동안 손이 비므로 브라우저에서 콘솔 로그인과 액세스 키 발급을 끝낸다.

| 터미널 | 브라우저 |
|---|---|
| 도구 일괄 설치 스크립트 실행 | 콘솔 로그인 → 액세스 키 발급 |
| 저장소 클론 | CloudShell 탭 그룹·즐겨찾기 세팅 |

합류점은 `aws configure` 다 — CLI 설치와 키 발급이 **둘 다** 끝난 뒤 새 터미널에서 한다.

:::caution[CloudShell 경로를 여기서 검증한다]
EKS 가 나오는 과제라면 채점은 **선수의 일반 CloudShell** 에서 이뤄지고, 허용되는 명령은 `aws eks update-kubeconfig` 한 줄뿐이다. 그 한 줄 뒤에 `kubectl get nodes` 가 되는지를 **배포 직후 반드시 확인**한다.

작업용 bastion 을 만들었다면 채점 전에 지우는데, **지우기 전에 CloudShell 경로를 먼저 검증한다.** 지운 뒤에 권한이 없다는 것을 알면 손쓸 방법이 없다.
:::

## 1. 종이 과제지 대조 — 첫 15분

형광펜으로 표시하며 훑는다. 찾는 것은 셋이다.

1. **연습본과 다른 값** — 이름 접두사, 리전, CIDR, 인스턴스 타입, 개수, 버전.
2. **새로 붙은 문장** — 기존 문항 뒤에 한 줄이 붙는 형태가 대부분이다.
3. **사라진 문장** — 요구가 빠졌으면 그것을 만드는 것은 불필요 리소스 감점이다.

값 대조는 정답지의 `DAY-OF.md` **값 대조표**를 쓴다. 세트별로 이름·CIDR·리전이 한 표에 모여 있어, 종이와 표를 나란히 놓고 다른 칸에 형광펜을 친다.

:::note[이름 오타를 만나면]
과제지에 오타가 있어도 **적힌 그대로 쓰는 것이 원칙**이다. 채점이 이름을 정확히 비교하기 때문이다.

단 정정 공지로 이미 고쳐진 오타가 있다 — [정정 내역](/reference/errata/)을 먼저 본다. 고쳐진 오타를 사양으로 착각해 그대로 쓰면 그쪽이 오답이 된다.
:::

## 2. 추가 문항 — 명사 하나를 뽑아 키트를 고른다

과제의 30% 범위에서 문항이 **추가**된다. 기존 문항을 갈아엎는 것이 아니라 붙는 방식이라, 대응도 붙이는 방식이다.

정답지 저장소의 `shared/addons/` 에 **부착 키트 36개**가 있다. 기존 세트의 Terraform 상태를 건드리지 않고 파일만 복사해 얹는 구조다.

| 단계 | 하는 일 | 끝 조건 |
|---|---|---|
| 1 | 바뀐 문장에서 **명사 하나**를 뽑는다 (`WAF`, `TTL`, `액세스 로그`, `CMK`) | 키트 하나 결정 |
| 2 | 그 키트 README 를 연다 | `CHANGE` 표의 필수 변수 확인 |
| 3 | 코드 블록을 지정된 `.tf` 파일에 붙인다 | 세트의 리소스 주소로 치환 |
| 4 | `fmt` → `init` → `validate` → `plan` | **기존 리소스에 replace/delete 0건** |
| 5 | apply 후 세트 `mark.sh` 로 확인 | 해당 항목 통과 |

**4단계의 끝 조건이 안전장치다.** `plan` 에 기존 리소스의 replace 나 delete 가 뜨면 apply 하지 않고 멈춘다. 이름이 충돌하면 **기존 것을 지우지 말고 키트 쪽 변수를 리네임**한다 — 사전 제공 리소스를 지우는 것은 되돌릴 수 없다.

키트를 고르는 훈련은 [23. 변동 드릴](/part-6/23-mutation-drill/)에서 한다.

### 1과제 추가 문항이 나오는 자리

필수 항목은 이미 다 구현돼 있으므로, 새 문항은 **아직 안 쓰인 옵션**에서 나온다.

| 옵션 | 첫 판단 |
|---|---|
| **관측성** (가장 유력) | Container Insights 는 애드온 한 줄 · 도구형(Grafana/Loki)은 기존 세트의 monitoring 복사 |
| KMS | 대상이 신규 리소스인지 기존 리소스인지 먼저 판별한다 — RDS·EBS·ECR·EKS 는 **생성 후 변경 불가** |
| WAF | Web ACL 이 없으면 새로 · 있으면 룰만 추가 |
| IAM·IRSA | 채점이 ServiceAccount 의 `role-arn` annotation 을 읽으면 IRSA, 아니면 Pod Identity |
| Lambda GET API | 기존 세트의 `lambda.tf` 가 가장 가까운 재료다 |

넘으면 오독인 금지선도 있다 — **인프라 스케일링 문항은 1과제에 없고**, 서드파티 애드온(Istio·Cilium·Nginx 등)은 쓸 수 없으며, Helm 자체는 채점 요소가 되지 않는다.

## 3. 코드 블록을 고칠 때 — 치환 자리

키트 코드의 꺾쇠 표기는 전부 치환 대상이다. 하나라도 남으면 `validate` 에서 걸린다.

| 표기 | 어디서 얻나 |
|---|---|
| `<기존>` | 자기 세트 `.tf` 에서 리소스 주소를 직접 뽑는다 — `resource "aws_s3_bucket" "web"` 이면 `web` |
| `<클러스터>` · `<region>` | `terraform.tfvars`, 과제지 |
| `<이름>` · `<버킷>` | **과제지 원문 그대로** |
| `<account_id>` | `aws sts get-caller-identity --query Account --output text` |
| `<선수번호>` | 좌석표·과제지 |

**세트별 대조표를 찾기보다 자기 세트에서 직접 뽑는 편이 빠르고 언제나 맞는다.** 표는 일부 세트만 채워져 있고 당일 세트는 표에 없다.

## 4. 채점 직전

| 확인 | 왜 |
|---|---|
| 일반 CloudShell 에서 `update-kubeconfig` 한 줄 뒤 `kubectl get nodes` | 안 되면 k8s 항목 전부 소실 |
| 요구되지 않은 리소스가 남아 있지 않은가 | 존재 자체가 감점 |
| 데이터 상태가 채점이 기대하는 상태인가 | 남은 데이터가 오답을 만드는 항목이 있다 |
| 대시보드·지표에 `No Data` 패널이 없는가 | 값이 없으면 미충족으로 본다 |
| 로그 시각이 요구된 시간대인가 | 아홉 시간 어긋나면 그대로 실점 |

세트별 리셋 절차는 각 과제의 `README.md` 에 있다. 데이터를 비우는 항목은 [정정 내역](/reference/errata/)을 함께 본다 — 무엇을 비운 상태로 두어야 하는지가 정정으로 바뀐 세트가 있다.
