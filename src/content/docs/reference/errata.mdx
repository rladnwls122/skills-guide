> 문서 유형: reference

배포된 과제지·채점지 파일과 **실제 채점 기준이 다를 수 있다.** 이의 제기로 확정된 정정은 별도 공지로 오고 파일이 항상 다시 배포되지는 않는다. 이 문서는 그 차이를 모은다 — 정답지나 이 사이트의 다른 문서가 정정 전 기준으로 쓰여 있으면 **여기가 우선**이다.

개별 항목이 아니라 질의 절차·수정 범위·지급 권한 같은 운영 규칙은 [대회 운영 규칙](/reference/competition-rules/)에 있다.

## 정정 절차와 일정 :badge[협의회]{variant=note}

지도교사 협의회(2026-07-31)에서 확정된 절차다.

- **접수 창구**: 마이스터넷 과제 출제 게시판의 댓글. 접수 대상은 **오류와 오류 정정에 관한 사항만**이고, 과제 내용 자체의 수정 요청은 받지 않는다.
- **오류 제기·수정 마감**: 대회 10일 전인 **8월 13일**. 접수된 건은 72시간(3일) 이내 처리된다.
- **정정 방식**: 출제자는 게시된 과제 파일을 직접 고치지 않고 **댓글 또는 텍스트 파일**로 변경 사항을 안내한다. 정정 내역 표에 "과제지에 명시"라고 적힌 항목도 배포본이 그대로일 수 있다 — 공지된 내용이 기준이다.
- **취합본은 최종본이 아니다**: 심사장이 접수분을 취합해 공유할 수 있으나 대회 기간 중 검토로 또 바뀔 수 있다.
- 13일 이후에도 오류가 나올 수 있어 추가 정정은 불가피하다는 답변이 있었다. 마감 뒤 심사진이 발견한 오류는 대회 기간 중 과제 검토를 거쳐 수정·삭제된다. **대회 직전까지 공지를 다시 확인한다.**
- set-08 채점지는 정확한 확인 방법이 명시되지 않은 항목이 있어, 기존 파일을 고치는 대신 **예상 출력값을 별도 텍스트 파일로 제공할 예정**이다. 그 파일이 나오면 출력형 채점의 기대 출력 정본이 된다.

## set-07 (제기됨 — 답변 대기)

확정 답변이 아직 없는 질의다. 아래 대부분은 **채점에는 통과하지만 과제지를 그대로 읽으면 오답으로 가는** 유형이라, 답변을 기다리기보다 각 항목의 "실측 대응"대로 만들어 두는 편이 안전하다.

### 2과제

| 모듈 | 제기된 문제 | 실측 대응 |
|---|---|---|
| 2모듈 | 과제지는 Distribution **Name**을 `skillsphone-cdn-ab-distribution`으로 명시하는데, 채점은 **Comment(설명)** 값을 확인한다. 콘솔에서 Name을 지정하면 Name 태그로 들어가 채점과 어긋난다 | Comment에 그 값을 넣는다. Name 태그는 별개로 둔다 |
| 3모듈 | **과제지에 스케일인 시간 요건이 없는데** 채점 3-7이 시간 안에 수렴을 요구한다. KEDA `min ≥ 1`이면 HPA에 위임되고 HPA 기본 안정화 창이 300초, Karpenter `consolidateAfter`가 60초라 **기본 설정으로는 182초가 걸려 실패**한다 | `scaleDown` behavior를 직접 오버라이드한다. 이 값들은 3-4-A·3-5-A 채점에 영향을 주지 않는다 |
| 3모듈 | 스케일인 대기 루프가 `mark3.sh`에서 `for i in $(seq 1 30)` — 5초 간격이라 **실질 150초**인데 채점지 문구는 "최대 3분 대기"다. 환경에 따라 Karpenter 통합과 EC2 종료에 150초를 넘겨 `Final Pods 1 / Final Nodes 2`가 나온다. `seq 1 60`으로 늘리면 정상 수렴 확인 | 반복 횟수 상향 요청 접수. 그전까지는 **150초 안에 끝나도록** 시간 예산을 짠다 |
| 3모듈 | 3-3-A 채점지의 노드 예상 출력에 `v1.35.5-eks-...`가 박혀 있다. 과제지는 클러스터 버전 `1.35`만 지정하므로, **노드 kubelet 패치 버전은 AMI 릴리스에 따라 달라진다** | 패치 번호까지 맞출 방법이 없다. 버전 불일치로 감점되면 이의 사유가 된다 |
| 4모듈 | 제공 `Dockerfile`이 Flask를 설치하지 않고 같은 폴더에 `requirements.txt`도 없다(3모듈에는 있다). 그대로 빌드하면 CrashLoop | **자체 Dockerfile로 빌드하되 제공 `app.py`는 수정하지 않는다** |

### 1과제

| 제기된 문제 | 실측 대응 |
|---|---|
| 과제지 11번이 와일드카드 액션·리소스를 금지하는데 `ec2:DescribeVpcs`는 리소스 와일드카드를 피할 수 없다. 채점 스크립트가 액션만 검사하고 리소스는 보지 않아 통과는 된다 | 액션은 개별 나열하고 리소스 와일드카드는 불가피한 것만 남긴다 |
| WAF **Managed Rule Group의 차단에는 커스텀 응답 본문을 붙일 수 없다.** 과제지는 Override 없이 그대로 적용하라면서 차단 응답 본문까지 요구한다 — Rule-level override 없이는 구조적으로 불가능하다. 채점은 상태 코드만 확인해 통과한다 | 커스텀 룰(레이트 제한)에만 커스텀 응답을 붙이고, 관리형 룰은 기본 403 본문을 둔다 |
| 모든 노드 시간대를 KST로 지시하는데 로그 `timestamp`는 `Z`(UTC) 접미사로 `date -u`와 1분 이내 일치를 본다. 로컬 시간으로 포맷하면서 `Z`를 붙이면 **정확히 9시간 어긋나** 12-1-A가 오답이 된다 | 노드 TZ와 무관하게 **로그 timestamp는 UTC(RFC3339 `Z`)로 기록**한다 |

| `client-id-created-at-index` GSI의 파티션 키가 `client_id`인데 Lambda API 입력에 `client_id`가 없어 **이 GSI를 쓸 경로가 없다.** 채점은 GSI 구성만 확인한다 | 구성만 요구대로 만들어 둔다 |

## set-08 · 2과제 (확정 — 2026-08-01 정정본 배포)

| 2-4 | Service EC2 보안 그룹의 TCP/8080 인바운드는 VPC Lattice 관리형 프리픽스 리스트로 제한한다. **`0.0.0.0/0` 허용이면 미충족** |
| 3-5 | Lambda를 직접 호출해 180초 안에 `IpPermissions`가 빈 배열이면 득점. **CloudTrail 전달 지연은 채점하지 않는다** |
| 4-4 | `minReplicaCount 0` · `maxReplicaCount 6` · `pollingInterval <= 15` · `cooldownPeriod <= 30` · 트리거 `aws-sqs-queue`의 `queueLength=2` |
| 4-5 | **`min 0`이라 채점 시점에 워커 Pod가 없어도 감점되지 않는다** — Pod의 EC2 배치는 4-6 스케일아웃 출력까지 포함해 판정한다 |
| 4-6 | 메시지 12건 발송 후 180초 안에 Pod 증가와 Karpenter 노드 1대 이상 Ready. `ApproximateNumberOfMessagesNotVisible`이 남아 있어도 실패가 아니고, **스케일인 시간은 채점하지 않는다.** 큐를 오염시키므로 **4모듈의 마지막 항목으로 수행**한다 |

### 채점 스크립트 수정 요지

- 네 스크립트 모두 앞부분이 "도구 없으면 종료"에서 **자동 설치**로 바뀌었다 — `sudo dnf install`로 `curl`·`jq`·`grep`·`unzip`을 깔고 AWS CLI와 `kubectl` v1.35.0을 `~/.local/bin`에 내려받는다. 채점 환경이 `dnf`를 쓰는 Amazon Linux 계열(CloudShell)임을 전제한다.
- `mark2-4.sh` 4-1의 `Vpc:vpcConfig`는 존재하지 않는 필드였다 — `resourcesVpcConfig.vpcId`와 `Subnets`로 교체됐다.
- 4-2·4-4·4-5의 조회가 **YAML 전문 덤프에서 `jq` 필드 추출로 바뀌었다.** 판정에 쓰는 필드만 출력되므로 그 필드가 비어 있으면 곧바로 감점이다.
- 4-6의 메시지 본문이 실행마다 달라지던 `skills-scale-out-<타임스탬프>-N`에서 **`judge-N` 고정**으로 바뀌었다.
