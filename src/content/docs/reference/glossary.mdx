> 문서 유형: reference

문서를 읽다 **모르는 단어가 나오면 여기로 온다.** 이 사이트가 계속 쓰는 말들이고, 대부분 이 분야가 아니라 **이 대회의 말**이라 검색해도 안 나온다.

:::tip[처음 왔다면]
아래 다섯 줄만 먼저 읽어도 문서가 읽힌다.

**과제**가 시험이고, **과제지**가 문제, **채점 스크립트**가 답안지다. 대회는 여러 벌의 과제를 만들어 두고 그중 하나를 뽑는데 그 한 벌이 **세트**다. 이 사이트는 실제로 상을 받은 세트의 구현을 **정답지**라 부르고, 그걸 읽으며 배운다.
:::

## 시험의 구조

### 과제

시험 한 판이다. 클라우드컴퓨팅 직종은 과제가 셋이고 성격이 다르다.

| | 이름 | 하는 일 | 시간 |
|---|---|---|---|
| 1과제 | Solution Architecture | 아키텍처 하나를 처음부터 세운다 | 4시간 |
| 2과제 | Small Challenge | 독립된 작은 모듈 여럿을 각각 푼다 | 4시간 |
| 3과제 | 운영 | 이미 있는 시스템을 부하 속에서 운영한다 | — |

1과제는 "만들 줄 아는가", 2과제는 "폭이 넓은가", 3과제는 "돌아가게 유지하는가"를 본다. 자세한 분해는 [실기출 분해](/reference/past-exams/)에 있다.

### 과제지 · 채점지 · 채점 스크립트

셋이 다른 문서다. **이 구분을 모르면 문서 절반이 안 읽힌다.**

| 말 | 실체 | 무엇을 말하나 |
|---|---|---|
| **과제지** | `task.md` | 무엇을 만들라는 **요구** |
| **채점지** | `mark.md` | 무엇을 볼 것인지의 **기준** |
| **채점 스크립트** | `mark.sh` | 실제로 실행되는 **검사 코드** |

셋이 어긋날 수 있다. 그때 통과 여부를 정하는 것은 **실행되는 코드**다 — 그래서 이 사이트는 [스크립트를 먼저 읽으라](/reference/mark-script-guide/)고 말한다.

`mark.sh` 는 대개 이런 모양이다. AWS 에 조회를 던져 나온 값을 기대값과 비교한다.

```bash
aws elbv2 describe-load-balancers \
  --query 'LoadBalancers[?LoadBalancerName==`wsc2026-alb`].Scheme' --output text
```

### 세트

대회는 같은 시험을 여러 벌 만들어 두고 그중 하나를 골라 낸다. **그 한 벌이 세트**이고 `set-02`·`set-03`·`set-07` 처럼 번호로 부른다.

세트마다 요구가 다르다 — 같은 "로그를 모아라"라도 어떤 세트는 CloudWatch 로, 어떤 세트는 Loki 로 요구한다. **번호가 같아도 주제가 같지 않다.**

### 후보 세트

여러 세트 중 이 사이트가 근거로 삼는 것들이다. 실제로 **상을 받아 구현이 검증된** 세트라 "이 형태면 점수가 나온다"의 증거가 된다.

1과제는 `set-02`·`03`·`07`, 2과제는 `set-02`·`07`·`08` 이다. 나머지 세트는 참고만 한다.

## 이 사이트가 쓰는 말

### 정답지

수상 세트의 실제 구현 코드다. `skills-2026` 저장소에 들어 있고 [사전 준비](/start/#4-저장소-클론)에서 클론한다.

**"답을 베끼는 곳"이 아니라 "읽고 대조하는 곳"이다.** 이 사이트의 설명 대부분이 "정답지의 이 파일이 왜 이렇게 생겼나"를 푸는 형태다.

:::caution[정답지가 곧 정답은 아니다]
저장소에 구현이 있다는 것과 그 구현이 채점을 통과했다는 것은 다르다. 어느 쪽인지는 [경로 매핑](/reference/links/)의 검증 상태 표에 적어 두었다.
:::

### 기준본

실습을 시작할 때 이미 서 있는 상태다. 보통 `set-02` 로 만든 스택이다.

처음부터 다시 만드는 것이 아니라 **기준본을 다른 세트의 요구에 맞게 고치는 것**이 이 사이트의 훈련 방식이다.

### 이행

기준본을 다른 세트의 요구로 **옮기는 것**이다. 이 사이트의 실습이 대부분 이 형태다.

> `set-02` 는 인터넷에서 닿는 로드밸런서를 쓴다. `set-07` 은 내부용을 쓴다.
> 기준본을 `set-07` 요구로 **이행하라** — 어디를 고쳐야 하나?

새로 만드는 것보다 어렵다. **무엇을 고치고 무엇을 지울지 판단**해야 하기 때문이다.

### 변동

당일 요구가 바뀌는 것. 이름·개수·리전 같은 값이 공개된 과제에서 30% 범위로 바뀐 채 나온다.

그래서 이 사이트는 속도가 아니라 **"바뀐 요구를 읽고 고칠 자리를 찾는 능력"** 을 기른다.

### 드릴

훈련 문서다. 만드는 순서를 알려 주지 않고 **요구만 주고 직접 하게 한다.**

모듈에 따라 문서가 셋이거나 넷이다.

| 문서 | 하는 일 |
|---|---|
| 개요 | 목표·소요 시간·비용 |
| 이론 | 왜 그렇게 되는가 |
| 실습(Lab) | 따라 만들며 세운다 |
| 드릴(Drill) | 요구만 받고 직접 이행하고, 심어 둔 고장을 진단한다 |

드릴이 있는 모듈은 **실습을 마친 뒤에** 연다.

### 런북

자기가 쓴 배포 절차 문서다. 남의 문서가 아니라 **자기 손으로 정리한 순서**를 말한다.

이 사이트를 다 읽는 것이 목표가 아니라, 읽고 나서 **자기 런북을 갖게 되는 것**이 목표다.

### 실기출

실제로 시행된 해의 과제다. 2024·2025 두 해를 분해해 [실기출 분해](/reference/past-exams/)에 정리했다.

문서에 `:badge[실기출]{variant=note}` 가 붙어 있으면 **실제로 나왔던 요구**라는 뜻이다.

### 실측

직접 만들어 보고 잰 값이다. `:badge[실측]{variant=note}` 가 붙은 숫자와 함정은 추측이 아니라 실제로 겪은 것이다.

예를 들어 "MSK 클러스터 생성 31분 40초"는 문서에서 옮긴 값이 아니라 [직접 잰 값](/reference/timings/)이다.

## 자주 나오는 AWS 약어

이 사이트가 풀어 쓰지 않고 지나가는 것들이다. 개념 자체는 [선수 학습](/start/)에서 다룬다.

| 약어 | 풀이 | 어디서 배우나 |
|---|---|---|
| VPC | 내 전용 가상 네트워크 | [vpc-basics](/start/vpc-basics/) |
| CIDR | 주소 범위 표기(`10.0.0.0/16`) | [vpc-basics](/start/vpc-basics/) |
| IAM | 누가 무엇을 할 수 있는지 정하는 체계 | [iam-basics](/start/iam-basics/) |
| ARN | AWS 리소스의 전역 고유 이름 | [iam-basics](/start/iam-basics/) |
| EKS | AWS 가 운영해 주는 쿠버네티스 | [eks-basics](/start/eks-basics/) |
| IRSA | 파드에 IAM 역할을 붙이는 방식 | [eks-basics](/start/eks-basics/) |
| ALB | 요청을 뒤로 나눠 주는 로드밸런서 | [loadbalancer-basics](/start/loadbalancer-basics/) |
| KMS | 암호화 키를 맡아 주는 서비스 | [kms-basics](/start/kms-basics/) |
| CMK | 직접 만들어 정책을 붙이는 키 | [kms-basics](/start/kms-basics/) |
| GSI | DynamoDB 에서 다른 축으로 찾게 해 주는 인덱스 | [dynamodb-basics](/start/dynamodb-basics/) |
| IaC | 인프라를 코드로 정의하는 방식(Terraform 등) | [hcl-basics](/start/hcl-basics/) |
