## 2과제 모듈 지도 — 후보 3세트 × 4모듈

2과제는 세트마다 **독립 모듈 4개**(각 7.5점)다. 후보가 set-02·07·08 셋이므로 사정권은 **12개 모듈** 전체다. 추첨된 1인의 세트 4개가 전부 출제되고, 협의회 공지대로 최대 2개가 더 붙어 최대 6개를 푼다 — 어느 세트가 뽑히든 그 세트의 1·2·3·4모듈을 다 풀어야 한다. **6개가 되어도 추가 시간은 없다**([대회 운영 규칙](/reference/competition-rules/)).

| 세트 | 1모듈 | 2모듈 | 3모듈 | 4모듈 |
|---|---|---|---|---|
| **set-02** | 서버리스 워크플로<br/>[모듈 09](/part-4/09-serverless-event/) · 정답지 O | Kinesis + Flink Studio<br/>[모듈 10](/part-4/10-scaling-logging-streaming/) · 정답지 O | 이벤트 자동복구<br/>[모듈 09](/part-4/09-serverless-event/) · 정답지 O | MSK<br/>[모듈 10](/part-4/10-scaling-logging-streaming/) · 정답지 O |
| **set-07** | DynamoDB NoSQL<br/>[모듈 03](/part-1/03-container-lambda-dynamodb/) · 정답지 O | CDN Function<br/>[모듈 13](/part-4/13-cdn-function/) · 정답지 O | KEDA + Karpenter<br/>[모듈 10](/part-4/10-scaling-logging-streaming/) · 정답지 O | OTel + Loki 로깅<br/>[모듈 10](/part-4/10-scaling-logging-streaming/) · **정답지 X** |
| **set-08** | DocumentDB<br/>[모듈 11](/part-4/11-documentdb/) · 정답지 O | VPC Lattice<br/>[모듈 12](/part-4/12-vpc-lattice/) · 정답지 O | Cloud Event Handling<br/>[모듈 09](/part-4/09-serverless-event/) · 정답지 O | Fargate + SQS 스케일링<br/>[모듈 10](/part-4/10-scaling-logging-streaming/) · 정답지 O |

"정답지 X"는 `skills-2026`에 구현이 없다는 뜻이고, 그 모듈의 근거는 과제지·채점지·채점 스크립트뿐이다. 리전이 모듈마다 다르고 **틀리면 그 모듈은 0점**이다.

set-08 2과제 4모듈은 2026-08-01에 구현이 들어와 근거가 코드로 바뀌었다. 단 **브랜치 `set-08/task-2`에 있고 `main`에 병합돼 있지 않다** — 클론만 해서는 보이지 않으니 브랜치를 먼저 체크아웃한다. 항목별 판정 기준은 같은 날 배포된 정정본이 정본이다([정정 내역](/reference/errata/)).

같은 번호라고 같은 주제가 아니다 — 3모듈만 봐도 set-02는 EC2 정책 위반 자동복구, set-07은 KEDA/Karpenter 스케일링, set-08은 Security Group 자동복구다. 세트가 확정되면 번호가 아니라 **주제로** 해당 문서를 연다.

## 모듈별 변동 짝 (PART-1~3)

01~08 의 실습은 **기준본을 타깃 세트 요구로 이행하는** 훈련이다. 어느 세트에서 어느 세트로 가는지가 아래 표다. 전부 diff 로 확인한 값이다.

| 모듈 | 기준본 | 변동 타깃 | 변동의 성격 | 판정 축 |
|---|---|---|---|---|
| [01](/part-1/01-terraform-vpc/lab/) | set-02 | set-07 | CIDR 규칙 계산 · 3 AZ 6서브넷 · Endpoint · Flow Log | `plan` 의 `forces replacement` |
| [02](/part-1/02-kms-s3-cloudfront/lab/) | set-02 | set-07 | 키 분류 축이 리소스별 → 용도별 · 90일 회전 · 다중 리전 키 · WAF 신설 | 같음 |
| [03](/part-1/03-container-lambda-dynamodb/lab/) | set-02 | set-07 | 파티션 키 · GSI 축 · PITR · 태그 정책 | 같음 + **프로바이더 버전** |
| [04](/part-2/04-eksctl-cluster/lab/) | set-02 | set-07 | IRSA → Pod Identity · private 클러스터 · CMK 볼륨 · KST | **수정 API 유무** |
| [05](/part-2/05-k8s-workloads-alb/lab/) | set-02 | set-07 | 인터넷 ALB → internal ALB + VPC Origin · SA 직접 생성 | k8s 불변 필드 + AWS 불변 속성 |
| [06](/part-2/06-observability/lab/) | set-02 | set-07 | 수집 범위 · 로그 형식 · 저장소 · 네임스페이스 분리 | 위 + **시간 축** |
| [07](/part-2/07-full-deploy-set02/lab/) | set-02 | set-07 | 위 여섯을 한 번에 · 타이머 | 순서와 배점 |
| [08](/part-3/08-private-eks-iam/lab/) | **set-07** | **set-03** | 작업 호스트가 수동 → IaC · taint · 커스텀 도메인 | 수정 API 유무 + **삭제 판단** |

08 만 방향이 반대다. 1과제 수상 후보 중 fully-private 클러스터를 쓰는 것은 set-03 과 set-07 둘뿐이라, 기준본이 set-07 이면 타깃이 하나로 결정된다.

**판정 축이 모듈마다 다른 것이 요점이다.** Terraform 모듈은 `plan` 이 답을 주지만 eksctl 에는 그 출력이 없고, k8s 는 `apply` 가 `field is immutable` 로 거부하는 것으로 대신한다. 08 의 "삭제 판단"은 어느 도구도 안 잡아 준다.
