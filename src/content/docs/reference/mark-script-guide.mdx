수상의 실제 비결. **구현 전에 mark 스크립트부터 읽는다.**

## 판단 원칙 (수상 과제 :badge[실측]{variant=note})

1. **mark 스크립트가 1순위.** 과제지(task)와 채점지(mark)가 다르면 mark를 따른다.
   - set-02 m1: 처리 Lambda 이름이 task엔 없고 mark에만 등장 → mark 이름으로 생성.
2. **오타도 사양이다.** set-02 m2 역할명 `wsc2026-alaytics-ec2-role` — 고치면 오답.
3. **둘 다 애매하면 합집합 구현.** set-02 m3: 함수 6개·룰 6개 전부 생성, mark는 그중 일부만 채점.
4. **문자열 정확 일치.** 이름·필드 순서·개수·대소문자·키 순서(JSON 출력)까지 본다.
5. **개수도 채점이다.** ALB 규칙 "정확히 2개", 버킷정책 `Statement[0]`만 검사, env 리터럴 3개만.
6. **상태도 채점이다.** Flink 노트북 READY(시연 후 Stop), Pod 1/Node 1 수렴, Grafana No Data 0개.

## 읽기 절차

<Steps>

1. 스크립트를 항목(N-N) 단위로 자른다.

2. 각 항목을 표로 정리: **어떤 명령으로 → 무엇을 grep/비교 → 기대값**.

   ```
   | 항목 | 검사 명령 | 기대값 |
   | 7-2 | aws elbv2 describe-rules ... jq HttpHeaderConfig.Values[] | wskorea26-cf 2줄 |
   ```

3. 기대값에 등장하는 **모든 리터럴**(이름/태그/키/문자열)을 구현 체크리스트로 옮긴다.

4. `sleep`/재시도 로직 → 시간 의존 항목 표시 (예: 로그 30초, rate-limit 60+30초 대기).

5. 스크립트 첫머리의 환경 준비(예: `rm -rf ~/.aws`, `export number=`) → **어디서 실행해야 하는지** 결정.

   :::danger[본 PC 자격증명]
   `rm -rf ~/.aws` 있으면 반드시 CloudShell에서 (본 PC 자격증명 날아감).
   :::

   `export number=<등번호>`는 apply 시 `player_number`와 정확 일치 필요 (set-07 9-1/9-2 실측).

</Steps>

## 채점 직전 리셋 체크리스트

- [ ] 시연 데이터 정리 (S3 error/processed 비우기, DynamoDB 전삭제 등 — **재현 절차는 정확히 1회**: 두 번 업로드하면 error 8건으로 오답)
- [ ] 요구 상태 복원 (노트북 READY, 인스턴스 running, Pod/Node 수렴, weight 원복 후 drift 확인)
- [ ] 트래픽 시드 (Grafana 전 패널 데이터, `/log?level=...` 각각 호출)
- [ ] 임시 리소스 제거 (bastion, S3 `_transfer/`, 스테이징 바이너리) — 불필요 리소스는 감점
- [ ] 채점 신원 확인 (`sts get-caller-identity` = 클러스터 생성자)

## 실행 환경 매트릭스

| 작업 | 장소 | 이유 |
|---|---|---|
| terraform / eksctl | 본 PC (PS7) | 도구·파일 로컬 |
| docker build/push | 일반 CloudShell | 인터넷 O, Docker 내장 |
| kubectl / helm / 채점 | VPC CloudShell 또는 CloudShell | private 클러스터 접근, 신원 일치 |
| 파일 전달 | S3 `_transfer/` 릴레이 | VPC CloudShell 업로드 UI 없음 |
