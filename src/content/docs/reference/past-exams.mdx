> 문서 유형: reference

이 문서의 근거는 **실제로 시행된 과제**다. 공모전 제출작(`skills-2026`)이 아니라 경기장에서 쓰인 문제지·채점지·채점 스크립트다. 사이트의 다른 문서가 "실기출에 나왔다"고 말할 때 가리키는 곳이 여기다.

| 해 | 자료 | 과제 |
|---|---|---|
| 2024 (부산) | 문제지·채점지·채점 스크립트·배포파일 | 1과제 Web Service Provisioning / 2과제 IAM·Governance·CICD / 3과제 System operation |
| 2025 (전국) | 문제지·채점기준·채점 스크립트·배포 바이너리 | 1과제 Solution Architecture / 2과제 Small Challenge / 3과제 운영 |

:::caution[한 해만 나온 축과 두 해 다 나온 축을 구분한다]
두 해 다 나온 축은 다음에도 나올 확률이 높다. 한 해만 나온 축은 그 해의 색깔일 수 있다. 아래 1절 대조표가 그 구분을 담는다.
:::

:::note[2026 시행분은 여기에 없다]
2026년 과제는 이미 시행됐지만 **배포되지 않았다.** 그래서 이 문서가 다루는 최신 자료가 2025년분이다. 2026 자료가 나오면 1절 대조표에 열을 하나 더해 갱신한다.

`skills-2026` 저장소는 시행문제가 아니라 **공모전 제출작 모음**이다. 근거의 층이 다르므로 인용할 때 구분한다.
:::

## 1. 두 해 주제 대조

| 축 | 2024 부산 | 2025 전국 | 판정 |

| Bastion | m5.large, SSH 포트 변경, 로그인 로그 | t3.medium, SSH 2222, 패키지 지정 | **매년** |
| 트래픽 검사 | 없음 | Network Firewall + Suricata (1·2과제 둘 다) | 2025 신규 |
| EKS | 1.29, Calico, assume-role RBAC | 1.32, addon·app 노드그룹 분리 | **매년** |
| CI/CD | CodeCommit·Build·Deploy·Pipeline | GitHub Actions + CodeBuild·CodePipeline | **매년** |
| GitOps·배포 전략 | 없음 | ArgoCD + Argo Rollouts BlueGreen | 2025 신규 |
| 시크릿 | 없음 | Secrets Manager + External Secrets(IRSA) | 2025 신규 |
| 서버리스 | API Gateway + Lambda@Edge | Step Functions + API Gateway 프록시 | **매년** |
| 데이터 보호 | 없음 | Macie + Lambda 마스킹 | 2025 신규 |
| WAF | ALB 고정응답 403 | SQLi 룰 직접 작성 | **매년** |
| RDS | MySQL 인덱스 설계 | 포트 3309 + CMK + RDS Proxy 전용 | **매년** |
| 로깅 | CloudWatch Logs 직접 | Fluent Bit DaemonSet + 필터 | **매년** |
| CloudFront | 오리진 2개, presigned URL | 없음 | 2024 |
| 3과제 컴퓨팅 | EC2 t3.micro 직접 | ECS 강제, c5.large, EKS·Lambda 금지 | **매년** |

**읽는 법.** "매년"이 붙은 축은 형태가 바뀌어도 반드시 나온다. 도구 이름을 외우지 말고 그 축이 푸는 문제를 이해한다. 2024 의 CodeCommit 과 2025 의 GitHub Actions 는 같은 문제를 다른 도구로 푼 것이다.

## 3. 과제별 요구사항 분해

### 3-1. 2025 1과제 — Solution Architecture (4시간, 30점)

**네트워크.** VPC 가 둘이다.

| 이름 | CIDR |
|---|---|
| `gj2025-hub-vpc` | `10.0.0.0/16` |
| `gj2025-app-vpc` | `192.168.0.0/16` |

Hub 에 Public 서브넷 둘, Private 서브넷 둘, Firewall 서브넷 하나가 있다. App 에 Private 서브넷 둘, Data 서브넷 둘이 있다. 둘을 잇는 것이 Transit Gateway(`gj2025-tgw`) 다. Data 서브넷 라우팅 테이블에는 게이트웨이가 없다. 인터넷으로 나갈 길이 아예 없다는 뜻이다.

**앱.** `red` 와 `green` 두 Go 애플리케이션이다. 각각 POST 로 넣고 GET 으로 꺼낸다. 버전 `1.0.0` 과 `1.0.1` 이 응답의 `version` 필드로 갈린다. 상태 검사 경로는 `/health` 다. DB 접속 정보를 Pod 에 직접 쓰면 안 되고 Secrets Manager 값을 External Secrets 로 읽어야 한다.

**보안.** Network Firewall 이 들고 나는 모든 트래픽을 검사한다. 규칙은 Stateful Suricata 형식이다. `gj2025-app-vpc` 에서 `ifconfig.io` 로 나가는 HTTP·HTTPS 를 차단하되 Bastion 은 모두 허용한다. 로그는 FLOW 유형만 CloudWatch Logs 로 보낸다.

**RDBMS.** MySQL 8.0.x, DB 이름 `day1`, 포트 3309다. 일반·에러·감사 로그를 수집하고, 고객관리형 키(CMK)로 암호화하며, 삭제방지를 켠다. 트래픽은 RDS Proxy 를 통해서만 받는다.

**컨테이너.** EKS 1.32 다. 노드그룹을 둘로 나눈다. `gj2025-eks-addon-nodegroup` 에 애드온을, `gj2025-eks-app-nodegroup` 에 애플리케이션을 둔다. DaemonSet 을 뺀 모든 애드온은 addon 노드그룹에 있어야 한다.

**로깅.** Fluent Bit 을 DaemonSet 으로 배포한다. HTTP 메서드가 포함된 로그만 보내고 `/health` 는 제외한다. 3초 안에 CloudWatch 에서 보여야 한다.

**로드밸런싱.** External NLB(Hub) 에서 PrivateLink 를 거쳐 Internal ALB(App) 로 간다.

**CI.** CodeBuild 와 CodePipeline 을 쓰고 소스는 GitHub OAuth 로 인증한다. **CD.** ArgoCD 가 gitops 브랜치를 감시해 Blue/Green 으로 롤아웃한다. Green 단계에서 `/health` 로 확인한 뒤 Blue 로 승격한다. 3분 안에 완료해야 한다.

### 3-2. 2025 2과제 — Small Challenge (4시간)

다섯 모듈이고 모듈마다 리전이 다르다.

| 모듈 | 리전 | 핵심 |
|---|---|---|
| CI/CD | `ap-southeast-1` | ECR·EKS·ALB·GitHub Actions·ArgoCD |
| Storage data protect | `ap-northeast-2` | S3·Macie·Lambda 마스킹 |
| WAF | `us-east-1` | 취약 Flask 앱·ALB·WAF SQLi 차단 |
| Secure networking | `eu-west-1` | Egress VPC·Network Firewall 3단 방어 |
| Serverless Inventory | `us-west-1` | Step Functions·API Gateway |

:::danger[리전을 틀리면 그 모듈이 통째로 0점이다]
채점 스크립트 첫 줄이 `aws configure set region <리전>` 이다. 다른 리전에 만들면 조회 자체가 빈 결과를 낸다. 리소스는 멀쩡히 있는데 점수만 없다.
:::

Serverless Inventory 모듈은 Lambda 는 물론 EC2 와 ECS 까지 전부 금지다. 컴퓨팅 없이 풀어야 한다.

**Macie 마스킹 규칙** — 원본은 감지되고 마스킹본은 감지되지 않아야 한다.

| 유형 | 원본 | 마스킹 |
|---|---|---|
| 이름 | `Crystal White` | `Crystal *****` |
| 이메일 | `davisjesus@example.org` | `d*********@example.org` |
| 전화 | `010-7658-5153` | `010-7658-****` |
| 주민번호 | `887-07-7325` | `887-07-****` |
| 카드 | `4468-6779-7028-4776` | `4468-6779-7028-****` |
| UUID | `665ef2db-cd63-4086-81e9-661ccaf8dd20` | `665ef2db-cd63-4086-81e9-************` |

**Network Firewall 3단 방어** (Secure networking 모듈)

1. Stateless 규칙으로 모든 ICMP 를 차단한다
2. Stateful 규칙으로 UDP·TCP 53 외부 DNS 질의를 차단한다
3. IP 직접 접속과 HTTPS 우회까지 차단한다

**Serverless Inventory** — DynamoDB `inventory` 테이블은 파티션 키가 `name` 이고 속성이 `value` 다. Step Functions `inventory-state-machine` 이 `{"sales": N}` 을 받아 재고와 잔고를 갱신한다. API Gateway REST API 는 AWS Service Proxy 통합으로 Lambda 없이 DynamoDB 를 직접 읽는다. `item` 쿼리스트링이 `mysecret` 으로 시작하면 403 을 낸다.

### 3-3. 2025 3과제 — 운영 (40점)

컴퓨팅 제약이 이 과제의 성격을 정한다.

- 컨테이너 오케스트레이션은 ECS 다. EKS 를 쓸 수 없다.
- 컴퓨팅은 EC2 c5.large 만 쓴다. Fargate 와 Lambda 를 쓸 수 없다.
- RDS 는 `db.t3.micro` Multi-AZ 한 대만이고 읽기 전용 복제본을 만들 수 없다.
- DynamoDB 는 테이블 하나만 만든다.

앱은 셋이다. `user` 는 MySQL 을 쓰고 목표 응답시간이 0.2초, `product` 는 DynamoDB 를 쓰고 0.2초, `stress` 는 1.0초다. 모두 TCP 8080 에 바인딩하고 Go 1.22 로 빌드했으며 액세스 로그를 stdout 과 stderr 로 낸다.

애플리케이션에 없는 로직을 인프라로 만들어야 하는 항목이 하나 있다. `POST /v1/user` 의 이메일이 `xxxx@xxxx.xxxx` 형식이 아니면 403 을 내야 하는데, 문제지가 "이는 어플리케이션 로직으로 구현되어 있지 않다"고 못 박는다. WAF 나 라우팅 계층에서 잡아야 한다는 뜻이다.

엔드포인트는 하나로 단일화한다. 정의되지 않은 경로는 404 를, 비정상 요청은 403 을 낸다.

### 3-4. 2024 1과제 — Web Service Provisioning (4시간)

3AZ VPC(`10.0.0.0/16`) 에 Public·Private·Protected 서브넷을 각 3개 만든다. Flow Logs 포맷이 지정돼 있다.

```
${region} ${vpc-id} ${action} ${instance-id}
```

Bastion(m5.large) 은 로그인과 로그아웃을 CloudWatch Logs 에 기록한다.

```
{ ec2-user, ec2-user has logged in!, 2024-05-22 14:18:11 }
```

Control Plane(c5.large, Private A) 에 리눅스 계정 `user` 와 `dev` 를 만든다. 각각 IAM 역할 `user` 와 `developer` 를 assume 한 뒤에만 `skills` 네임스페이스에 접근할 수 있다. `user` 는 조회만 하고 `dev` 는 조회와 삭제를 한다.

EKS 1.29 에 노드그룹 둘(`wsi-app-ng` 와 `wsi-addon-ng`)을 두고 Calico 로 파드 간 통신을 차단한다. 외부 DNS·HTTP·HTTPS 는 허용한다.

CloudFront 는 오리진이 둘이다. S3 쪽은 캐싱하고 ALB 쪽은 캐싱하지 않으며 쿼리스트링을 모두 전달한다. Lambda@Edge 로 `/preview?img=<이름>` 에 3분 만료 presigned URL 을 낸다.

### 3-5. 2024 2과제 — 30분 모듈 3개

| 모듈 | 핵심 |
|---|---|
| IAM | 태그 조건부 정책. `user1` 은 조회와 `wsi-project: developer` 태그 인스턴스 생성만, `user2` 는 그 태그 인스턴스 삭제만 |
| Governance | CloudTrail 에서 CloudWatch 로, 다시 Lambda 로. 콘솔 로그인 기록을 4분 안에 로그 스트림에 남긴다 |
| CICD | CodeCommit·CodeBuild·ECR·CodeDeploy(In-place)·CodePipeline. 승인 절차 없이 5분 안에 |

:::note[30분짜리 모듈이라는 사실이 설계를 정한다]
2024 2과제는 모듈당 30분이다. 콘솔로 클릭해 끝내는 편이 Terraform 을 쓰는 것보다 빠르다. 2025 2과제는 네 시간에 다섯 모듈이라 성격이 다르다.
:::

### 3-6. 2024 3과제 — System operation

2025 와 골격이 같다. 다른 점만 적는다.

- 컴퓨팅이 t3.micro 이고 오케스트레이션 도구는 자유다. Fargate 와 Lambda 만 금지다.
- 앱이 둘이다. `token` 은 목표 1초, `employee` 는 MySQL 을 쓰고 0.2초다.
- 환경변수 이름이 `MYSQL_USER` · `MYSQL_PASSWORD` · `MYSQL_HOST` · `MYSQL_PORT` · `MYSQL_DBNAME` 이다.

## 4. 채점 스크립트가 실제로 치는 명령

채점 스크립트는 문제지보다 정확하다. 문제지가 애매하게 쓴 것도 스크립트는 정확한 값으로 검사한다. 아래는 실기출 스크립트에서 그대로 가져온 명령이다.

### 4-1. 채점이 먼저 하는 일

```bash
rm -rf ~/.aws
mkdir -p ~/.aws
aws configure set region ap-northeast-2
```

:::danger[자격증명 파일이 지워진다]
2025 1과제 채점은 시작하자마자 `~/.aws` 를 통째로 지운다. Bastion 의 접근 권한이 IAM 역할(인스턴스 프로파일)로 붙어 있지 않고 `~/.aws/credentials` 파일에만 있으면 그 순간 모든 조회가 실패한다.
:::

### 4-2. 이름과 태그로 찾는다

```bash
aws ec2 describe-vpcs --filter Name=tag:Name,Values=gj2025-hub-vpc --query "Vpcs[0].CidrBlock"
aws ec2 describe-subnets --filter Name=tag:Name,Values=gj2025-hub-public-subnet-a --query "Subnets[0].CidrBlock"
```

이름 태그가 한 글자라도 틀리면 `null` 이 나오고 그 항목은 0점이다. 대소문자를 구분한다.

### 4-3. 라우팅은 게이트웨이가 붙어 있는지로 본다

```bash
aws ec2 describe-route-tables --filters "Name=tag:Name,Values=gj2025-hub-public-rtb" --query "RouteTables[].Routes[?GatewayId != null && starts_with(GatewayId, 'igw')].GatewayId" --output text
```

### 4-4. Transit Gateway 는 연결 이름까지 본다

```bash
TGW_ID=$(aws ec2 describe-transit-gateways --filters "Name=tag:Name,Values=$TGW_NAME" --query "TransitGateways[0].TransitGatewayId" --output text)
aws ec2 describe-transit-gateway-attachments --filters "Name=transit-gateway-id,Values=$TGW_ID" --query "TransitGatewayAttachments[*].{Name:Tags[?Key=='Name'].Value|[0]}" --output json
```

### 4-5. 앱은 실제로 왕복시킨다

```bash
APP_EXTERNAL_NLB=$(aws elbv2 describe-load-balancers --names gj2025-app-external-nlb --query "LoadBalancers[].DNSName" --output text)
id_red=$(curl -s -H "Content-Type: application/json" -d '{"name":"kim"}' http://$APP_EXTERNAL_NLB/red | jq -r '.id')
curl -s http://$APP_EXTERNAL_NLB/red?id=$id_red
```

POST 로 넣은 `id` 를 그대로 GET 에 넣는다. 저장이 실제로 되지 않으면 두 번째 줄이 빈 값을 낸다.

### 4-6. 방화벽은 파드를 띄워 밖으로 나가 본다

```bash
kubectl run firewall-test --image=radial/busyboxplus --restart=Never --command -- sh -c "while true; do sleep 3600; done"
kubectl exec firewall-test -- curl -m 5 -sS https://ifconfig.io
```

차단이 제대로 되면 이 `curl` 이 타임아웃한다. 성공하면 안 되는 명령이다.

### 4-7. RDS Proxy 는 파드에서 붙어 본다

```bash
kubectl run proxy-test --image=mysql:8 --restart=Never -- sleep 60
ENDPOINT=$(aws rds describe-db-proxies --db-proxy-name gj2025-rds-proxy --query 'DBProxies[0].Endpoint' --output text)
kubectl exec proxy-test -- mysql -h $ENDPOINT -u admin -pSkills53#\$% -e 'SELECT 1' && echo True || echo False
```

### 4-8. Fluent Bit 은 DaemonSet 을 지웠다 다시 올려서 본다

```bash
kubectl get daemonset red-fluent-bit -n amazon-cloudwatch -o yaml > red-fluent-bit.yaml
kubectl delete daemonset red-fluent-bit -n amazon-cloudwatch
aws logs delete-log-group --log-group-name /gj2025/app/red
kubectl apply -f red-fluent-bit.yaml
sleep 3
curl -s -X POST -H "Content-Type: application/json" -d '{"name":"kim"}' http://$EXTERNAL_NLB/red
sleep 3
aws logs get-log-events --log-group-name /gj2025/app/red --log-stream-name app-red-logs --limit 1 --query 'events[*].message' --output json | jq -r '.[0] | fromjson | .log'
```

로그 그룹을 지우고 다시 채운다. 로그 스트림 이름이 `app-red-logs` 로 고정돼 있어야 이 조회가 성립한다. 3초 안에 들어와야 한다는 요구가 여기서 실제로 검사된다.

### 4-9. IRSA 정책은 Resource 를 펼쳐 본다

```bash
for arn in $(aws iam list-attached-role-policies --role-name $ROLE --query 'AttachedPolicies[*].PolicyArn' --output text); do
  aws iam get-policy-version --policy-arn $arn --version-id $(aws iam get-policy --policy-arn $arn --query 'Policy.DefaultVersionId' --output text) --query 'PolicyVersion.Document.Statement[*].Resource' --output text
done
```

`Resource` 를 `*` 로 두면 이 출력에 `*` 가 찍히고 최소 권한 항목이 깎인다.

### 4-10. WAF 는 공격 요청을 직접 쏴 본다

```bash
curl "http://$ALB_ENDPOINT/login?name=admin'--&secret=anything"
curl "http://$ALB_ENDPOINT/lookup?id=id%3D1+OR+1%3D1"
```

차단되면 403 이 온다. 차단 전 원본 EC2 에 같은 요청을 쏴 취약함을 먼저 보인 다음 ALB 로 쏴서 막힘을 보이는 구조다.

### 4-11. Argo Rollouts 는 전략과 상태를 본다

```bash
kubectl argo rollouts get rollout red-rollout -n skills | egrep "Strategy"
kubectl argo rollouts get rollout red-rollout -n skills | egrep "stable" | grep "Healthy" | awk '{print $6,$8}'
```

`Strategy` 가 `BlueGreen` 으로 찍혀야 하고 stable 리비전이 `Healthy` 여야 한다.
