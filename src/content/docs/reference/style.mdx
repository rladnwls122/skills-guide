이 레포의 모든 문서가 따르는 규칙. 새 문서를 쓰거나 고칠 때 이 문서를 기준으로 판단한다.

콘텐츠는 전부 `src/content/docs/` 아래의 `.mdx` 다. Starlight 가 frontmatter 의 `title` 을 제목으로 렌더하므로 본문에 H1 을 따로 쓰지 않는다.

## A. Diátaxis 문서 체계

[Diátaxis](https://diataxis.fr)는 문서를 4유형으로 나눈다.

| 유형 | 목적 | 축 |
|---|---|---|
| tutorial | 학습 — 따라 하며 배운다 | 학습 × 습득 |
| how-to | 과제 해결 — 특정 목표를 달성한다 | 작업 × 적용 |
| reference | 조회 — 사실을 찾아본다 | 작업 × 습득 |
| explanation | 이해 — 원리와 이유를 안다 | 학습 × 적용 |

:::caution[핵심 규칙 — 유형 혼합 금지]
한 문서는 한 유형만 담는다. 설명이 필요한 tutorial은 explanation 문서로 링크하고, 절차가 필요한 explanation은 tutorial/lab으로 링크한다.
:::

### 이 레포 매핑

모듈 디렉터리는 `index` / `theory` / `lab` 세 파일로 이뤄진다.

| 파일 | 유형 | 담는 것 | 금지 |
|---|---|---|---|
| 모듈 `theory.mdx` | explanation (+끝의 퀴즈) | 원리·왜·채점 관점 | 절차(단계별 실행 지시) |
| 모듈 `lab.mdx` (PART-1~4) | tutorial (검증 절차는 how-to 성격) | 학습 단계·검증 명령 | 개념 설명 — theory 링크로 대체 |
| PART-5 `lab.mdx` | how-to | 훈련 절차·판정 기준 | 개념 설명 |
| 모듈 `index.mdx` | 개요 | 목표/소요/비용/경로 | 내용 서술 |
| `reference/*.mdx` | reference | 조회용 표·명령·매핑 | 설명·훈련 지침 |
| `start/*.mdx` | explanation | 선수 지식 요약+퀴즈 | — |

## B. 문장 규칙 (Google·Microsoft·Apple 종합)

- **능동태·현재형.** 독자를 직접 지칭하는 명령형("~한다/~하라")을 쓴다. "우리는" 금지. [Google]
- **조건이 지시보다 먼저.** "채점 전에 X하려면 Y한다" — 지시 뒤에 조건을 붙이지 않는다. [Google]
- **큰 아이디어, 적은 단어.** 군더더기 삭제: 불필요한 "~할 수 있다", "~하는 것이 가능하다", "기본적으로/사실상". 단, 학습 목표 체크리스트의 "~을 설명할 수 있다"는 달성 기준이므로 유지. [Microsoft]
- **동사로 시작하는 지시 우선, 핵심 먼저(front-load).** [Microsoft]
- **제목: 마침표·콜론 금지.** 부제는 `—` 로 잇는다. 영문 제목·용어는 sentence case. [Microsoft/Google]
- **순차 절차 = 번호 목록, 그 외 = 불릿.** [Google]
- **코드·명령·리소스명 = 코드 폰트, UI 요소 = 굵게.** [Google]
- **의인화 금지.** "채점 스크립트가 원한다/똑똑하다" → "mark.sh는 X를 검사한다". [Apple]
- **사전 예고 금지**("나중에 다룰"). 링크 텍스트는 설명적으로. [Google]

### 용어 표준화 표 [Apple: 한 개념 한 표기]

| 표준 표기 | 규칙 | 금지/변형 예 |
|---|---|---|
| `mark.sh` | 파일당 첫 언급만 "채점 스크립트(mark.sh)" 병기, 이후 `mark.sh` | "채점 스크립트" 단독 반복 |
| mark 스크립트 | 여러 세트의 mark 파일(mark.sh, mark2-2.sh, mark2.sh) 통칭에만 | 특정 파일을 가리킬 땐 파일명 |
| 노드그룹 | 붙여쓰기 | "노드 그룹" |
| 채점지 | = `mark.md` | — |
| 과제지 | = `task.md` | — |
| 정답지 | = `skills-2026` 실측 코드 | — |
| 런북 | 자기 배포 절차 문서 | "runbook" |
| 배포 | 스택 전체를 세우는 행위 | — |
| 적용(apply) | `terraform apply`·`kubectl apply` 실행 | "어플라이" |
| 삭제방지 | 붙여쓰기 | "삭제 방지" |
| 잔존 리소스 | destroy 후 남는 과금 리소스 | "남은 리소스" |
| 치트시트 | 본문 표기 (파일명은 `cheatsheet.md`) | — |

## C. 파일 상단 유형 라벨

frontmatter(와 컴포넌트 import) 다음 1행에 인용구로 유형을 명시한다. 본문 첫 줄이다.

```mdx
---
title: 05. 이론 — k8s 워크로드와 ALB 연동
description: ...
---

import { Quiz, QuizResults } from 'starlight-quiz/components';

> 문서 유형: explanation
```

값은 `explanation` · `tutorial` · `how-to` · `reference` · `개요` 다섯 중 하나다.

## D. 도식 (mermaid)

도식은 ```` ```mermaid ```` 코드 펜스로 쓴다. 렌더·아이콘·전체화면 뷰어는 전부 사이트 쪽에서
처리하므로 문서에서는 아래 규칙만 지킨다.

### 줄바꿈은 `<br/>`

라벨 안의 `\n` 은 mermaid 11 에서 줄바꿈이 **아니라 글자로 렌더된다**. 반드시 `<br/>` 를 쓴다.

```
DEP["Deployment<br/>replicas 2 · probe 3종"]
```

### AWS 서비스 노드에는 아이콘을 붙인다

서비스·제품을 가리키는 노드는 아이콘 셰이프로 쓴다. 규격(`form`·`pos`·`h`·`w`)은 전 도식 공통이다.

```
S3@{ icon: "logos:aws-s3", form: "square", label: "S3 버킷<br/>정적 호스팅", pos: "b", h: 46, w: 46 }
```

개념·데이터·판단을 가리키는 노드(`{"…?"}` 마름모, `"실제 데이터"` 등)는 아이콘 없이 둔다.

:::caution[아이콘 셰이프는 엣지 문장 안에 못 쓴다]
`CF["CloudFront"] -->|"오리진"| ALB["ALB"]` 처럼 엣지 안에서 선언된 노드는 아이콘화할 수 없다.
노드를 각자 줄에 선언하고 엣지는 id 로만 잇는다.
:::

### subgraph 는 `<span>` 으로 붙인다

subgraph 라벨에는 `@{ icon: }` 문법이 없다. 클래스로 붙인다.

```
subgraph EKS["<span class='icon--logos icon--logos--aws-eks'></span> EKS 클러스터"]
```

라벨 없이 쓰던 `subgraph KMS` 는 대괄호 라벨을 만들어 붙인다.

### 아이콘 고르는 순서

1. `aws:*` — AWS 서비스·리소스. 공식 아키텍처 아이콘 패키지에서 뽑은 자체 팩
2. `logos:aws-*` — 자체 팩에 없는 AWS 로고
3. `k8s:*` — 쿠버네티스 리소스. Deployment·Pod·Service·ConfigMap 처럼 종류를 구분해야 할 때
4. `logos:*` — docker-icon·terraform-icon·helm·prometheus·grafana 등 제품 로고
5. `simple-icons:*` — `logos` 에 없는 브랜드
6. `mdi:*` — 위 어디에도 없는 **개념**일 때만

`logos:kubernetes` 는 로고 하나뿐이라 Deployment 도 Pod 도 Service 도 전부 같아 보인다.
쿠버네티스 리소스에는 `k8s:*` 를 쓴다.

`sequenceDiagram` 은 mermaid 가 아이콘을 지원하지 않는다 — 손대지 않는다.

:::danger[아이콘 이름 오타는 빌드가 안 잡는다]
목록에 없는 아이콘을 쓰면 그 노드만 조용히 깨지고 빌드는 통과한다. 도식을 고쳤으면 반드시 실행한다.

```bash
npm run check:icons
```

새 아이콘을 쓰려면 `src/mermaid-icons.mjs` 의 목록에 이름을 먼저 추가한다.
:::
